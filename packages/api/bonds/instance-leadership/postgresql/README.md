# @molecule/api-instance-leadership-postgresql

PostgreSQL provider for `@molecule/api-instance-leadership`: elect ONE API
instance to run platform-wide singleton work, using a PostgreSQL SESSION
advisory lock held on a dedicated connection.

```typescript
import { acquireLeadership, setProvider } from '@molecule/api-instance-leadership'
import { provider } from '@molecule/api-instance-leadership-postgresql'

setProvider(provider) // reads DATABASE_URL lazily; nothing connects here
acquireLeadership({
  onAcquired: () => startPoolManager(),
  onLost: () => stopPoolManager(),
})
```

Use this bond whenever the API runs as more than one process or Machine: a
host-local lock (a loopback port, a file) elects one leader PER HOST, so
every singleton — pool managers, hibernation, retention sweeps, status
recorders — runs once per Machine instead of once per platform.

### Classes

#### `PgLeaderLockSession`

The production session: one `pg.Client`, one advisory lock.

Exported so a host that owns its own connection settings (the platform API's
SSL derivation, a Vault-backed URL resolver) can build a session directly and
pass it to the provider as its `createSession` factory.

```typescript
class PgLeaderLockSession implements LeaderLockSession {
  private lostHandler: (() => void) | null = null
  private lost = false

  /**
   * Track the connection's lifecycle so a lost session demotes the leader.
   *
   * @param client - A connected client owned exclusively by this session.
   * @param lockId - The advisory lock id to hold.
   */
  constructor(
    private readonly client: pg.Client,
    private readonly lockId: number,
  ) {
    const lost = (): void => {
      if (this.lost) return
      this.lost = true
      this.lostHandler?.()
    }
    // `error` covers a socket/network failure; `end` covers the backend ending
    // the session (a server restart, an idle-session kill). Either way the lock
    // is gone.
    this.client.on('error', (error) => {
      getLogger().warn('Leadership lock connection error', { error })
      lost()
    })
    this.client.on('end', lost)
  }

  /** {@inheritDoc LeaderLockSession.tryLock} */
  async tryLock(): Promise<boolean> {
    const { rows } = await this.client.query<{ locked: boolean }>(
      'SELECT pg_try_advisory_lock($1) AS locked',
      [this.lockId],
    )
    return rows[0]?.locked === true
  }

  /** {@inheritDoc LeaderLockSession.release} */
  async release(): Promise<void> {
    if (!this.lost) {
      try {
        await this.client.query('SELECT pg_advisory_unlock($1)', [this.lockId])
      } catch (error) {
        // The session is ending either way, and a session lock is released by
        // the backend when it ends — an unlock failure changes nothing.
        getLogger().debug('Leadership advisory unlock failed; the session end releases it', {
          error,
        })
      }
    }
    try {
      await this.client.end()
    } catch (_error) {
      // Already ended.
    }
  }

  /** {@inheritDoc LeaderLockSession.onLost} */
  onLost(handler: () => void): void {
    this.lostHandler = handler
  }
}
```

#### `createPostgresLockFactory(options)`

Builds a {@link LeaderLockFactory} that opens PostgreSQL session locks.

retries on its own connection, and a leader reconnects on a fresh one after

## Injection Notes

### Requirements

Peer dependencies:

- `@molecule/api-bond` ^1.0.1
- `@molecule/api-instance-leadership` ^1.0.0

### Environment Variables

- `DATABASE_URL` _(required)_ — PostgreSQL connection string
  - Setup: Use a direct connection or a session-mode pooler; transaction-mode pooling cannot retain advisory locks.

### Runtime Dependencies

- `@molecule/api-bond`
- `@molecule/api-instance-leadership`
- `pg`

- **A session lock dies with its connection.** The holder's process exiting,
  crashing, or losing the network ends the backend session and PostgreSQL
  releases the lock — no TTL to tune, no lock row left stale.
- **A leader that loses its connection demotes itself.** The provider stops
  treating itself as leader and calls `onLost`; a follower retries every
  `retryMs` (default 2 s) and takes over within seconds.
- **`prepareThreshold`/pooling caveat.** The lock MUST be taken on a direct
  client connection, never through a transaction-mode pooler (PgBouncer in
  transaction mode), which multiplexes statements from many clients onto a
  session: a lock "held" there is held by an unrelated session. Use a
  session-mode pooler or a direct connection.
- **Pick a lock id nobody else uses.** Advisory locks share one namespace per
  database. The exported `provider` uses `8675310`; a second application
  sharing the same database must pass its own id to
  `createPostgresLockFactory`.
- **This bond runs no singleton work itself.** It only tells the application
  which instance leads; the loops belong to the app (`onAcquired`/`onLost`).
