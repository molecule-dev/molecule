# @molecule/api-process-lifecycle

Process lifecycle core interface for molecule.dev.

Defines the contract a process uses to report readiness and liveness, drain
before shutdown, and run ordered teardown hooks. The interface carries no
implementation: `@molecule/api-process-lifecycle-express` provides the
Express/Node binding that mounts health endpoints and handles SIGTERM/SIGINT.

  registerReadinessCheck,
  registerShutdownHook,
  isReady,
} from '@molecule/api-process-lifecycle'
import { provider } from '@molecule/api-process-lifecycle-express'
import { setProvider } from '@molecule/api-process-lifecycle'

// Wire the provider once at startup
setProvider(provider)

// Readiness gates a load balancer; hooks close what the process owns
registerReadinessCheck({ name: 'database', check: async () => db.ping() })
registerShutdownHook({ name: 'database-pool', run: () => db.pool.end() })

const report = await isReady()

#### `LifecycleCheck`

A named readiness or liveness check.

Checks are async-friendly and individually bounded: a check that does not
answer within {@link LifecycleCheck.timeoutMs} is reported as failed (and
`timedOut: true`) instead of holding the health endpoint open. A check that
throws is a failed check, never a crashed process.

```typescript
interface LifecycleCheck {
  /** Unique name shown in the readiness/liveness report (e.g. `'database'`). */
  name: string
  /** The check itself. Return/resolve `true`/`undefined` to pass, `false` to fail. */
  check: () => LifecycleCheckOutcome | Promise<LifecycleCheckOutcome>
  /** Per-check timeout in milliseconds. Defaults to the provider's configured value (2000 ms). */
  timeoutMs?: number
  /**
   * Whether this check gates the overall verdict. A failing critical check
   * makes readiness (or liveness) false; a failing non-critical check is
   * reported but does not remove the process from rotation. Defaults to `true`.
   */
  critical?: boolean
  /** Optional human-readable purpose of the check, for logs. */
  description?: string
}
```

#### `WarmupStep`

A named step of the boot warm-up.

A load balancer takes the NEXT instance down as soon as this one's check
passes, so readiness must not pass while the process is still loading its
module graph or preloading caches. Warm-up steps are the work a boot does
AFTER the port is bound but BEFORE the instance can serve at full speed;
readiness stays closed until every step has completed or timed out.

A step that throws or exceeds its own timeout is reported and logged, and
the warm-up still settles: a broken preload must not hold an instance out of
rotation for the whole deploy window.

```typescript
interface WarmupStep {
  /** Unique name shown in the warm-up report (e.g. `'chat-handler-module-graph'`). */
  name: string
  /** The work to observe. Resolve when the work has settled. */
  run: () => void | Promise<void>
  /**
   * How long this step may take before it is reported as timed out. Defaults
   * to the provider's configured value (45000 ms).
   */
  timeoutMs?: number
}
```

#### `DrainHook`

A step run as a shutdown starts, BEFORE the load-balancer flip window and
before in-flight requests are drained.

This is where an application checkpoints work it could otherwise lose to a
force-kill during the flip window (for example, persisting a running chat
turn). Drain hooks are bounded and never stop the shutdown: a hook that
throws is reported, and the flip window still runs — skipping it would let a
load balancer route to an instance whose readiness is already 503.

```typescript
interface DrainHook {
  /** Unique name shown in the drain report and logs (e.g. `'chat-turn-checkpoint'`). */
  name: string
  /**
   * The work to run.
   *
   * @param reason - Why the shutdown started (usually a signal name).
   */
  run: (reason?: string) => void | Promise<void>
  /** Execution order, lowest first. Hooks with the same order run in registration order. */
  order?: number
  /** Per-hook timeout in milliseconds. Defaults to the provider's configured hook timeout. */
  timeoutMs?: number
}
```

#### `ProcessLifecycleProvider`

The contract every process-lifecycle provider implements.

Application code reaches the bonded provider through the accessors in
`@molecule/api-process-lifecycle` (`setProvider`, `getProvider`,
`registerReadinessCheck`, `isReady`, …) rather than importing a provider.

```typescript
interface ProcessLifecycleProvider {
  /** The current lifecycle phase. */
  state(): ProcessLifecycleState
  /** Move from `starting` to `ready` once the boot sequence has finished. */
  markReady(): void
  /** `true` while draining or stopped. */
  isDraining(): boolean
  /** Begin draining: readiness reports not-ready from this call onward. Idempotent. */
  startDraining(reason?: string): void
  /**
   * Record that a request started. The returned function releases the
   * request; it is idempotent so a `finish`/`close` pair cannot double-count.
   */
  beginRequest(): () => void
  /** Number of requests currently being served. */
  inFlightRequests(): number
  /**
   * Resolve `true` when the in-flight count reaches zero, or `false` when
   * `timeoutMs` elapses first.
   */
  waitForRequestsToDrain(timeoutMs: number): Promise<boolean>
  /**
   * Register a named readiness check.
   *
   * @returns A function that removes the check.
   */
  registerReadinessCheck(check: LifecycleCheck): () => void
  /**
   * Register a named liveness check.
   *
   * @returns A function that removes the check.
   */
  registerLivenessCheck(check: LifecycleCheck): () => void
  /**
   * Register an ordered shutdown hook.
   *
   * @returns A function that removes the hook.
   */
  registerShutdownHook(hook: ShutdownHook): () => void
  /**
   * Register a named boot warm-up step.
   *
   * Steps registered before {@link ProcessLifecycleProvider.markReady} run as
   * one pass when it is called; readiness stays closed until every step has
   * completed or timed out.
   *
   * @returns A function that removes the step.
   */
  registerWarmupStep(step: WarmupStep): () => void
  /**
   * Run every registered warm-up step once.
   *
   * Idempotent: a second call joins the in-flight pass instead of running the
   * work again. Never rejects — a failing or hanging step is reported.
   *
   * @returns The per-step warm-up report.
   */
  runWarmup(): Promise<WarmupReport>
  /**
   * Whether the boot warm-up has settled (every step completed or timed out).
   *
   * @returns `true` once the warm-up pass has finished.
   */
  isWarm(): boolean
  /**
   * Register a drain hook, run at the start of a shutdown before the
   * load-balancer flip window.
   *
   * @returns A function that removes the hook.
   */
  registerDrainHook(hook: DrainHook): () => void
  /**
   * Run every drain hook in order, then resolve. Never rejects.
   *
   * The graceful-shutdown sequence calls this BEFORE its flip window and runs
   * the window even when a hook fails.
   *
   * @param reason - Why the shutdown started (usually a signal name).
   * @returns The per-hook drain report.
   */
  runDrainHooks(reason?: string): Promise<DrainHookReport[]>
  /** Run every readiness check and report whether traffic may be routed here. */
  isReady(): Promise<ReadinessReport>
  /** Run every liveness check and report whether the process is alive. */
  isLive(): Promise<LivenessReport>
  /** Run every shutdown hook in order, then mark the process stopped. Idempotent. */
  runShutdownHooks(reason?: string): Promise<ShutdownReport>
}
```

### Types

#### `ProcessLifecycleState`

The lifecycle phase of an API process.

- `starting` — the process exists but has not finished its boot sequence; a
  load balancer must not route to it yet.
- `ready` — the process is serving traffic.
- `draining` — a shutdown was requested. Readiness reports not-ready so a
  load balancer stops sending new traffic, while in-flight requests finish.
- `stopped` — every shutdown hook has run; the process is about to exit.

```typescript
type ProcessLifecycleState = 'starting' | 'ready' | 'draining' | 'stopped'
```

#### `LifecycleCheckOutcome`

What a check function may return. `true`/`undefined` mean the check passed;
`false` means it failed; an object carries a pass/fail verdict plus an
optional human-readable detail for logs and the readiness response body.

```typescript
type LifecycleCheckOutcome = boolean | void | LifecycleCheckResult
```

## Injection Notes

### Requirements

Peer dependencies:

- `@molecule/api-bond` ^1.0.1

### Runtime Dependencies

- `@molecule/api-bond`

- **Liveness and readiness answer different questions.** Liveness asks "is
  this process alive?" and stays `true` while draining (restarting a draining
  process would abort the requests the drain is finishing). Readiness asks
  "may traffic be routed here?" and turns `false` at the first
  `startDraining()` call.
- **Checks are individually bounded.** A check that hangs is reported as
  failed at its timeout instead of holding the health endpoint open. A check
  that throws is a failed check, never an unhandled rejection.
- **Critical vs non-critical.** Only critical failures change the verdict;
  non-critical results are visible in the report so a degraded dependency can
  be observed without taking the whole process out of rotation.
- **Read `getProvider()` after bonds are wired.** Like every bond-backed
  accessor, these throw when no provider is bonded, so do not call them at
  module top level.
