# @molecule/app-solid

Solid.js framework bindings for molecule.dev.

Provides Solid-specific implementations of molecule.dev core interfaces
using Solid's reactive primitives (signals, effects, resources): wrap the
app in `MoleculeProvider` with a `config` of providers, then consume them

## Quick Start

```tsx
import { MoleculeProvider, createAuth, createTheme } from '@molecule/app-solid'
import { Show } from 'solid-js'
import { provider as stateProvider } from '@molecule/app-state-zustand'
import { provider as themeProvider } from '@molecule/app-theme-css-variables'
import { createJWTAuthClient } from '@molecule/app-auth'

const authClient = createJWTAuthClient({ baseURL: '/api' })

function UserProfile() {
  const { user, isAuthenticated, logout } = createAuth<{ name?: string }>()
  const { theme, toggleTheme } = createTheme()

  return (
    <Show when={isAuthenticated()} fallback={<a href="/login">Log in</a>}>
      <div style={{ background: theme().colors.background }}>
        <h1>Welcome, {user()?.name}</h1>
        <button onClick={toggleTheme}>Toggle Theme</button>
        <button onClick={() => logout()}>Logout</button>
      </div>
    </Show>
  )
}

function App() {
  return (
    <MoleculeProvider config={{ state: stateProvider, auth: authClient, theme: themeProvider }}>
      <UserProfile />
    </MoleculeProvider>
  )
}
```

```typescript
interface HttpClient {
  /**
   * Base URL for all requests.
   */
  baseURL: string

  /**
   * Default headers for all requests.
   */
  defaultHeaders: Record<string, string>

  /**
   * Makes a generic HTTP request. `data` is a field of THIS config object — the same body
   * `post(url, data, config)` takes as its second argument.
   */
  request<T = unknown>(config: FullRequestConfig): Promise<HttpResponse<T>>

  /**
   * Makes a GET request.
   */
  get<T = unknown>(url: string, config?: RequestConfig): Promise<HttpResponse<T>>

  /**
   * Makes a POST request. `data` is the request BODY, not a config object: the wire body is
   * `data` itself, so `post(url, { data: body })` sends `{"data":body}` — pass `body` directly.
   * A config (headers, params) is the THIRD argument.
   */
  post<T = unknown>(url: string, data?: unknown, config?: RequestConfig): Promise<HttpResponse<T>>

  /**
   * Makes a PUT request. `data` is the request BODY (second argument) — never `{ data: body }`,
   * which sends `{"data":body}`; a config is the THIRD argument.
   */
  put<T = unknown>(url: string, data?: unknown, config?: RequestConfig): Promise<HttpResponse<T>>

  /**
   * Makes a PATCH request. `data` is the request BODY (second argument) — never `{ data: body }`,
   * which sends `{"data":body}`; a config is the THIRD argument.
   */
  patch<T = unknown>(url: string, data?: unknown, config?: RequestConfig): Promise<HttpResponse<T>>

  /**
   * Makes a DELETE request.
   */
  delete<T = unknown>(url: string, config?: RequestConfig): Promise<HttpResponse<T>>

  /**
   * Adds a request interceptor.
   * Returns a function to remove the interceptor.
   */
  addRequestInterceptor(interceptor: RequestInterceptor): () => void

  /**
   * Adds a response interceptor.
   * Returns a function to remove the interceptor.
   */
  addResponseInterceptor(interceptor: ResponseInterceptor): () => void

  /**
   * Adds an error interceptor.
   * Returns a function to remove the interceptor.
   */
  addErrorInterceptor(interceptor: ErrorInterceptor): () => void

  /**
   * Sets the authorization token.
   *
   * A static token: every request carries it until the next `setAuthToken` call. A client
   * that has a {@link HttpClient.setAuthTokenResolver | resolver} (registered through
   * `@molecule/app-http`'s `setAuthTokenSource`) ignores this value when it assembles a
   * request — the resolver IS the session, and reading it per request is what keeps a
   * session adopted without an auth event from sending the previous account's bearer. Once
   * the resolver is removed, the static token is sent again.
   */
  setAuthToken(token: string | null): void

  /**
   * Returns the token the client applies to its next request: the resolver's answer when one
   * is registered, else the static token from `setAuthToken`.
   */
  getAuthToken(): string | null

  /**
   * Registers the LIVE token resolver every request of this client reads, or clears it with
   * `null`.
   *
   * `@molecule/app-http`'s `setAuthTokenSource()` calls this on every client it bonds, and the
   * client MUST consult the resolver again each time it assembles a request (and report it from
   * `getAuthToken()`). A session can change with no auth event and no observable state change —
   * `authClient.setSession()` with the same profile data, or the OAuth callback's
   * `setAccessToken()` — so a token pushed only at bond time or on `login`/`logout` events
   * leaves every later request carrying the PREVIOUS session's bearer while the UI shows the
   * new one.
   *
   * The resolved token takes the static token's place, with the same precedence: an
   * `Authorization` header passed per request or in the client's default headers wins over it
   * exactly where it won over a static token in this transport.
   *
   * A resolver that returns `null` (or `undefined`) means "this session has no body token": the
   * request carries no `Authorization` header of the client's own. A cookie-session API issues
   * no bearer, and the server prefers the header over the fresh cookie, so a kept bearer
   * authenticates as the prior — possibly deleted — session.
   *
   * Optional, so an implementation written against the previous interface still conforms.
   * `setAuthTokenSource()` follows such a client through a request interceptor instead, pushing
   * the source with `setAuthToken` before each request: that request carries the change only
   * when the transport applies its token after running its interceptors, so a transport that
   * applies it earlier sends a session adopted mid-page from the following request on.
   *
   * @param resolver - Returns the current access token (or null/undefined), or `null` to clear.
   */
  setAuthTokenResolver?(resolver: AuthTokenResolver | null): void

  /**
   * Registers a handler for authentication errors (401).
   *
   * @returns An unsubscribe function.
   */
  onAuthError(handler: () => void): () => void
}
```

```typescript
interface I18nProvider {
  /**
   * Gets the current locale.
   */
  getLocale(): string

  /**
   * Sets the current locale.
   *
   * **Fleet contract:** every conformant provider (the core simple provider,
   * `@molecule/api-i18n-simple`, `@molecule/app-i18n-i18next`, and
   * `@molecule/app-i18n-react-i18next`) MUST throw `Error('Locale "<code>"
   * not found')` when `locale` is not registered — via the constructor's
   * `initialLocales`/`locales` config, `addLocale()`, or `addTranslations()`
   * (all three register a locale). It must NOT silently degrade to
   * fallback-locale text while `getLocale()` reports the unregistered code —
   * that divergence makes a misconfigured locale switch indistinguishable
   * from a working one until a user notices the wrong language on screen.
   */
  setLocale(locale: string): Promise<void>

  /**
   * Gets all available locales.
   */
  getLocales(): LocaleConfig[]

  /**
   * Adds a locale.
   */
  addLocale(config: LocaleConfig): void

  /**
   * Removes a locale by code, notifying subscribers so language pickers
   * built on `onLocaleChange` re-render their list. If the removed locale
   * is currently active, the caller is responsible for switching to a
   * fallback (e.g. `'en'`) BEFORE calling this — the provider will not
   * auto-fall-back on its own.
   *
   * Returns `true` if the locale was registered and removed, `false`
   * otherwise.
   */
  removeLocale(code: string): boolean

  /**
   * Adds translations to a locale. Auto-creates the locale if it doesn't exist.
   *
   * **Fleet contract:** merges are DEEP, not a shallow spread — registering
   * two calls (e.g. two modules) that share a top-level namespace key merges
   * their subtrees instead of the second call clobbering the first's nested
   * translations wholesale. `@molecule/api-i18n-simple` implements the same
   * contract on the API side.
   */
  addTranslations(locale: string, translations: Translations, namespace?: string): void

  /**
   * Translates a key with optional interpolation values and pluralization.
   *
   * **Fleet plural contract (matches i18next's own key resolution order):**
   * when `options.count` is provided, the plural-suffixed key
   * (`` `${key}_${pluralForm}` ``, e.g. `item_one`/`item_few`/…, falling back
   * to `` `${key}_other` ``) is looked up FIRST and wins over the base `key`
   * if BOTH are registered. Only when no plural-suffixed key exists at all
   * does resolution fall back to the base key. A catalog that ships both
   * `item` and `item_one`/`item_other` therefore pluralizes identically
   * whichever provider is bonded.
   *
   * @returns The translated string, or the default value / key if not found.
   */

    key: string,
    values?: InterpolationValues,
    options?: { defaultValue?: string; count?: number },
  ): string

  /**
   * Checks if a translation key exists.
   *
   * **Fleet contract:** follows the SAME locale-resolution chain as `t()` —
   * the active locale, then the English fallback — so `exists(key) === true`
   * whenever `t(key)` would render real translated text (not the raw key or
   * an inline `defaultValue`). Do not narrow this to "only the active
   * locale's own catalog"; that made `exists()` return `false` for keys `t()`
   * happily rendered via the English fallback, and the answer differed by
   * provider.
   *
   * @returns `true` if the key has a translation.
   */
  exists(key: string): boolean

  /**
   * Formats a number according to the current locale.
   *
   * @returns The locale-formatted number string.
   */
  formatNumber(value: number, options?: NumberFormatOptions): string

  /**
   * Formats a date according to the current locale.
   *
   * @returns The locale-formatted date string.
   */
  formatDate(value: Date | number | string, options?: DateFormatOptions): string

  /**
   * Formats a relative time (e.g. "2 hours ago").
   *
   * @returns The locale-formatted relative time string.
   */

   * Formats a list (e.g. "A, B, and C").
   *
   * @returns The locale-formatted list string.
   */

  /**
   * Subscribes to locale changes.
   *
   * @returns An unsubscribe function.
   */
  onLocaleChange(listener: (locale: string) => void): () => void

  /**
   * Gets a counter that advances for every change `onLocaleChange` announces:
   * a locale switch, a locale-list change, or translations added for a locale
   * `t()` reads (the active locale and the locales it falls back to — English
   * for `createSimpleI18nProvider`). It does NOT advance for a re-registration
   * that leaves every rendered string identical.
   *
   * **Optional — read it only when present.** A consumer that observes the
   * provider through `useSyncExternalStore` (the React hooks do) compares this
   * value across renders, so it also sees a change that happened before its

   *

   *
   * @returns The provider's current revision.
   */

   *
   * @returns `'ltr'` or `'rtl'`.
```

#### `SessionReady(props)`

Renders its children once `createAuth().state().status` has left `'loading'` — the session
is decided (signed in, signed out, or `'unavailable'`) — and `fallback` until then. It never
redirects. An unavailable session is unconfirmed and may still have a null user.

After a full page load a returning visitor's session is restored by one request. Until it
answers, `createAuth().user()` is `null` everywhere, so a public page that renders a
signed-in action at once lets that action run against "signed out": a Follow button whose
handler starts with `if (!user()) return` ignores the click, one that redirects to `/login`
signs the visitor out of the flow. Wrapping the routes (or passing `awaitSession` in the
`MoleculeProvider` config) makes every page's first render read the restored user when
restoration succeeds.

A visitor with no session to restore settles in microtasks without a request. Must render
inside `MoleculeProvider` with `auth` configured. A client that nobody initialized starts its
restore on this first read. The bundled JWT client bounds each auth request (default
10 seconds), then settles as `'unavailable'` on timeout. Custom clients must also settle
their initial session status.

Route-level redirects for signed-in-only pages stay with `createAuthGuard`
(`./primitives/auth.js`).

```typescript
function SessionReady(props: ParentProps<SessionReadyProps>): JSX.Element
```

- `props` — {@link SessionReadyProps}.

**Returns:** The children once the session is decided, otherwise the fallback.
