# @molecule/app-vue

Vue framework bindings for molecule.dev.

Provides Vue composables and an app plugin for all molecule core
interfaces: install `moleculePlugin` with your providers, then consume
them in components via `useAuth`, `useTheme`, `useTranslation`,
`useStore`, and the other composables.

Render session-dependent UI from the three-way `status`, never a boolean
signed-out branch: `status === 'loading'` is undecided, redirect only on
`status === 'unauthenticated'`, and `'unavailable'` keeps a session candidate
for retry — a restore failure other than 401/403 never signs out.

Component tests: list `@molecule/app-vue/testing/setup` in vitest's `setupFiles`. A test's
events then land after the render they follow, as a user's do: Vue skips a listener attached in
the millisecond an event was first handled, so without it a test whose container and item both
listen passes in one run and fails in the next. It also fails a test when the component fires an
event itself (`focus()`, `dispatchEvent()`) into a listener mounted in the same task, which a
browser can skip too.

```ts
import { createApp, defineComponent, h } from 'vue'
import { Link, moleculePlugin, useAuth, useTheme } from '@molecule/app-vue'
import { provider as stateProvider } from '@molecule/app-state-zustand'
import { provider as themeProvider } from '@molecule/app-theme-css-variables'
import { createJWTAuthClient } from '@molecule/app-auth'

const Dashboard = defineComponent({
  setup() {
    // Composables are inject()-based: call them here in setup(), nowhere else.
    const { user, isAuthenticated, logout } = useAuth<{ name?: string }>()
    const { theme, toggleTheme } = useTheme()
    return () =>
      isAuthenticated.value
        ? h('div', { style: { background: theme.value.colors.background } }, [
            h('h1', `Welcome, ${user.value?.name ?? ''}!`),
            h('button', { onClick: toggleTheme }, 'Toggle theme'),
            h('button', { onClick: () => logout() }, 'Log out'),
          ])
        : h(Link, { to: '/login' }, () => 'Log in')
  },
})

const app = createApp(Dashboard)
app.use(moleculePlugin, {
  state: stateProvider,
  auth: createJWTAuthClient({ baseURL: '/api' }),
  theme: themeProvider,
})
app.mount('#app')
```

```ts
import { defineComponent, h, type PropType } from 'vue'
import { useHttpClient, useOptimisticValue, useTranslation } from '@molecule/app-vue'

interface FavoriteRecord {
  slug: string
  favorited: boolean
  favoritesCount: number
}

const FavoriteButton = defineComponent({
  props: {
    article: { type: Object as PropType<FavoriteRecord>, required: true },
    onChanged: {
      type: Function as PropType<(saved: FavoriteRecord) => void>,
      default: undefined,
    },
  },
  setup(props) {
    const http = useHttpClient()
    const { t } = useTranslation()
    const favorite = useOptimisticValue({
      value: { favorited: props.article.favorited, count: props.article.favoritesCount },
      commit: async (next) => {
        const path = `/articles/${props.article.slug}/favorite`
        const response = next.favorited
          ? await http.post<{ article: FavoriteRecord }>(path)
          : await http.delete<{ article: FavoriteRecord }>(path)
        const saved = response.data.article
        props.onChanged?.(saved)
        return { favorited: saved.favorited, count: saved.favoritesCount }
      },
    })
    return () =>
      h(
        'button',
        {
          'aria-pressed': favorite.value.value.favorited,
          'aria-label': t('article.favorite', undefined, { defaultValue: 'Favorite article' }),
          onClick: () =>
            favorite.update((current) => ({
              favorited: !current.favorited,
              count: current.count + (current.favorited ? -1 : 1),
            })),
        },
        String(favorite.value.value.count),
      )
  },
})

const FavoriteControl = defineComponent({
  props: {
    article: { type: Object as PropType<FavoriteRecord | null>, default: null },
  },
  setup(props) {
    return () =>
      props.article ? h(FavoriteButton, { key: props.article.slug, article: props.article }) : null
  },
})
```

#### `AuthState`

Reactive authentication state snapshot (initialized, authenticated, user, loading, and error).

```typescript
interface AuthState<T = UserProfile> {
  /**
   * The session's state as one value — render from this instead of combining
   * `initialized`/`authenticated`/`loading`. `'loading'` is undecided, so wait
   * and redirect only on `'unauthenticated'`; `'unavailable'` keeps the candidate
   * for retry and can have a null profile. A restore failure other than 401/403
   * never signs out. See {@link AuthStatus}.
   */
  status: AuthStatus

  /**
   * Whether auth state has been initialized.
   */
  initialized: boolean

  /**
   * Whether the client has an authenticated session. This is not a server
   * confirmation flag: during `'unavailable'` it can be false for a retained
   * token/cookie-only candidate with no cached profile. Use `status` for redirects.
   */
  authenticated: boolean

  /**
   * Current user, or null when none is cached. In particular, an `'unavailable'`
   * token/cookie-only restore has a retained candidate but no profile yet.
   */
  user: T | null

  /**
   * Whether an auth operation is in progress.
   */
  loading: boolean

  /**
   * Last auth error (if any).
   */
  error: string | null
}
```

#### `AuthClient`

Auth client interface that all auth bond packages must implement.
Provides login/logout/register flows, token management, profile
updates, and auth state subscription.

```typescript
interface AuthClient<
  T = UserProfile,
  TRegister extends RegisterExtraShape<TRegister> = Record<never, never>,
> {
  /**
   * Returns the current authentication state snapshot.
   *
   * READING the state starts the client's one session restore when nobody has called
   * {@link initialize} yet — lazily and exactly once, sharing the promise an explicit
   * `initialize()` returns. A hook (`useAuth()`), a subscriber, `isAuthenticated()` and
   * `getUser()` are reads too, so a client whose entry file dropped the template's
   * `authClient.initialize()` line still restores instead of reporting `'loading'`
   * forever.
   */
  getState(): AuthState<T>

  /**
   * Returns whether the user is currently authenticated.
   */
  isAuthenticated(): boolean

  /**
   * Gets the current user.
   */
  getUser(): T | null

  /**
   * Optional ownership marker for the current session. Compare values only within
   * this client: replacing or ending a session changes it, including re-adopting
   * the same token and user. Profile updates and same-session refreshes keep it.
   * Consumers can use it to discard stale async work without treating editable
   * user fields as an immutable account identifier. Providers without this
   * capability require the consumer's own stable identity check.
   */
  getSessionRevision?(): number

  /** Updates the cached user object (state + persistent storage) without hitting the network. */
  setUser(user: T | null): void

  /**
   * Gets the current access token.
   */
  getAccessToken(): string | null

  /**
   * Stores the access token in the configured token storage adapter (in a
   * browser, Web Storage; `'memory'` where no browser store exists). Use this
   * to seed the token after an out-of-band exchange (e.g. the OAuth
   * code→token redirect) instead of writing to `localStorage` directly,
   * which would violate the storage contract and make a stored bearer token
   * JS-readable (XSS-exfiltratable). Pass `null` to clear it.
   *
   * Passing `null` does not by itself sign a signed-in client out: use
   * {@link logout} to end a session, or {@link setUser} with `null` for
   * local-only sign-out. A non-null token on a client that is not signed in is
   * the first or second half of the app's own sign-in pair: together with
   * {@link setUser} it adopts the session (see there). Prefer {@link setSession}
   * with the token and user, or {@link login} / {@link register} for a
   * credential exchange.
   */
  setAccessToken(token: string | null): void

  /**
   * Adopts a session an out-of-band exchange already established: stores the
   * access token (and the refresh token when given), caches the user, and
   * sets the COMPLETE state — `initialized`, `authenticated`, `status:
   * 'authenticated'`, no error — in one update, with one subscriber
   * notification. Every hook reading the shared client sees the user as
   * signed in immediately.
   *
   * This is the way to seed an OAuth/custom sign-in. The field-setter pair
   * ({@link setAccessToken} then {@link setUser}, or the reverse) on a client
   * that is not signed in adopts the session the same way.
   */
  setSession(session: AuthSessionSeed<T>): void

  /**
   * Gets the refresh token.
   */
  getRefreshToken(): string | null

  /**
   * Logs in with credentials.
   */
  login(credentials: LoginCredentials): Promise<AuthResult<T>>

  /**
   * Logs out the current user. The server request is best-effort: a missing
   * logout route (404), any other HTTP failure, or a network error never makes
   * this method reject. It always clears the access token, refresh token and
   * cached user, stops automatic refresh, and publishes one settled
   * `authenticated: false`, `status: 'unauthenticated'` transition. Every pending
   * session operation loses ownership; a persistent marker prevents reload from
   * restoring an older session, and late credentials are revoked best-effort.
   *
   * When the API has no logout route, set {@link AuthClientConfigOptions.logoutEndpoint}
   * to `null` (or `''`) to skip the request. Local sign-out still happens.
   */
  logout(): Promise<void>

  /**
   * Registers a new user. Accepts the base fields plus the app's own fields
   * (`TRegister`) at the top level — see {@link RegisterData}.
   */
  register(data: RegisterData<TRegister>): Promise<AuthResult<T>>

  /**
   * Exchanges a stored refresh token, or re-reads `currentUserEndpoint` with the
   * existing access token/session cookie when the API has no refresh credential.
   * That fallback maps, stores and publishes the server user without renewing
   * the access token. Failures reject. A 401/403 ends the session, as does an
   * additional {@link AuthClientConfigOptions.currentUserRejectionStatuses}
   * code from the fallback. Transient failures retain it as unavailable. Use {@link updateProfile} for a profile
   * save, or {@link setUser} with the canonical row from an app-owned mutation.
   */
  refresh(): Promise<AuthResult<T>>

  /**
   * Requests a password reset.
   */
  requestPasswordReset(data: PasswordResetRequest): Promise<void>

  /**
   * Confirms a password reset.
   */
  confirmPasswordReset(data: PasswordResetConfirm): Promise<void>

  /**
   * Updates the current user's profile.
   * Returns the saved profile: the answer applied onto the signed-in user field
   * by field, with or without an `id` — a field it carries replaces the value
   * (`null` clears it), one it omits or leaves `undefined` is kept, so a field
   * cleared by omission must arrive as `null`. A non-object answer is returned
   * as it came. An answer for a replaced or ended session leaves the current one
   * untouched.
   */
  updateProfile(data: Partial<T>): Promise<T>

  /**
   * Changes the current user's password.
   */
  changePassword(oldPassword: string, newPassword: string): Promise<void>

  /** Initializes auth state (e.g., from stored tokens). */
  initialize(): Promise<void>

  /** Re-checks a restored session against the server, in the background — the boot-time validation an app with a stored token needs when a revoked or expired token… */
  validateSession?(): Promise<void>

  /** Resolves when the session restore started by `initialize()` has settled — the point after which the client knows whether this visitor is signed in. */
  whenRestored?(): Promise<void>

  /**
   * Subscribes to auth state changes.
   */
  subscribe(callback: (state: AuthState<T>) => void): () => void

  /**
   * Subscribes to auth state changes (alias for subscribe).
   */
  onAuthChange(callback: (state: AuthState<T>) => void): () => void

  /**
   * Gets the current access token (alias for getAccessToken).
   */
  getToken?(): string | null

  /**
   * Adds an auth event listener.
   *
   * The listener is typed by this client's profile: one signature,
   * `AuthEventListener<T>`, so an inline arrow is contextually typed and `event`
   * is never implicitly `any`. A client whose profile extends
   * {@link UserProfile} also accepts a default {@link AuthEventListener}: when
   * `T` extends `UserProfile`, `AuthEvent<T>` is assignable to
   * `AuthEvent<UserProfile>`, so a listener that takes the wider default event
   * accepts every event this client emits and keeps compiling. (`UserProfile`
   * is the wider type here — it has fewer required fields — and the assignable
   * direction runs from the client's `AuthEvent<T>` to the listener's
   * `AuthEvent<UserProfile>`.) A profile that does not extend `UserProfile`
   * (no `id`) rejects the default listener: an `AuthEvent<UserProfile>` would
   * promise an `id` the runtime user does not have, and the narrower-typed
   * event is not assignable to it.
   */
  addEventListener(listener: AuthEventListener<T>): () => void

  /**
   * Destroys the auth client.
   */
  destroy(): void
}
```

```typescript
   * Clears the error for a specific field.
   */

  /**
   * Clears all errors.
   */
  clearErrors(): void

   * Gets the field state for a specific field.
   */

   * Registers a field for form management. A `defaultValue` that fills an
   * empty field is announced to subscribers once, in a microtask, so a field
   * registered during a render does not update other components mid-render.
   */
  register(nameOrOptions: string | RegisterOptions, options?: RegisterOptions): FieldRegistration

  /**
   * Unregisters a field.
   */

  /**
   * Validates a specific field.
   */
  validateField<K extends keyof T>(name: K): Promise<boolean>

  /**
   * Validates all fields.
   */
  validate(): Promise<boolean>

  /**
   * Resets the form and clears errors, touched fields and submission state.
   *
   * With no argument it restores the current baseline — the initial
   * `defaultValues`, or the values a previous `reset(values)` established.
   * Passing `values` merges them over the current baseline and makes the
   * result the new baseline, so a form reset to freshly loaded or saved data
   * reads clean (`isDirty === false`). A changed non-null `id` replaces the
   * record and cancels a pending submit.
   */
  reset(values?: Partial<T>): void

  /**
   * Applies externally loaded values without clearing submission state.
   *
   * The new clean baseline is the original `defaultValues` plus this latest
   * record, never a merge of earlier records. With `keepDirtyValues`, edited
   * fields retain their values while pristine fields take the loaded values.
   * A changed non-null `id` still replaces the record and cancels a pending
   * submit. Equal-content baselines cause no update. `keepOmittedValues` opts
   * into incremental top-level field fills using the current clean baseline.
   */
  updateValues(values: Partial<T>, resetOptions?: FormUpdateOptions): void

  /**
   * Handles form submission.
   */
  handleSubmit(
    onSubmit: (values: T) => void | Promise<void>,
    onError?: (errors: Partial<Record<keyof T, string>>) => void,
  ): (event?: { preventDefault?: () => void }) => Promise<void>

  /**
   * Sets focus to a field.
   */
  setFocus(name: keyof T): void

  /**
   * Subscribes to form state changes.
   */
  subscribe(callback: (state: FormState<T>) => void): () => void

  /**
   * Destroys the form controller.
   */
  destroy(): void
}
```

#### `HttpClient`

HTTP client interface.

All HTTP providers must implement this interface.
An explicit text, blob or arraybuffer parser determines the data type even when
a JSON generic is supplied. Keep JSON as the default for mutations returning a
record. A successful DELETE with no body already resolves with null data.

Every verb also takes a URL alone, through a signature with the same three parameters on every
verb, so a verb chosen at runtime (`client[verb](url)`) type-checks and a wrapper can implement
a verb with an arrow (`get: (url, config) => inner.get(url, config)`). With a body or a config,
choose the verb through `request({ method, url, data })` instead: the second argument is the
body for post/put/patch but the config for get/delete, so one call cannot serve both.

```typescript
   * `post(url, data, config)` takes as its second argument.

  ): Promise<HttpResponse<string>>
  request<T = unknown>(
    config: FullRequestConfig & { responseType: 'blob' },

   * Registers a handler for authentication errors (401), with the rejected request's metadata.
   *
   * @param handler - Receives the method, URL and credential state of the rejected request.
```

#### `useAuth(options)`

Composable for authentication state and actions.

`status === 'loading'` is undecided: wait for it and redirect only on
`status === 'unauthenticated'`. `'unavailable'` keeps the session candidate
for retry, but `isAuthenticated` can be false and `user` can be null while a
token/cookie-only restore has no cached profile. A restore failure other than
401/403 never signs out.

#### `useOptimisticValue(options)`

A server-backed value — a favorite, follow, like or bookmark button, a rating, a quantity, a

differs (by `equals`) from the one the composable last received, and only while nothing is

from the server response in `commit`, and publish that response to parent/query caches there
if needed. Let commit reject on failure: a catch that returns old data hides the failure.
Replace display-state refs and prop-copy watchers with this composable's value and `update`.
`pending` is for feedback, never a reason to disable the toggle or drop a tap.

the way React re-renders `useOptimisticValue`: the controller and any pending save

`value` is taken when it differs by `equals` from the last one received.

mounted through refetches of the same record. This composable does not fix a click handler
that returns on a still-null profile, or a remount that throws its controller away.
Refetches during a save cannot replace pending intent; changed server snapshots arriving
AFTER saving finishes are accepted and need query-layer ordering if they can be stale.

**Returns:** The value to render, whether a save is pending, the newest failure, and `set`/`update`.

#### `useVerifyPaymentReturn(options)`

Reads the payment id a provider put in the return URL and confirms the
purchase server-side with `POST /users/:id/verify-payment/:provider`.

**This is why a hosted checkout returns the buyer to the APP and not the
API.** Session cookies are host-only on the app's origin, so a top-level
redirect from the provider straight to an authenticated API callback on a
different host arrives with NO credentials — it answers 401 and the paid plan
is never granted. The request this composable makes is a same-origin call
from a loaded app page, so the credentials apply. It waits for auth to
hydrate first: after the redirect the page is a cold load, and the session is
restored from the httpOnly cookie via `GET /users/me`.

Verification is idempotent server-side (first-claim-wins on the transaction),
and this composable additionally runs at most once per transaction id per
page. Safe on pages that are also reached normally: with no id in the URL it
stays `idle` and issues no request.

If the component unmounts while the request is in flight, a verified
purchase still refreshes the cached profile (the plan is paid for), but the
composable calls neither `onVerified` nor `onError` and leaves the URL alone:
by then the address may belong to another page. A failure after unmount is
logged instead.

```typescript

  options?: UseVerifyPaymentReturnOptions,
): UseVerifyPaymentReturnResult
```

- `options` — Provider fallback + lifecycle callbacks (see {@link UseVerifyPaymentReturnOptions}).

**Returns:** The verification state (see {@link UseVerifyPaymentReturnResult}).

#### `SessionReady`

Renders its default slot once `useAuth().status` has left `'loading'` — the session is
decided (signed in, signed out, or `'unavailable'`) — and its `fallback` slot until then.
It never redirects. An unavailable session is unconfirmed and may still have a null user.

With the bundled JWT client, a stored token AND cached user restore synchronously,
so this boundary renders immediately. Token-only and cookie-only sessions need an
asynchronous current-user request. Until it answers, `useAuth().user.value` is `null`, so a
public page that renders a
signed-in action at once lets that action run against "signed out": a Follow button whose
handler starts with `if (!user) return` ignores the click, one that redirects to `/login`
signs the visitor out of the flow. Wrapping `<RouterView />` in `App.vue` makes every page's
first render read the restored user when restoration succeeds.

A visitor with no session candidate settles synchronously without a request. Must render
inside an app that installed `moleculePlugin` with `auth` (like every composable consumer, it
throws when its service was not provided). A client that nobody initialized starts its
restore on this first read. The bundled JWT client bounds each auth request (default
10 seconds), then settles as `'unavailable'` on timeout. Custom clients must also settle
their initial session status.

Route-level redirects for signed-in-only pages stay with the app's auth route guard
(`AuthGuard` in the scaffold).

```typescript
const SessionReady: DefineSetupFnComponent<
  Record<never, never>,
  Record<never, never>,
  SlotsType<SessionReadyProps>,
  Record<never, never> & {},
  PublicProps
>
```
