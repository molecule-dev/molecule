# @molecule/app-drag-drop-dndkit

Real `@dnd-kit` drag-drop provider for molecule.dev.

Implements `DragDropProvider` from `@molecule/app-drag-drop` on `@dnd-kit`'s
framework-neutral DOM layer. Two layers ship here, neither tied to a UI
framework:

1. An imperative order store ({@link provider} / {@link createDndKitProvider})
   — `createSortable`/`createDraggable`/`createDroppable` — whose reorders use
   `@dnd-kit/helpers`' `arrayMove`.
2. What every framework's sortable list shares: the pointer and keyboard
   sensors ({@link sortableListSensors}), the axis limits
   ({@link sortableListModifiers}), the translated screen-reader instructions
   and announcements ({@link sortableListPlugins}) and the drop rule
   ({@link sortableListDrop}), with the options every list takes
   ({@link SortableListOptions}).

The sortable lists themselves are in the framework bindings:
`@molecule/app-drag-drop-dndkit-react`, `-vue`, `-solid`, `-svelte` and
`-angular`. Each takes the same {@link SortableListOptions}, so a list swaps
between frameworks unchanged.

interface SortableListOptions<T extends { id: string }> {
  /** The items, in their current order. */
  items: T[]
  /**
   * Called with the whole list in its new order when a drop moves an item. Not
   * called when the drag is cancelled, the list is disabled, or the item is
   * dropped where it started. Persist the order here; the list renders `items`.
   *

  strategy?: SortableStrategy
  /** Disables dragging every item. Defaults to `false`. */
  disabled?: boolean
  /** Pointer activation thresholds and the Escape behavior. */
  config?: DndKitConfig
  /**
   * The name a screen reader hears for an item in the drag announcements
   * ("Picked up {label}, position 2 of 5."). Defaults to the item's `id`.
   *
   * @param item - The item.
   * @returns Its label.
   */
  getItemLabel?: (item: T) => string
  /** Called when a drag starts. */
  onDragStart?: (event: DragStartEvent) => void
  /** Called while a dragged item is over another item. */
  onDragOver?: (event: DragOverEvent) => void
  /** Called when a drag ends, before `onReorder`. `overId` is the item whose place it took. */
  onDragEnd?: (event: DragEndEvent) => void

#### `SortableListLocale`

A dnd-kit plugin that sets each row's `aria-roledescription` to
{@link sortableItemRoleDescription} and, on every locale change, rewrites it
and the instructions element named by `descriptionId`.

```typescript
class SortableListLocale extends Plugin<DragDropManager, SortableListLocaleOptions> {
  private readonly stopListening: () => void
  private readonly observer: MutationObserver

  /**
   * Creates the plugin for one list's manager.
   *
   * @param manager - The list's drag-and-drop manager.
   * @param options - The id of the list's instructions element.
   */
  constructor(manager: DragDropManager, options?: SortableListLocaleOptions) {
    super(manager, options)
    const set = (element: Element, roleDescription = sortableItemRoleDescription()): void => {
      if (element.getAttribute('aria-roledescription') !== roleDescription)
        element.setAttribute('aria-roledescription', roleDescription)
    }
    // dnd-kit's accessibility plugin writes `draggable` in a later frame, in an order relative to this
    // plugin that varies; the observer puts the translation back after any such write.
    this.observer = new MutationObserver((records) => {
      for (const record of records) if (record.target instanceof Element) set(record.target)
    })
    const label = (): void => {
      const roleDescription = sortableItemRoleDescription()
      for (const draggable of this.manager.registry.draggables.value) {
        const activator = draggable.handle ?? draggable.element
        if (!activator) continue
        set(activator, roleDescription)
        this.observer.observe(activator, {
          attributes: true,
          attributeFilter: ['aria-roledescription'],
        })
      }
    }
    // `label` reads the rows reactively, so this runs again whenever a row registers or gets a handle.
    this.registerEffect(label)
    this.stopListening = onLocaleChange(() => {
      const description = options ? document.getElementById(options.descriptionId) : null
      if (description) description.textContent = sortableListInstructions()
      label()
    })
  }

  /** Stops following the locale and the rows, and removes the plugin's effect. */
  override destroy(): void {
    this.stopListening()
    this.observer.disconnect()
    super.destroy()
  }
}
```

## E2E Tests

Integration checklist — drive the real UI (live preview, no mocks), adapt
each item to this app's actual sortable lists / drop zones, and check every
box off one by one. A box you can't check is an integration bug to fix — not
a skip:

- [ ] Dragging an item to a new position REORDERS the list: the item lands in
      the drop slot, the surrounding items shift, and the rendered order now
      matches getItems() — reordering along the configured axis (a horizontal or
      grid list moves left/right, not just top/bottom). The instance is a headless
      order store, so a drag that visibly "does nothing" means the wiring is
      missing, not that the feature works.
- [ ] The reorder fires onReorder with the NEW item array and the app SAVES
      it: after a full reload the list keeps the new order (proving onReorder
      persisted it, not just shuffled local state). If the save fails, the UI
      restores the previous order via setItems() instead of lying about it.
- [ ] Dragging an item BETWEEN two containers moves it: it leaves the source
      list and appears in the target, BOTH lists update, and the target's onDrop
      fires identifying the item that moved (data + draggableId say which item
      went where) — the move survives a reload if the app persists it.
- [ ] A drop zone with `accept` set takes only the draggable types it lists
      and rejects the rest — a disallowed item does not land there and no onDrop
      fires for it.
- [ ] A disabled item can't be dragged: with `disabled: true` (on the item or
      the whole sortable) a drag attempt does nothing, the order is unchanged, and
      no reorder/drop callback fires.
- [ ] When `handle: true`, only the drag-handle element starts a drag —
      grabbing the item body anywhere else does not move it.
- [ ] Dropping outside any valid zone CANCELS: the item snaps back to its
      origin, the order is unchanged, and no callback claims a move — the item is
      never lost or left in limbo.
