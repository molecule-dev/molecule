# @molecule/app-routing-solid-router

Solid Router provider for `@molecule/app-routing`.

Implements the molecule `Router` over `@solidjs/router`, so molecule packages
navigate the app's real Solid Router. Build it from a component under the router and
hand it to `MoleculeProvider`, so every molecule package shares it:

With HTTP and auth clients bonded, the app's router (`createSolidRouter()` in the router's
`root`, or `MoleculeRouterProvider`)
replaces the current URL with `/login` after a credential-free GET receives a 401 and
the session is confirmed signed out, as React's `BrowserRouter` does. `location.state.from`
holds the original location. Set `signInPath` to use a different sign-in route or pass
`signInPath: false` to opt out.

## Quick Start

```tsx
import { MemoryRouter, Route } from '@solidjs/router'
import { MoleculeProvider } from '@molecule/app-solid'
import { createSolidRouter } from '@molecule/app-routing-solid-router'

;<MemoryRouter
  history={memory}
  root={(props) => (
    <MoleculeProvider router={createSolidRouter({ history: memory })}>
      {props.children}
    </MoleculeProvider>
  )}
>
  <Route path="/users/:id" component={User} />
  <Route path="*rest" component={NotFound} />
</MemoryRouter>
```

### Functions

#### `ListRouteNav(props)`

Render every declared list view as a router link. The URL selects the active choice, and
selecting any view resets pagination through useListRoute. Native link behavior (new-tab
clicks, keyboard activation and history) is preserved. This is a navigation landmark,
not an ARIA tablist with local panels. No active-value state or change handler is needed.
When children are supplied, they render after the navigation landmark. Put loading and
empty results in that branch so a pending list never removes the filter controls.

```typescript
function ListRouteNav<Selection extends string>(props: ListRouteNavProps<Selection>): JSX.Element
```

- `props` — Named destinations, translated labels, optional auth and native nav attributes.

**Returns:** The navigation landmark with all its choices, followed by any rendered content.

#### `defineRoute(path, page)`

Register a literal Solid Router path and give its page the params that path declares.

Create the route at module scope and pass it to a router's `children` or `routes`.
A render callback builds the page from the params, or pass `{ Component: EditPage }`
to give the page a typed `params` prop automatically. The render callback runs once
when the page mounts and returns its JSX. Read params inside JSX or an effect so the
page follows URL changes. The params object is Solid's reactive one, so reading it
outside a tracking scope does not update. Values arrive percent-decoded, as they do
in the other routing bonds, although Solid Router itself hands out the raw URL text.

Use the returned `href` for links and post-save navigation. It builds the destination
from the same path that mounts the page, with the parameter names required by that
path, exactly as React Router's bond builds it. Pass values from the saved response
when identity can change.

```typescript
function defineRoute<const Path extends string>(
  path: Path,
  page:
    | ((params: NoInfer<SolidRouteParams<Path>>) => JSX.Element)
    | {
        Component: (props: { params: NoInfer<SolidRouteParams<Path>> }) => JSX.Element
      },
): SolidRouteDefinition<Path> & { path: Path; href: (...args: SolidLinkArgs<Path>) => string }
```

- `path` — A route path, including any named parameters.
- `page` — A render callback building the page, or an object with the page's `Component`.

**Returns:** The Solid Router route definition and a function that builds a link to it.

#### `useMoleculeRouter(options)`

Gets the molecule `Router` inside any Solid Router. No `MoleculeRouterProvider` is
required.

When `MoleculeRouterProvider` is mounted, returns its exact router with its named
routes. Otherwise creates ONE router for the calling component's whole life — its
location, params and queries follow the native router through every navigation, and
`subscribe()` hears the native router's own links and the back button — without bonding
it globally; the router is destroyed when the component is cleaned up. Mount
`MoleculeRouterProvider` for the non-Solid `@molecule/app-routing` `navigate()`/
`getRouter()` bond or `onRouterReady`.

```typescript
function useMoleculeRouter(options?: SolidRouterOptions): Router
```

- `options` — Route definitions for a component-owned router's named routes, and the memory history a `<MemoryRouter history={…}>` above uses (see {@link createSolidRouter}); ignored when a provider supplies the router.

**Returns:** The molecule `Router` instance.

#### `lazyPage(load, options)`

Load a route's page on demand, inside a Suspense boundary that belongs to the page.

Use it instead of Solid's `lazy` for every page a `<Route>` renders. Navigating to a
page whose code has not loaded yet then replaces the previous page at once: the
previous page unmounts and the new page's own boundary shows `fallback` until its
code arrives. With `lazy` under one shared `<Suspense>` around the routes, Solid
Router's navigation transition keeps the previous page mounted (hidden) behind that
boundary's fallback, so the URL already names the new page while the old page's
content is still in the DOM, and a check such as `getByRole('heading')` finds the old
page's headings. Layout routes (an app shell around the router's children) stay
mounted either way.

```typescript
function lazyPage<Page extends LazyLoadableComponent>(
  load: () => Promise<{ default: Page }>,
  options?: LazyPageOptions,
): LazyPageComponent<Page>
```

- `load` — Loads the page module, as for Solid's `lazy`: `() => import('./pages/Article.js').then((m) => ({ default: m.Article }))`.
- `options` — Optional `fallback` shown in the page's area while its code loads.

**Returns:** A component to use as a route's `component`: `<Route path="/article/:slug" component={Article} />`. Its props are the page's own, without the `undefined` an optional props parameter (`function Draft({ initial }: DraftProps = {})`) adds.

**Returns:** The history, with the shape Solid's `MemoryRouter` takes.

#### `MoleculeRouterProvider(props)`

Provider component that creates ONE molecule Router over the Solid Router the call sits
inside, for its whole mounted life, and bonds it as the active singleton via
`@molecule/app-routing`'s `setRouter`. Subscribers and guards registered on the router
survive navigation: `@molecule/app-routing`'s `getRouter()` keeps returning it,
`onRouterReady` fires once, and Solid Router's own links and the back button reach
`router.subscribe()`.

Bonding happens while the component renders, before its children, so a page's first
render already reads this router — no manual `setRouter` wiring required. It also renders
`@molecule/app-solid`'s `RouterProvider` with the router, so that binding's routing
primitives read it. It provides no routed view: Solid Router gives a route's component its
nested route as `props.children`, so a layout or guard used as a route component gets its
page as children. Mount it as the router's `root` (as in the example). The bond's own
routing hooks work without it. A `MoleculeRouterProvider` inside another one uses the outer
one's router: it registers its `routes` there and calls `onRouterReady` with it.

```typescript
function MoleculeRouterProvider(props: MoleculeRouterProviderProps): JSX.Element
```

- `props` — The provider props (see {@link MoleculeRouterProviderProps}): `children` (rendered inside the router context), `routes` (optional named-route definitions; pass a stable array — later identities register onto the same router), `onRouterReady` (optional callback invoked ONCE with the router after it is bonded, e.g. to register guards), `history` (the memory history the mounted `<MemoryRouter>` uses) and `signInPath` (the sign-in path a signed-out GET 401 sends the visitor to; `false` turns it off).

**Returns:** The rendered provider wrapping children with the router context.

every molecule package shares the native router:

```typescript
function createSolidRouter(options?: SolidRouterOptions): Router
```

- `options` — Route definitions and, for a memory router, its history.

**Returns:** A molecule `Router` driving that Solid Router.

#### `useConsumedSearchParam(name)`

Consume a credential query parameter into component state and remove only that parameter
from the address through the native router. The value survives local updates, failed-submit
retries and later query-only navigation; a newly arriving value on the same mounted route is
consumed too. Path, hash, unrelated query values and router location state are retained.

The bond's router owns the URL replacement, so the native location and `window.location`
agree. Its replace keeps the entry's app-owned state fields, including ones the native
router does not model.

```typescript
function useConsumedSearchParam(name: string): [string, (value: string) => void]
```

- `name` — The credential query key to consume, for example `token` or `code`.

**Returns:** The consumed value and its setter, in the binding's tuple shape: index 0 is the live value (`''` before first consumption), index 1 sets it.

#### `useListRoute(options)`

Own URL-backed pagination, filters and selected views without mirrored state or navigation effects.
Works inside any Solid Router (`<Router>`, `<HashRouter>`, `<MemoryRouter>`); no data-router
feature or `MoleculeRouterProvider` is needed — a provider supplies named routes and the
non-Solid `@molecule/app-routing` bond, nothing this hook requires. Ordinary links, direct
visits and Back/Forward all read the same URL. Page links retain path parameters and unrelated
queries; changing filters or views resets the page atomically. Protected views wait for auth
and redirect only a confirmed signed-out session, with `state.returnTo` set.

```typescript
function useListRoute<Filter extends string = string, Selection extends string = string>(
  options?: ListRouteOptionsInput<Filter, Selection>,
): UseListRouteResult<Filter, Selection>
```

- `options` — App-owned filter sources, view paths, pagination and optional auth readiness, or an accessor of them (a new auth status re-resolves the list).

**Returns:** Reactive list state plus link builders and navigation actions. Gate data queries with `canLoad`.

#### `matchPath(pattern, pathname, exact)`

Matches a route pattern against a pathname. `:name` captures one segment and `*` matches
anything. The whole pathname must match unless `exact` is `false`, which also accepts a pathname
that only starts with the pattern.

```typescript
function matchPath<Params extends RouteParams = RouteParams>(
  pattern: string,
  pathname: string,
  exact?: boolean,
): RouteMatch<Params> | null
```

- `pattern` — The pattern, such as `/users/:id` or `/files/*`.
- `pathname` — The pathname to match.
- `exact` — Whether the whole pathname must match (default `true`).

**Returns:** The match with its params, or `null`.

#### `generatePath(pattern, params)`

Builds a path from a pattern by putting each `:name` param in its place, percent-encoded. A
pattern given no params is returned as it is.

```typescript
function generatePath(pattern: string, params?: RouteParams): string
```

- `pattern` — The pattern, such as `/users/:id`.
- `params` — The param values.

**Returns:** The path.

#### `resolvePath(to, fromPathname)`

Resolves a path against the pathname it is relative to: an absolute `to` is returned as it is;
otherwise `to` is joined to `fromPathname`'s parent, with `..` moving up and `.` staying.

```typescript

```

- `to` — The path to resolve.
- `fromPathname` — The pathname it is relative to.

**Returns:** The resolved pathname.

#### `normalizePath(path)`

Removes trailing slashes from a path, keeping `/` itself.


- `path` — The path.

**Returns:** The path without trailing slashes.

### Constants

#### `provider`

Typed provider constant for the bond registry.

A Solid Router needs a component context (`useLocation` and friends read it), so no
router can be built at import time: `provider` is `@molecule/app-routing`'s own
browser router, correct only where no Solid Router is mounted. Wire
`createSolidRouter()` from a component under the router instead (see its example).

```typescript
const provider: Router
```

- Call `createSolidRouter()` inside the router's `root` component (any component under

- **A route with parameters? Declare its page with `defineRoute`.** The route path is the
  source of truth for the page's parameter names: `:name`, `:name?` and `*rest` each arrive
  as `string | undefined`. For example:

  ```tsx
  import { defineRoute } from '@molecule/app-routing-solid-router'

  const shelves = [
    defineRoute('/shelves/:shelf', ({ shelf }) => <Shelf name={shelf} view="all" />),
    defineRoute('/shelves/:shelf/saved', ({ shelf }) => <Shelf name={shelf} view="saved" />),
  ]
  ```

  Keep the returned route when links or a save handler need its destination. For
  `const detail = defineRoute('/shelves/:shelf', { Component: ShelfDetail })`, use
  `detail.href({ shelf: saved.slug })` to navigate to the saved record.
