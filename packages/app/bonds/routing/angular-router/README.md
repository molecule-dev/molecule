# @molecule/app-routing-angular-router

Angular Router provider for `@molecule/app-routing`.

Implements the framework-neutral molecule `Router` over the Angular Router, so
molecule packages and app code can navigate, read params/query and register guards
without importing `@angular/router` — while Angular keeps owning its own routes,
links and guards. Guards, named routes, query/hash helpers and subscriptions come
from `@molecule/app-routing`'s `createHistoryRouter`, so this bond behaves exactly
like the other routing bonds and an app can swap routing bonds without noticing.

Wire it once at bootstrap, next to Angular's own router providers, and inject it
through `@molecule/app-angular`'s `ROUTER` token:

With HTTP and auth clients bonded, the router `provideMoleculeRouter` provides
replaces the current URL with `/login` after a credential-free GET receives a 401 and
the session is confirmed signed out, as React's `BrowserRouter` does. `location.state.from`
holds the original location. Set `signInPath` to use a different sign-in route or pass
`signInPath: false` to opt out.

## Quick Start

```ts
import { bootstrapApplication } from '@angular/platform-browser'
import { provideRouter } from '@angular/router'
import { provideMoleculeRouter } from '@molecule/app-routing-angular-router'

bootstrapApplication(App, {
  providers: [
    provideRouter([
      { path: '', component: HomeComponent },
      { path: 'users/:id', component: UserComponent },
    ]),
    provideMoleculeRouter({ routes: [{ path: '/users/:id', name: 'user' }] }),
  ],
})
```

Outside Angular's injector (no `inject(AngularRouter)` available), build the
adapter directly with {@link createAngularRouter}; the exported {@link provider}
constant is the core browser router fallback (an Angular-backed router needs a
booted injector, which an import-time constant cannot have).

`useMoleculeRouter`, `useMoleculeQuery`, `useMoleculeNavigate` and `useIsActive` are
React's routing hooks under React's names: they work inside any Angular application
whose injector has Angular's `Router` (`provideRouter(routes)`, or `provideRouter` plus
`provideLocationMocks()` for a memory history), with or without
{@link provideMoleculeRouter} — React's hooks never need their provider either. Call
them in an injection context; the two whose answer follows the URL return signals.
{@link lazyPage} is React's `lazyPage` under React's name: a route page loaded on
demand, replaced at once when the URL moves and showing its own `fallback` until its
code arrives — where `loadComponent` makes the router hold the previous page. Angular
page props are the wrapper's `props` input.
{@link ListRouteNav} is React's `ListRouteNav` as `<nav mol-list-route-nav>`: every
declared list view is one of its own anchors, and the URL selects the active choice.
Mount {@link provideMoleculeRouter} to bond the adapter for `@molecule/app-routing`'s
`navigate()`/`getRouter()`, to name routes, or to receive `onRouterReady`. A router a
hook created without a provider stays local, so several of them cannot overwrite the
global bond.

A route with parameters? Declare its page with `defineRoute` and read its parameters with
`injectRouteParams`. The route path is the source of truth for the parameter names (`:name`;
Angular paths have no optional parameters):

```ts
import { defineRoute, injectRouteParams } from '@molecule/app-routing-angular-router'

class ShelfPage {
  readonly params = injectRouteParams<'shelves/:shelf'>()
}

const routes = [defineRoute('shelves/:shelf', ShelfPage)]
```

#### `ListRouteNav`

Render every declared list view as a router link. The URL selects the active choice, and
selecting any view resets pagination through useListRoute. Native link behavior (new-tab
clicks, keyboard activation and history) is preserved. This is a navigation landmark,
not an ARIA tablist with local panels. No active-value state or change handler is needed.
When `children` is supplied, its template renders after the navigation landmark. Put
loading and empty results in that branch so a pending list never removes the filter
controls.

The host element IS the `<nav>` (attribute selector `nav[mol-list-route-nav]`), so the
app's own attributes — `aria-label`, `id`, `class` — sit on it exactly as React's props
do on its nav. The links are this component's OWN anchors: each `href` is the molecule
router's `createHref` (the href the native router's own link writes, base path and hash
history included), and a click goes through `followRouterLink`, so a modified click, a
`target` other than `_self` or an external URL is left to the browser. The rendered
markup is exactly react-router's `ListRouteNav`: same elements, attributes and ARIA, and
no styles of its own.

Works inside any Angular application whose injector has Angular's `Router`; no
molecule provider is needed. Angular creates the page before its router has matched the
URL (React renders only once its router resolved one), so the navigation appears with
the router's first navigation. Where React takes nodes and a render function, this port
takes a `TemplateRef`: `label` may be a template rendered inside the link, and
`children` is a template rendered with the resolved list as its context.

```typescript
@Component({
  selector: 'nav[mol-list-route-nav]',
  standalone: true,
  imports: [NgTemplateOutlet],
  template: LIST_ROUTE_NAV_TEMPLATE,
})
export class ListRouteNav<Selection extends string = string> {
  private readonly router = useMoleculeRouter()
  private readonly selectionsInput = signal<Record<Selection, ListRouteNavItem> | undefined>(
    undefined,
  )
  private readonly defaultSelectionInput = signal<Selection | undefined>(undefined)
  private readonly pageParamInput = signal<string | undefined>(undefined)
  private readonly authInput = signal<ListRouteAuth | undefined>(undefined)
  private readonly listInput = signal<{ className?: string; itemClassName?: string } | undefined>(
    undefined,
  )
  private readonly linkClassNameInput = signal<
    string | ((state: ListRouteNavItemState<Selection>) => string | undefined) | undefined
  >(undefined)
  // The current route's params, the base every choice's destination is built on, as React
  // reads them from `useParams()` on every render.
  private readonly routeParams = signal<RouteParams>(this.router.getParams())
  // Angular creates the page before its router has matched the URL (React renders only
  // after its router resolved one), so the nav appears with the native router's first
  // navigation; until then a choice's `:params` cannot be resolved and nothing renders.
  private readonly nativeRouter = inject(AngularRouter)
  private readonly matched = signal(this.nativeRouter.navigated)
  private readonly destroyRef = inject(DestroyRef)
  private readonly stopParams = this.router.subscribe(() => {
    this.routeParams.set(this.router.getParams())
    this.matched.set(true)
  })
  // The same declaration drives the list rules and the links: item params are applied to
  // the destination path, and the current route's params fill the rest.
  private readonly options = computed<ListRouteOptions<string, Selection>>(() => {
    const current = this.routeParams()
    const destinations: Record<string, ListRouteNavItem> = {}
    const declared = this.selectionsInput()
    if (declared !== undefined) {
      for (const [selection, item] of selectionEntries(declared)) {
        destinations[selection] = item.params
          ? { ...item, path: generatePath(item.path, { ...current, ...item.params }) }
          : item
      }
    }
    return {
      selections: destinations,
      defaultSelection: this.defaultSelectionInput(),
      pageParam: this.pageParamInput(),
      auth: this.authInput(),
    }
  })
  private readonly listRoute: UseListRouteResult<string, Selection> = useListRoute<
    string,
    Selection
  >(this.options)
  // React's `children` function receives the plain resolved list; the hook's signals are
  // read here so a template renders the same object.
  private readonly result = computed<ListRouteResult<string, Selection>>(() => {
    const list = this.listRoute
    return {
      page: list.page(),
      pageSize: list.pageSize(),
      offset: list.offset(),
      filters: list.filters(),
      selection: list.selection(),
      params: list.params(),
      canLoad: list.canLoad(),
      status: list.status(),
      redirectTo: list.redirectTo(),
      href: list.href,
      navigate: list.navigate,
      setPage: list.setPage,
      setFilters: list.setFilters,
      select: list.select,
    }
  })
  private readonly vcr = inject(ViewContainerRef)
  private readonly childrenContext: ListRouteNavContext<Selection> = {
    $implicit: this.result(),
    route: this.result(),
  }
  private childrenTemplate: TemplateRef<ListRouteNavContext<Selection>> | null = null
  private childrenView?: EmbeddedViewRef<ListRouteNavContext<Selection>>
  private viewReady = false

  /** The declared choices, in declaration order. */
  @Input() set selections(value: Record<Selection, ListRouteNavItem>) {
    this.selectionsInput.set(value)
  }

  /** Tie-breaker when several choices match, or the fallback when none does. */
  @Input() set defaultSelection(value: Selection | undefined) {
    this.defaultSelectionInput.set(value)
  }

  /** The pagination query key to reset on selection, defaulting to `page`. */
  @Input() set pageParam(value: string | undefined) {
    this.pageParamInput.set(value)
  }

  /** Authentication readiness for protected selections. */
  @Input() set auth(value: ListRouteAuth | undefined) {
    this.authInput.set(value)
  }

  /** Render the links in a list, with optional classes for the list and its items. */
  @Input() set list(value: { className?: string; itemClassName?: string } | undefined) {
    this.listInput.set(value)
  }

  /** App-owned link styling: one class, or a function of each choice's URL-derived state. */
  @Input() set linkClassName(
    value: string | ((state: ListRouteNavItemState<Selection>) => string | undefined) | undefined,
  ) {
    this.linkClassNameInput.set(value)
  }

  /** The template rendered after the navigation landmark, with the resolved list as its context (React's `children` render function). */
  @Input() set children(value: TemplateRef<ListRouteNavContext<Selection>> | undefined) {
    const next = value ?? null
    if (next === this.childrenTemplate) return
    this.childrenTemplate = next
    if (this.viewReady) this.renderChildren()
  }

  constructor() {
    this.destroyRef.onDestroy(this.stopParams)
    // React re-renders `children` with the new route; an embedded view's context object is
    // updated in place so its view never has to be rebuilt.
    effect(() => {
      const route = this.result()
      this.childrenContext.$implicit = route
      this.childrenContext.route = route
      // The nav (and its children) appear with the native router's first navigation.
      this.matched()
      this.renderChildren()
      this.childrenView?.markForCheck()
    })
  }

  /** Each declared choice with the attributes it renders, recomputed whenever the URL or a declaration changes. */
  protected readonly choices = computed<RenderedChoice<Selection>[]>(() => {
    const route = this.result()
    const linkClassName = this.linkClassNameInput()
    const itemClassName = this.listInput()?.itemClassName
    const declared = this.selectionsInput()
    if (declared === undefined) return []
    return selectionEntries(declared).map(([selection, item]) => {
      const active = route.selection === selection
      const disabled = item.disabled === true
      const to = disabled ? null : route.href({ selection })
      return {
        selection,
        text: labelText(item.label),
        labelTemplate: labelTemplateOf(item.label),
        disabled,
        className:
          typeof linkClassName === 'function'
            ? linkClassName({ selection, active, disabled })
            : linkClassName,
        state: active ? 'active' : 'inactive',
        molId: `list-route-${selection}`,
        current: active ? 'page' : null,
        href: to === null ? null : this.router.createHref(to),
        to,
        itemClassName,
      }
    })
  })

  /** Whether the choices render inside a `<ul>` / `<li>` list. */
  protected readonly withList: Signal<boolean> = computed(() => this.listInput() !== undefined)

  /** The `<ul>`'s class, when the app renders a list. */
  protected listClassName(): string | undefined {
    return this.listInput()?.className
  }

  protected onChoiceClick(event: MouseEvent, choice: RenderedChoice<Selection>): void {
    if (choice.to === null) return
    followRouterLink(event, choice.to, this.router)
  }

  /** Renders the children template, once the component's own view exists. */
  ngAfterViewInit(): void {
    this.viewReady = true
    this.renderChildren()
  }

  private renderChildren(): void {
    if (!this.viewReady || !this.matched() || this.childrenTemplate === null) {
      this.childrenView?.destroy()
      this.childrenView = undefined
      return
    }
    this.childrenView ??= this.vcr.createEmbeddedView(this.childrenTemplate, this.childrenContext)
  }
}
```

### Functions

#### `defineRoute(path, page)`

Register a literal Angular Router path and the component that renders it.

Create the route at module scope and add it to the routes passed to `provideRouter`.
Pass the component directly or as `{ Component }`. The declared path may keep the
leading slash every other routing bond uses (`/shelves/:shelf`): it is accepted here
and removed for Angular's route table, so one string serves the route, `href` and
`ListRouteNav`. Angular paths have no optional parameters and no splat. Inside the
component, call {@link injectRouteParams} with the same path to read its parameters.

Use the returned `href` for links and post-save navigation. It builds the destination
from the same path that mounts the page, with the parameter names that path requires.
Pass values from the saved response when identity can change.

```typescript
function defineRoute<const Path extends string>(
  path: Path,
  page: Type<unknown> | { Component: Type<unknown> },
): Route & {
  path: RouteTablePath<Path>
  href: (...args: LinkArgs<Path>) => string
}
```

- `path` — A route path, with or without a leading slash, including any `:name` parameters.
- `page` — The page component class, or `{ Component: page }`.

**Returns:** The path for Angular's route table, the component, and a function building a link to it.

#### `injectRouteParams()`

Read the parameters a route path declares, as a signal that follows URL changes.

Call it in a field initializer or constructor of the page component, where Angular's
injection context is active, and name the same path that `defineRoute` registered:
`params = injectRouteParams<'/shelves/:shelf'>()`. Values are percent-decoded.

```typescript
function injectRouteParams<Path extends string>(): Signal<AngularRouteParams<Path>>
```

**Returns:** A signal of the declared parameters; a parameter missing from the URL is `undefined`.

#### `lazyPage(load, options)`

Load a route's page on demand, inside the page's own area.

Use it instead of Angular's `loadComponent` for every page a route renders. Navigating
to a page whose code has not loaded yet then replaces the previous page at once: the
previous page leaves and this component's own `fallback` shows in the page's area until
its code arrives. With `loadComponent`, `@angular/router` awaits the code after guards
and resolvers and before activating the route, so a navigation the URL has already
moved for — the Back button, which the browser has already applied, or any route with
`urlUpdateStrategy: 'eager'` — keeps the previous page in the DOM under the new URL,
and a check such as `getByRole('heading')` finds the old page's headings. Layout routes
(an app shell around `<router-outlet>`) stay mounted either way.

The page's props are this component's `props` input, a record of the page's inputs,
which are bound onto the loaded component through `NgComponentOutlet`. Most pages read
their route parameters with `injectRouteParams` and take no props at all.

```typescript
function lazyPage<Page extends LazyLoadableComponent>(
  load: () => Promise<{ default: Page }>,
  options?: LazyPageOptions,
): Type<{ props: LazyPageProps<Page> }>
```

- `load` — Loads the page module, as `import()` does: `() => import('./pages/Article.js').then((m) => ({ default: m.Article }))`.
- `options` — Optional `fallback` component shown in the page's area while its code loads.

**Returns:** The component to use as a route's `component`: `{ path: 'article/:slug', component: Article }`. Its single input, `props`, takes the page's own props.

#### `createAngularRouter(router, location, options)`

Creates a molecule `Router` over the Angular Router.

Reads, navigation and notifications all go through Angular itself: `location()`
parses `router.url`, `push`/`replace` call `router.navigateByUrl` (returning its
promise), `go` calls `location.historyGo`, and `listen` follows `router.events` —
one notification per committed navigation (Angular's own links, the back button,
or this router's `navigate`), `'pop'` for a popstate navigation, nothing for a
cancelled, failed or skipped one. Each committed entry gets a location key in its
`history.state`, which Angular carries through Back and Forward, so the key names
the entry as React Router's does. Guards, named routes and the query/hash helpers
come from `createHistoryRouter`.

```typescript
function createAngularRouter(
  router: AngularRouter,
  location: Location,
  options?: AngularRouterOptions,
): Router
```

- `router` — Angular's `Router` (inject it, or get it from an `EnvironmentInjector`).
- `location` — Angular's `Location` over the same history (injected alongside the router; with `provideRouter` it shares the `LocationStrategy` the router uses).
- `options` — Molecule route definitions for named routes and route params.

**Returns:** A molecule `Router` driving the Angular Router.

#### `provideMoleculeRouter(options)`

Provides the molecule `Router` built on Angular's own `Router` and `Location`,
under `@molecule/app-angular`'s `ROUTER` token, so molecule packages and app code
(`inject(ROUTER)`, `@molecule/app-angular`'s services) navigate through Angular.

Apps add it next to Angular's own `provideRouter(routes)` — Angular keeps owning
its route config; the molecule options only name the routes molecule should know
({@link Router.navigateTo}, {@link Router.generatePath}).

The application's environment initializer bonds the adapter through
`@molecule/app-routing`'s `setRouter` when the app bootstraps (React's
`MoleculeRouterProvider` bonds in its mount effect), so `navigate()`/`getRouter()`
from `@molecule/app-routing` drive the real Angular Router instead of the core's
browser-history fallback. {@link AngularRouterOptions.onRouterReady} runs at that
same moment, once per router.

With HTTP and auth clients bonded, the router replaces the current location with
`/login` after a credential-free GET receives a 401 and the session is confirmed signed
out, as React's `BrowserRouter` does (`redirectSignedOutRejections` from
`@molecule/app-routing`), until the application is destroyed. `location.state.from`
holds the original location. Set `signInPath` to use a different sign-in route or
`signInPath: false` to opt out.

```typescript
function provideMoleculeRouter(options?: AngularRouterOptions): EnvironmentProviders
```

- `options` — Molecule route definitions for named routes and route params, and the optional ready callback.

**Returns:** Environment providers.

#### `useConsumedSearchParam(name)`

Consume a credential query parameter into component state and remove only that
parameter from the address through the Angular Router. The value survives local
rerenders, failed-submit retries and later query-only navigation; a newly arriving
value on the same mounted route is consumed too. Path, hash, unrelated query values
and router location state are retained.

The bond's router owns the URL replacement, so the Angular Router's location and
`window.location` agree. Its replace keeps the entry's app-owned state fields, including
ones Angular Router does not model: the bond reads every non-Angular key into the
location's state and carries it back on the replace (React Router drops those keys,
which is why React's hook re-adds them itself).

Call it in an injection context (a component field initializer or constructor).

```typescript
function useConsumedSearchParam(name: string): readonly [string, (value: string) => void]
```

- `name` — The credential query key to consume, for example `token` or `code`.

**Returns:** The consumed value and its setter, in the same tuple shape `@molecule/app-angular`'s `useConsumedSearchParam` returns: index 0 is the value (`''` before first consumption, kept current in place) and index 1 sets it.

#### `useListRoute(options)`

Own URL-backed pagination, filters and selected views without mirrored state or
navigation effects. Works inside any Angular application whose injector has Angular's
`Router` (`provideRouter(routes)`, or `provideRouter` plus `provideLocationMocks()` for
a memory history); no molecule provider is needed. Ordinary links, direct visits and
Back/Forward all read the same URL. Page links retain path parameters and unrelated
queries; changing filters or views resets the page atomically. Protected views wait for
auth and redirect only a confirmed signed-out session, with `state.returnTo` set.

Call it in an injection context (a component field initializer or constructor). The
options may be a signal: an auth status going from `loading` to `unauthenticated`
reaches the list on the same component, the way React re-renders `useListRoute` with
new options.

```typescript
function useListRoute<Filter extends string = string, Selection extends string = string>(
  options?: ListRouteOptionsInput<Filter, Selection>,
): UseListRouteResult<Filter, Selection>
```

- `options` — App-owned filter sources, view paths, pagination and optional auth readiness (or a signal of them).

**Returns:** Reactive list state as signals, plus link builders and navigation actions. Gate data queries with `canLoad`.

#### `matchPath(pattern, pathname, exact)`

#### `provider`
