# @molecule/app-routing-vue-router

Vue Router provider for `@molecule/app-routing`.

This package provides a Vue Router implementation of the molecule Router interface,
allowing you to use molecule's routing abstractions with Vue Router.

## Quick Start

```vue
<!-- App.vue (or a root-level component INSIDE the vue-router app) -->
<script setup lang="ts">
import { useLocation, useMoleculeRouterProvider } from '@molecule/app-routing-vue-router'

// Builds the adapter from vue-router's useRouter()/useRoute() AND bonds it, so
// molecule packages using @molecule/app-routing share THIS router. No manual
// setRouter watch needed.
const router = useMoleculeRouterProvider()

const location = useLocation()
function goToProfile() {
  router.value.navigate('/profile')
}
</script>

<template>
  <p>Current path: {{ location.pathname }}</p>
  <button @click="goToProfile">Go to Profile</button>
</template>
```

#### `defineRoute(path, page)`

Register a literal Vue Router path and give its page the params that path declares.

Create the route at module scope and add it to the `routes` passed to
`createRouter`. The render callback returns the page's vnodes and runs again
when the params change. Pass `{ Component: EditPage }` to give the page a typed
`params` prop automatically. A render callback can also supply app-owned props,
such as a view selected by a literal suffix. Keep page hooks inside the page
component. In nested routes, layout components own the params declared on their
own paths.

Use the returned `href` for links and post-save navigation. It builds the
destination from the same path that mounts the page, with the parameter names
required by that path, and writes it the way Vue Router writes a URL. Pass
values from the saved response when identity can change. A repeated parameter
(`:name+`, `:name*`) takes one string joined with `/`, and an omitted optional
parameter is left out of the link.

```typescript
function defineRoute<const Path extends string>(
  path: Path,
  page: RoutePage<Path>,
): RouteRecordRaw & { path: Path; href: (...[params]: LinkArgs<Path>) => string }
```

- `path` — A route path, including any named parameters.
- `page` — A component receiving `params`, or a function building the page's vnodes.

**Returns:** The route table entry and a function that builds a link to it.

#### `lazyPage(load, options)`

Load a route's page on demand, each page inside a fallback of its own.

Use it instead of `defineAsyncComponent` for every page a route names. Navigating to a
page whose code has not loaded yet then replaces the previous page at once: the
previous page unmounts and the new page shows `fallback` until its code arrives. A page
loaded through `defineAsyncComponent` (suspensible by default) instead suspends into the
nearest `<Suspense>`: when the boundary's own content is the page, it keeps the
previous page's content mounted while the new one is pending, so the URL already names
the new page while the old page is still there. Layout routes (an app shell around
`<RouterView>`) stay mounted either way.

The page's code is loaded with `suspensible: false` and `delay: 0`, so the fallback is
what renders while the code is on its way instead of an empty page that waits for the
shared boundary. Do not give the async component to a route record directly: Vue
Router warns (`VUE_ROUTER_R0029`) and handles loading itself; this returns the plain
wrapper component a route record should name.

```typescript
function lazyPage<Page extends LazyLoadableComponent>(
  load: () => Promise<{ default: Page }>,
  options?: LazyPageOptions,
): DefineSetupFnComponent<ComponentProps<Page>>
```

- `load` — Loads the page module, as for `defineAsyncComponent`: `() => import('./pages/Article.js').then((m) => ({ default: m.Article }))`.
- `options` — Optional `fallback` shown in the page's area while its code loads.

**Returns:** A component to use as a route record's `component`: `{ path: '/article/:slug', component: lazyPage(load, { fallback }) }`.

#### `useListRoute(options)`

Own URL-backed pagination, filters and selected views without mirrored state or navigation
effects. Works inside any Vue Router router — a plain `createRouter` app with no molecule
provider, or one wrapped in `MoleculeRouterProvider`. Ordinary links, direct visits, and
Back/Forward all read the same URL. Page links retain path parameters and unrelated
queries; changing filters or views resets the page atomically. Protected views wait for
auth and redirect only a confirmed signed-out session, with `state.returnTo` set.

The options may be reactive (a ref, a reactive object or a getter), so an auth status
going from `loading` to `unauthenticated` performs the sign-in redirect on the same
component, the way React re-renders `useListRoute` with new options.

```typescript
function useListRoute<Filter extends string = string, Selection extends string = string>(
  options?: MaybeRefOrGetter<ListRouteOptions<Filter, Selection>>,
): ComputedRef<ListRouteResult<Filter, Selection>>
```

- `options` — App-owned filter sources, view paths, pagination and optional auth readiness.

**Returns:** A computed ref of the list state plus link builders and navigation actions. Gate data queries with `canLoad`.

- `params` — The Vue Router params object from `route.params`.

Converts `URLSearchParams` into `QueryParams`. A key that appears more than once becomes an array

#### `stringifyQuery(params)`

Serializes `QueryParams` into a query string with a leading `?`, percent-encoding keys and values

```typescript

```

- `params` — The query params.

**Returns:** The query string, or `''` when there is nothing to write.

#### `matchPath(pattern, pathname, exact)`

Matches a route pattern against a pathname. `:name` captures one segment and `*` matches
anything. The whole pathname must match unless `exact` is `false`, which also accepts a pathname
that only starts with the pattern.

```typescript
function matchPath<Params extends RouteParams = RouteParams>(
  pattern: string,
  pathname: string,
  exact?: boolean,
): RouteMatch<Params> | null
```

- `pattern` — The pattern, such as `/users/:id` or `/files/*`.
- `pathname` — The pathname to match.
- `exact` — Whether the whole pathname must match (default `true`).

**Returns:** The match with its params, or `null`.

#### `generatePath(pattern, params)`

Builds a path from a pattern by putting each `:name` param in its place, percent-encoded. A
pattern given no params is returned as it is.

```typescript
function generatePath(pattern: string, params?: RouteParams): string
```

- `pattern` — The pattern, such as `/users/:id`.
- `params` — The param values.

**Returns:** The path.

#### `resolvePath(to, fromPathname)`

Resolves a path against the pathname it is relative to: an absolute `to` is returned as it is;
otherwise `to` is joined to `fromPathname`'s parent, with `..` moving up and `.` staying.

```typescript
function resolvePath(to: string, fromPathname: string): string
```

- `to` — The path to resolve.
- `fromPathname` — The pathname it is relative to.

**Returns:** The resolved pathname.

#### `normalizePath(path)`

Removes trailing slashes from a path, keeping `/` itself.

```typescript
function normalizePath(path: string): string
```

- `path` — The path.

**Returns:** The path without trailing slashes.

### Constants

#### `ListRouteNav`

Render every declared list view as a router link. The URL selects the active choice, and
selecting any view resets pagination through useListRoute. Native link behavior (new-tab
clicks, keyboard activation and history) is preserved. This is a navigation landmark,
not an ARIA tablist with local panels. No active-value state or change handler is needed.
When children are supplied, they render after the navigation landmark. Put loading and
empty results in that branch so a pending list never removes the filter controls.

The links are the component's OWN anchors: their `href` is the molecule router's
`createHref` (the href the native router's own link writes, base path and hash history
included), and a plain click navigates through `followRouterLink`, so a modified click,
a `target` other than `_self` or an external URL is left to the browser. The rendered
markup is exactly react-router's `ListRouteNav`: same elements, attributes and ARIA, no
styles of its own. The accessible name and every other native attribute (`id`, `class`,
listeners) arrive through Vue's attribute fallthrough onto the `<nav>`.

```typescript
const ListRouteNav: DefineSetupFnComponent<
  ListRouteNavProps<string>,
  {},
  {},
  ListRouteNavProps<string> & {},
  PublicProps
>
```

- `props` — Named destinations, translated labels, optional auth and native nav attributes.

**Returns:** The navigation landmark with all its choices, followed by any rendered content.

#### `MoleculeRouterProvider`

Provider component that builds ONE molecule `Router` over the current Vue Router and
bonds it via `@molecule/app-routing`'s `setRouter`, so `navigate()` / `getRouter()` from
core drive the REAL Vue Router. It also provides that exact router under
{@link MOLECULE_ROUTER_KEY}, so every descendant's `useMoleculeRouter()` returns it.

Bonding happens when the provider's setup runs, so core navigation reaches the native
router for the provider's whole mounted life. `onRouterReady` fires once per router: a
navigation or a re-render does not fire it again, and neither does changing only the
callback.

```typescript
const MoleculeRouterProvider: DefineComponent<
  ExtractPropTypes<{
    routes: { type: PropType<RouteDefinition[]>; default: undefined }
    onRouterReady: { type: PropType<(router: Router) => void>; default: undefined }
  }>,
  () => VNode[] | null,
  {},
  {},
  {},
  ComponentOptionsMixin,
  ComponentOptionsMixin,
  {},
  string,
  PublicProps,
  Readonly<
    ExtractPropTypes<{
      routes: { type: PropType<RouteDefinition[]>; default: undefined }
      onRouterReady: { type: PropType<(router: Router) => void>; default: undefined }
    }>
  > &
    Readonly<{}>,
  { routes: RouteDefinition[]; onRouterReady: (router: Router) => void },
  {},
  {},
  {},
  string,
  ComponentProvideOptions,
  true,
  {},
  any
>
```

#### `MOLECULE_ROUTER_KEY`

Injection key for the molecule `Router` a `MoleculeRouterProvider` provides to every
component below it. `useMoleculeRouter` reads it first, so mounting the provider once
makes each descendant composable return that exact router — with its named routes and
its bond — instead of a router owned by the calling component.

A provided value is normally the provider's `ComputedRef<Router>`; a plain `Router` is
accepted too, for an app that provides its adapter by hand.

```typescript
const MOLECULE_ROUTER_KEY: InjectionKey<ComputedRef<Router> | Router | undefined>
```

#### `provider`

Default Vue Router provider (no Vue Router instance: the core's browser router). For the
real Vue Router, use `createVueRouter` with `useRouter` — or the `useMoleculeRouter*`
composables, which bond it for you.

```typescript
const provider: Router
```

## Core Interface

Implements `@molecule/app-routing` interface.

## Bond Wiring

Setup function to register this provider with the core interface:

```typescript
import { setRouter } from '@molecule/app-routing'
import { provider } from '@molecule/app-routing-vue-router'

export function setupRoutingVueRouter(): void {
  setRouter(provider)
}
```

## Injection Notes

### Requirements

Peer dependencies:

- `@molecule/app-i18n` ^1.0.1
- `@molecule/app-routing` ^1.4.0
- `vue` ^3.4.20
- `vue-router` ^4.3.0 || ^5.0.0

### Runtime Dependencies

- `@molecule/app-i18n`
- `@molecule/app-routing`
- `vue`
- `vue-router`

- **Use `useMoleculeRouterProvider()` once near the app root to bond the router.**
  It builds the adapter from `useRouter()` and calls `@molecule/app-routing`'s
  `setRouter`, so other molecule packages' `navigate()`/`getRouter()` drive the real
  Vue Router (SPA navigation). One Vue Router instance gets one molecule Router for the
  app's lifetime. `useMoleculeRouter()` (non-bonding) still exists for local use; if you
  only ever call that, molecule packages silently get the core's auto-created
  fallback browser router and navigate with full-page reloads.
- **Do NOT wire the exported `provider` const** in a vue-router app — without a Vue
  Router instance it is the core's browser router, not Vue Router.
- Composables must run inside a component tree that has the vue-router plugin
  installed (`app.use(router)`), since they call `useRouter()`/`useRoute()`.

- **A route with parameters? Declare its page with `defineRoute`.** The route path is the
  source of truth for the page's parameter names: `:name`, `:name?`, `:name(regex)`,
  `:name+` and `:name*` each arrive as `string | undefined` (a repeated parameter is joined with
  `/`). For example:

  ```ts
  import { h } from 'vue'
  import { defineRoute } from '@molecule/app-routing-vue-router'

  const routes = [
    defineRoute('/shelves/:shelf', ({ shelf }) => h(Shelf, { name: shelf, view: 'all' })),
    defineRoute('/shelves/:shelf/saved', ({ shelf }) => h(Shelf, { name: shelf, view: 'saved' })),
  ]
  ```
