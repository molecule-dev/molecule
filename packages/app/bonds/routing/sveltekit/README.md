# @molecule/app-routing-sveltekit

SvelteKit provider for the molecule `Router` (`@molecule/app-routing`).

SvelteKit's client router is reachable only inside a SvelteKit app, through the
virtual modules `$app/navigation`, `$app/state` and `$app/paths`, which a package
cannot import.
So the app passes those functions in — a {@link SvelteKitNavigation} — and this bond
never imports `$app/*`. Build the router ONCE in the root layout and hand it to
`@molecule/app-svelte`'s `setMoleculeContext({ router })`; molecule packages then
navigate, read params/query and guard through the framework-neutral `Router` while
every navigation runs through SvelteKit (kit links, `goto`, and the back button all
notify the same subscribers).

## Quick Start

```svelte
<!-- src/routes/+layout.svelte -->
<script lang="ts">
  import { afterNavigate, goto } from '$app/navigation'
  import { resolve } from '$app/paths'
  import { page } from '$app/state'
  import { createSvelteKitNavigation, createSvelteKitRouter } from '@molecule/app-routing-sveltekit'
  import { setMoleculeContext } from '@molecule/app-svelte'

  // `afterNavigate` must be called during component initialisation, so build the
  // navigation here, in the root layout, once. `resolve('/')` gives the bond the base
  // path (or `#` under hash routing) kit's `goto` and links need.
  const router = createSvelteKitRouter(
    createSvelteKitNavigation({ goto, page, afterNavigate, rootHref: resolve('/') }),
  )

  setMoleculeContext({ router })
</script>
```

#### `SvelteKitNavigation`

The subset of SvelteKit's client router this bond drives — what an app builds from
`$app/navigation`, `$app/state` and `$app/paths` in its root layout and passes to
`createSvelteKitRouter`. `goto` and `page` are kit's own exports and `rootHref` is
kit's `resolve('/')`; `onNavigate` is the adapter around kit's `afterNavigate` (which
only runs during component initialisation and returns no unsubscribe: kit drops the
callback only when that component is destroyed, so the adapter owns the unsubscribe
contract).

```typescript
interface SvelteKitNavigation {
  /**
   * SvelteKit's programmatic navigation (`$app/navigation`'s `goto`, `@sveltejs/kit`
   * `types/index.d.ts`: "Allows you to navigate programmatically to a given route …
   * Returns a Promise that resolves when SvelteKit navigates (or fails to navigate, in
   * which case the promise rejects) to the specified `url`.").
   *
   * @param url - The URL to navigate to, with the app's base (or `#`) first.
   * @param opts - `replace`, `state` and `persistState`; the bond passes nothing else.
   * @returns Kit's navigation promise.
   */
  goto(url: string, opts?: KitGotoOptions): Promise<void>

  /**
   * Kit's `page` — `$app/state`'s `page` (`@sveltejs/kit` `types/index.d.ts`: "A read-only
   * reactive object with information about the current page … In the browser, the values
   * can be read at any time"). Read at call time for the current location and params.
   */
  page: KitPage

  /**
   * The href of the app's root, kit's `resolve('/')` from `$app/paths`: `'/'`,
   * `'/app/'` under `paths.base: '/app'`, or `'#/'` under `router: { type: 'hash' }`
   * (`resolve` "prefix[es] it with the base path, if any … In hash routing mode, the
   * returned URL starts with `#`"). Kit's `goto` does not add the base itself ("if you've
   * set `config.paths.base` and the URL is root-relative, you need to prepend the base
   * path"), so the bond puts this prefix before every path it navigates to or links.
   */
  rootHref: string

  /**
   * An adapter around kit's `afterNavigate` that adds what kit cannot give a package:
   * an unsubscribe. `afterNavigate` "must be called during a component initialization"
   * and stays active while the component is mounted. Build this with
   * `createSvelteKitNavigation` in the root layout: it registers one `afterNavigate`
   * callback and fans it out, so the router can listen and stop listening repeatedly
   * without stacking kit callbacks.
   *
   * @param listener - Called once per committed navigation.
   * @returns A function that stops the listener.
   */
  onNavigate(listener: KitNavigateListener): () => void
}
```

### Functions

#### `createSvelteKitRouter(kit, options)`

Builds the molecule `Router` over a SvelteKit app's client router.

The app passes kit's `goto`, kit's `page`, its root href and an `afterNavigate` adapter (see
{@link SvelteKitNavigation.onNavigate} and the package example) once, from the root
layout, and registers the result with `@molecule/app-svelte`'s `setMoleculeContext`.

Subscribers hear exactly one call per navigation kit commits — kit links, the back
button, and this router's own `navigate` — because kit fires `afterNavigate` only
after a navigation completed (`@sveltejs/kit` 3.2 `src/runtime/client/client.js:2289`):
a navigation kit's own guards cancelled never reaches `afterNavigate`, so it never
notifies. The history holds no resources of its own: the kit subscription is released
through the unsubscribe `listen` returns.

```typescript
function createSvelteKitRouter(kit: SvelteKitNavigation, options?: SvelteKitRouterOptions): Router
```

- `kit` — The SvelteKit pieces (see {@link SvelteKitNavigation}).
- `options` — Route definitions, and an optional `onRouterReady` called once with the router.

**Returns:** The router.

#### `createSvelteKitNavigation(kit)`

Builds the {@link SvelteKitNavigation} that `createSvelteKitRouter` takes, from kit's own
exports. Call it during the root layout's component initialisation, where kit allows
`afterNavigate`. It registers ONE `afterNavigate` callback and passes each navigation to
the listeners the router adds and removes, so stopping and restarting a subscription
never leaves a second kit callback behind (a hand-written adapter whose unsubscribe does
nothing would notify subscribers twice after that).

```typescript
function createSvelteKitNavigation(kit: SvelteKitExports): SvelteKitNavigation
```

- `kit` — Kit's `goto`, `page`, `afterNavigate` and `resolve('/')`.

**Returns:** The navigation pieces for `createSvelteKitRouter`.

## Injection Notes

### Requirements

Peer dependencies:

- `@molecule/app-i18n` ^1.0.1
- `@molecule/app-routing` ^1.4.0
- `@sveltejs/kit` ^3.0.0

### Runtime Dependencies

- `@molecule/app-i18n`
- `@molecule/app-routing`
- `@sveltejs/kit`

- **Kit 3.** The bond drives kit 3's `goto` options (`replace`, `persistState`) and
  `$app/state`'s `page`; a kit 2 app uses `@molecule/app-routing-sveltekit` 1.x.
- **Read the location through the router, not `page`.** Molecule packages see
  `getLocation()`/`subscribe()`, with paths inside the app (no base, no `#`);
  `router.createHref(path)` is the href kit's links carry.
- **The exported `provider` constant is NOT for SvelteKit apps** — it is the core
  browser-history router, for molecule code outside SvelteKit. Wiring it in a SvelteKit
  app moves history behind kit's back.
- Navigation state is `page.state`, so it must be an object; kit's own `sveltekit:*`
  history keys are stripped from `getLocation().state`.
