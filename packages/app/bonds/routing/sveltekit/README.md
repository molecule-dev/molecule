# @molecule/app-routing-sveltekit

SvelteKit provider for the molecule `Router` (`@molecule/app-routing`).

SvelteKit's client router is reachable only inside a SvelteKit app, through the
virtual modules `$app/navigation`, `$app/state` and `$app/paths`, which a package
cannot import. So the app passes those functions in — a {@link SvelteKitNavigation} —
and this bond never imports `$app/*`.

Mount `MoleculeRouterProvider` ONCE in the root layout, around the rendered page. It
builds one molecule `Router` over the app's SvelteKit navigation, calls
`@molecule/app-routing`'s `setRouter` with it, and supplies it to the components below:
this bond's `useMoleculeRouter`, `useMoleculeQuery`, `useMoleculeNavigate` and
`useIsActive`, and `@molecule/app-svelte`'s router hooks, guards and layouts. Core
`navigate()` / `getRouter()` drive the same router — kit links, `goto` and the back button
all notify the same subscribers, before kit renders the new page.

With HTTP and auth clients bonded, the router `MoleculeRouterProvider` builds
replaces the current URL with `/login` after a credential-free GET receives a 401 and
the session is confirmed signed out, as React's `BrowserRouter` does. `location.state.from`
holds the original location. Set `signInPath` to use a different sign-in route or pass
`signInPath={false}` to opt out.

## Quick Start

```svelte
<!-- src/routes/+layout.svelte -->
<script lang="ts">
  import { goto } from '$app/navigation'
  import { resolve } from '$app/paths'
  import { navigating, page } from '$app/state'
  import {
    createSvelteKitNavigation,
    MoleculeRouterProvider,
  } from '@molecule/app-routing-sveltekit'

  // Build the navigation here, in the root layout's initialisation, once: it watches kit's
  // `page` from there. `resolve('/')` gives the bond the base path (or `#` under hash
  // routing) kit's `goto` and links need.
  const navigation = createSvelteKitNavigation({ goto, page, navigating, rootHref: resolve('/') })
</script>

<MoleculeRouterProvider {navigation}>
  {@render children()}
</MoleculeRouterProvider>
```

```svelte
<script lang="ts">

<button onclick={() => navigate('/orders', { replace: true })}>Reset</button>
<a href="/orders" class={$isOpenActive ? 'active' : ''}>All orders</a>
```

#### `SvelteKitNavigation`

The subset of SvelteKit's client router this bond drives — what an app builds from
`$app/navigation`, `$app/state` and `$app/paths` in its root layout and passes to
`createSvelteKitRouter`. `goto` and `page` are kit's own exports and `rootHref` is
kit's `resolve('/')`; `onNavigate` tells the router when kit's `page` changed.
`createSvelteKitNavigation` builds all four from kit's exports.

```typescript
interface SvelteKitNavigation {
  /**
   * SvelteKit's programmatic navigation (`$app/navigation`'s `goto`, `@sveltejs/kit`
   * `types/index.d.ts`: "Allows you to navigate programmatically to a given route …
   * Returns a Promise that resolves when SvelteKit navigates (or fails to navigate, in
   * which case the promise rejects) to the specified `url`.").
   *
   * @param url - The URL to navigate to, with the app's base (or `#`) first.
   * @param opts - `replace`, `state` and `persistState`; the bond passes nothing else.
   * @returns Kit's navigation promise.
   */
  goto(url: string, opts?: KitGotoOptions): Promise<void>

  /**
   * Kit's `page` — `$app/state`'s `page` (`@sveltejs/kit` `types/index.d.ts`: "A read-only
   * reactive object with information about the current page … In the browser, the values
   * can be read at any time"). Read at call time for the current location and params.
   */
  page: KitPage

  /**
   * The href of the app's root, kit's `resolve('/')` from `$app/paths`: `'/'`,
   * `'/app/'` under `paths.base: '/app'`, or `'#/'` under `router: { type: 'hash' }`
   * (`resolve` "prefix[es] it with the base path, if any … In hash routing mode, the
   * returned URL starts with `#`"). Kit's `goto` does not add the base itself ("if you've
   * set `config.paths.base` and the URL is root-relative, you need to prepend the base
   * path"), so the bond puts this prefix before every path it navigates to or links.
   */
  rootHref: string

  /**
   * Calls `listener` each time kit's `page` moves to a new URL or a new `page.state`, before
   * kit renders the page for it. `createSvelteKitNavigation` watches kit's `page` once and
   * passes each change to every listener, so the router can listen and stop listening
   * repeatedly.
   *
   * @param listener - Called once per change of kit's page.
   * @returns A function that stops the listener.
   */
  onNavigate(listener: KitNavigateListener): () => void
}
```

#### `Router`

Client-side router providing navigation, guards, route matching, and history control.

All routing providers must implement this interface.

```typescript
interface Router {
  /**
   * Returns the current route location (pathname, search, hash, state).
   */
  getLocation(): RouteLocation

  /**
   * Gets the current route params.
   */
  getParams<T extends RouteParams = RouteParams>(): T

  /**
   * Gets the current query params.
   */
  getQuery(): QueryParams

  /**
   * Gets a specific query parameter.
   */
  getQueryParam(key: string): string | undefined

  /**
   * Gets the current hash.
   */
  getHash(): string

  /**
   * Navigates to a path. A path that is only a query or a hash (`'?tab=2'`, `'#top'`) stays on
   * the current page, as React Router's `navigate` does; a hash alone drops the current query.
   */
  navigate(path: string, options?: NavigateOptions): void

  /**
   * Navigates to a named route.
   */
  navigateTo(
    name: string,
    params?: RouteParams,
    query?: QueryParams,
    options?: NavigateOptions,
  ): void

  /**
   * Goes back in history.
   */
  back(): void

  /**
   * Goes forward in history.
   */
  forward(): void

  /**
   * Goes to a specific point in history.
   */
  go(delta: number): void

  /**
   * Updates the current query params.
   */
  setQuery(params: QueryParams, options?: NavigateOptions): void

  /**
   * Updates a specific query parameter.
   */
  setQueryParam(key: string, value: string | undefined, options?: NavigateOptions): void

  /**
   * Updates the current hash.
   */
  setHash(hash: string, options?: NavigateOptions): void

  /**
   * Checks if a path matches the current location.
   *
   * @returns `true` if the path matches the current route.
   */
  isActive(path: string, exact?: boolean): boolean

  /**
   * Matches a path pattern against a pathname.
   */
  matchPath<Params extends RouteParams = RouteParams>(
    pattern: string,
    pathname: string,
  ): RouteMatch<Params> | null

  /**
   * Generates a URL from a named route.
   */
  generatePath(name: string, params?: RouteParams, query?: QueryParams): string

  /**
   * The `href` an anchor to the in-app `path` carries, as the native router's own link
   * writes it (its base path prefixed, or `#/…` under a hash history), so a middle-click,
   * a new tab or a copied link opens the same page a click does. A `path` that is only a
   * query or a hash (`'?tab=2'`, `'#top'`) is the current page's, as `navigate` reads it
   * and as React Router's `<Link>` writes it: `'#top'` on `/docs?x=1` is `/docs#top`.
   *
   * @param path - Pathname with optional query string and hash, as passed to `navigate`.
   * @returns The `href`.
   */
  createHref(path: string): string

  /**
   * Calls `listener` once after each navigation the router commits, however it started (a
   * link, the back button, `navigate`), with the new location and the navigation action.
   * A router calls it before the browser paints the new page, so a component that renders
   * from a listener (the framework bindings' `useLocation` and `useParams` do) shows the new
   * location in the same paint as the new page. The router conformance cases of
   * `@molecule/app-framework-conformance/routing` check that at every paint.
   *
   * @param listener - Called with the new location and the navigation action.
   * @returns Stops calling `listener`.
   */
```

### Functions

#### `createSvelteKitNavigation(kit)`

Builds the {@link SvelteKitNavigation} that `createSvelteKitRouter` takes, from kit's own
exports. Call it during the root layout's component initialisation (Svelte creates the
effect it uses only then, and throws `effect_orphan` anywhere else).

It watches kit's `page` once, with a pre-effect, and passes each move to a new URL or a new
`page.state` to every listener the router adds. Svelte runs a component's pre-effects
before the components below it update, so the router's subscribers (the binding's stores,
a layout's active item) read the new location in the same update that renders the new
page: no component shows the previous location beside it. A navigation kit cancelled never
changes `page`, so it is never heard, and an invalidation that keeps the URL and the state
is not heard either.

```typescript
function createSvelteKitNavigation(kit: SvelteKitExports): SvelteKitNavigation
```

- `kit` — Kit's `goto`, `page`, `navigating` and `resolve('/')`.

**Returns:** The navigation pieces for `createSvelteKitRouter`.

#### `createSvelteKitRouter(kit, options)`

Builds the molecule `Router` over a SvelteKit app's client router.

The app passes the {@link SvelteKitNavigation} `createSvelteKitNavigation` built from kit's
`goto`, `page`, `navigating` and root href, once, from the root layout. `MoleculeRouterProvider` builds it there and bonds it with
`@molecule/app-routing`'s `setRouter`; a layout that builds it by hand does the same, and
may also supply it to `@molecule/app-svelte`'s `setMoleculeContext`.

Subscribers hear one call each time kit's `page` moves to a new URL or a new `page.state`,
before kit renders the page for it: kit links, the back button, `goto`, this router's own
`navigate`, and the changes kit makes outside a navigation (a link to a hash on the same
page, shallow routing). A navigation kit's own guards cancelled never changes `page`, so it
never notifies. The action is `'pop'` for kit's back/forward navigations and the one this
router started for its own; anything else is heard as a `'push'`, because kit does not say
whether a change it made replaced the current entry (`goto(url, { replaceState: true })`
from app code, shallow `replaceState`) or moved between shallow entries. The history holds
no resources of its own: the subscription is released through the unsubscribe `listen`
returns.

```typescript
function createSvelteKitRouter(kit: SvelteKitNavigation, options?: SvelteKitRouterOptions): Router
```

- `kit` — The SvelteKit pieces (see {@link SvelteKitNavigation}).
- `options` — Route definitions, an optional `onRouterReady` called once with the router, and the `signInPath` a signed-out GET 401 sends the visitor to (`false` turns it off).

**Returns:** The router.

#### `useConsumedSearchParam(name)`

Takes a one-time credential (a reset `token`, an OAuth `code`) out of the URL and keeps
it in memory, React's `useConsumedSearchParam` in Svelte's idiom: a readable store of
the `[value, set]` tuple, through the router the nearest `MoleculeRouterProvider` built
over the app's SvelteKit navigation. The parameter is removed with a replace navigation
that keeps the path, the hash, the other query values and the location state; the value
survives renders and later query-only navigation, Back to an entry restores the value
consumed there, and a new value arriving on the same mounted route is consumed too.

Call it during a component's initialisation, where Svelte reads context. It connects on
mount, as React's effect does, so a server render never navigates.

```typescript
function useConsumedSearchParam(name: string): UseConsumedSearchParamStore
```

- `name` — The query key to consume, for example `token` or `code`.

**Returns:** A readable store of the consumed value (`''` before the parameter was ever present) and a setter (a form clears it after a successful submit).

#### `useIsActive(path, exact)`

Whether `path` is the current location (or a prefix of it), React's `useIsActive()` in
`@molecule/app-svelte`'s shape: a readable store that re-evaluates after every
navigation the router commits, so a nav link reading `$isActive` updates on a link
click, a back button or a navigation made here.

Call it during a component's initialisation, where Svelte reads context.

```typescript
function useIsActive(path: string, exact?: boolean): Readable<boolean>
```

- `path` — The path to check.
- `exact` — Whether to require an exact match (default: a prefix match).

**Returns:** A readable store of whether the path is active.

#### `useListRoute(options)`

URL-backed pagination, filters and selected views, React's `useListRoute` in Svelte's
idiom: the page, the filters and the view live in the URL only, so a reload, a shared
link and Back all show the same list. Each list field is a readable store that follows
the location, and the actions are plain functions, through the router the nearest
`MoleculeRouterProvider` built over the app's SvelteKit navigation. Built on
`resolveListRoute` from `@molecule/app-routing`, so every framework binding returns the
same result.

A signed-out visit to a view with `requiresAuth` replaces the entry with
`options.auth.redirectTo`, carrying `state.returnTo`; until auth is confirmed `canLoad`
is `false`.

The options may be a plain value or a readable store of one (a store holding
`undefined` means the default options): an auth status moving from `loading` to
`unauthenticated` re-resolves the list — and performs the sign-in redirect — on the
same component, the way React re-renders `useListRoute`.

Call it during a component's initialisation, where Svelte reads context.

```typescript
function useListRoute<Filter extends string = string, Selection extends string = string>(
  options?: MaybeReadable<ListRouteOptions<Filter, Selection> | undefined>,
): UseListRouteResult<Filter, Selection>
```

- `options` — Filter sources, view paths, pagination and optional auth readiness (or a store of them).

**Returns:** Each list field as a readable store, and its link builder and navigation actions.

### Requirements

Peer dependencies:

- `@molecule/app-bond` ^1.0.1
- `@molecule/app-i18n` ^1.0.1
- `@molecule/app-routing` ^1.5.0
- `@molecule/app-svelte` ^3.10.0
- `@sveltejs/kit` ^3.0.0
- `svelte` ^5.7.0

### Runtime Dependencies

- `@molecule/app-bond`
- `@molecule/app-i18n`
- `@molecule/app-routing`
- `@molecule/app-svelte`
- `@sveltejs/kit`
- `svelte`

- **The provider calls `setRouter`.** On initialisation it bonds the router it built, so
  other molecule packages' `navigate()`/`getRouter()` drive SvelteKit's client router
  instead of pushing `window.history` behind kit's back. `onRouterReady` receives that
  router once, after the bond exists; changing the callback later does not call it again.
- **Kit 3.** The bond drives kit 3's `goto` options (`replace`, `persistState`) and
  `$app/state`'s `page`; a kit 2 app uses `@molecule/app-routing-sveltekit` 1.x.
- **Read the location through the router, not `page`.** Molecule packages see
  `getLocation()`/`subscribe()`, with paths inside the app (no base, no `#`);
  `router.createHref(path)` is the href kit's links carry.
- **The exported `provider` constant is NOT for SvelteKit apps** — it is the core
  browser-history router, for molecule code outside SvelteKit. Wiring it in a SvelteKit
  app moves history behind kit's back.
- **The hooks are component-initialisation hooks**, as React's are render hooks: Svelte
  reads context then, so call them in a component's `<script>`, never in a module, an
  event handler or an async callback.
- **SvelteKit gives a layout its page as `children`.** The bond provides no routed view, so
  `@molecule/app-svelte`'s `RoutedView` throws and says to render `{@render children()}`.
- **A change kit makes outside a navigation is heard as a push.** Following a link to a hash
  on the same page, shallow routing's `pushState`/`replaceState`, or a back/forward move
  between such entries changes kit's `page` with no navigation kind, and kit does not say
  whether a `goto(url, { replaceState: true })` from app code replaced the entry; this
  router's own `navigate` and kit's back/forward navigations carry their real action.
- Navigation state is `page.state`, so it must be an object; kit's own `sveltekit:*`
  history keys are stripped from `getLocation().state`.
