# @molecule/app-routing-sveltekit

SvelteKit provider for the molecule `Router` (`@molecule/app-routing`).

SvelteKit's client router is reachable only inside a SvelteKit app, through the
virtual modules `$app/navigation` and `$app/stores`, which a package cannot import.
So the app passes those functions in — a {@link SvelteKitNavigation} — and this bond
never imports `$app/*`. Build the router ONCE in the root layout and hand it to
`@molecule/app-svelte`'s `setMoleculeContext({ router })`; molecule packages then
navigate, read params/query and guard through the framework-neutral `Router` while
every navigation runs through SvelteKit (kit links, `goto`, and the back button all
notify the same subscribers).

## Quick Start

```svelte
<!-- src/routes/+layout.svelte -->
<script lang="ts">
  import { afterNavigate, goto, replaceState } from '$app/navigation'
  import { page } from '$app/stores'
  import { createSvelteKitNavigation, createSvelteKitRouter } from '@molecule/app-routing-sveltekit'
  import { setMoleculeContext } from '@molecule/app-svelte'

  // `afterNavigate` must be called during component initialisation, so build the
  // navigation here, in the root layout, once.
  const router = createSvelteKitRouter(
    createSvelteKitNavigation({ goto, replaceState, page, afterNavigate }),
  )

  setMoleculeContext({ router })
</script>
```

#### `SvelteKitNavigation`

The subset of SvelteKit's client router this bond drives — what an app builds from
`$app/navigation` and `$app/stores` in its root layout and passes to
`createSvelteKitRouter`. `goto` and `page` are kit's own exports; `onNavigate` is the
adapter the app writes around kit's `afterNavigate` (which only runs during component
initialisation and cannot unsubscribe, so the adapter owns the unsubscribe contract).

```typescript
interface SvelteKitNavigation {
  /**
   * SvelteKit's programmatic navigation (`$app/navigation`'s `goto`,
   * `@sveltejs/kit` `types/index.d.ts`: "Allows you to navigate programmatically to a
   * given route … Returns a Promise that resolves when SvelteKit navigates (or fails to
   * navigate, in which case the promise rejects) to the specified `url`.").
   *
   * @param url - The path to navigate to (pathname, query string and hash).
   * @param opts - `replaceState` and `state`; the bond passes nothing else.
   * @returns Kit's navigation promise.
   */
  goto(url: string, opts?: KitGotoOptions): Promise<void>

  /**
   * Kit's `page` store — `$app/stores`' `page` (`@sveltejs/kit` `types/index.d.ts`:
   * "export const page: Readable<Page>")
   * or any `Readable<Page>`-shaped store (including `$app/state`'s reactive `page`
   * wrapped in one). Read at call time for the current location and params.
   */
  page: Readable<KitPage>

  /**
   * An adapter around kit's `afterNavigate` that adds what kit cannot give a package:
   * an unsubscribe. `afterNavigate` "must be called during a component initialization"
   * and stays active while the component is mounted. Build this with
   * `createSvelteKitNavigation` in the root layout: it registers one `afterNavigate`
   * callback and fans it out, so the router can listen and stop listening repeatedly
   * without stacking kit callbacks.
   *
   * @param listener - Called once per committed navigation.
   * @returns A function that stops the listener.
   */
  onNavigate(listener: KitNavigateListener): () => void
}
```

#### `KitPageState`

### Functions

#### `createSvelteKitRouter(kit, options)`

Builds the molecule `Router` over a SvelteKit app's client router.

The app passes kit's `goto`, kit's `page` store and an `afterNavigate` adapter (see
{@link SvelteKitNavigation.onNavigate} and the package example) once, from the root
layout, and registers the result with `@molecule/app-svelte`'s `setMoleculeContext`.

Subscribers hear exactly one call per navigation kit commits — kit links, the back
button, and this router's own `navigate` — because kit fires `afterNavigate` only
after a navigation completed (`@sveltejs/kit` `src/runtime/client/client.js:1987-1989`):
a navigation kit's own guards cancelled never reaches `afterNavigate`, so it never
notifies. The history holds no resources of its own: the kit subscription is released
through the unsubscribe `listen` returns.

```typescript
function createSvelteKitRouter(kit: SvelteKitNavigation, options?: SvelteKitRouterOptions): Router
```

- `kit` — The SvelteKit pieces (see {@link SvelteKitNavigation}).
- `options` — Route definitions.

**Returns:** The router.

#### `createSvelteKitNavigation(kit)`

Builds the {@link SvelteKitNavigation} that `createSvelteKitRouter` takes, from kit's own
exports. Call it during the root layout's component initialisation, where kit allows
`afterNavigate`. It registers ONE `afterNavigate` callback and passes each navigation to
the listeners the router adds and removes, so stopping and restarting a subscription
never leaves a second kit callback behind (a hand-written adapter whose unsubscribe does
nothing would notify subscribers twice after that).

```typescript
function createSvelteKitNavigation(kit: SvelteKitExports): SvelteKitNavigation
```

- `kit` — Kit's `goto`, `replaceState`, `page` and `afterNavigate`.

**Returns:** The navigation pieces for `createSvelteKitRouter`.

The conventional typed provider constant: the core's browser-history router

stories, or a plain page that mounts molecule components. Inside a SvelteKit app do
