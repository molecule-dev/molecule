# @molecule/app-billing-angular

Angular pricing page + checkout flow for the molecule.dev billing kit.

Components:
`<PricingPage />` — public pricing table that fetches `/api/billing/tiers`
and posts to `/api/billing/checkout` when the user clicks Upgrade.

`<BillingStatusBadge />` — compact account-page status display that
shows the current tier and offers a cancel-subscription button.

`<LimitsList>` / `<LimitsItem>` — building blocks for the
`renderLimits` template: a stacked checklist row with check / dash icon.

Hooks:
`usePricingTiers<TLimits>()` → `UseHttpResult<PricingTiersResponse<TLimits>>`
`useBillingStatus<TLimits>()` → `UseHttpResult<BillingStatus<TLimits>>`
`useStartCheckout()` → `{ data, loading, error, start(priceId) }`
`useCancelSubscription()` → `{ data, loading, error, cancel() }`

The API side of this kit lives in `@molecule/api-entitlements` +
`@molecule/api-payments-stripe`. Wire those into your project (any
mlcl flagship template that includes `@molecule/api-entitlements`
already exposes the `/api/billing/*` routes), then drop the pricing page
onto a `/pricing` route.

  /**
   * Optional callback invoked after a successful cancel. Most apps will
   * navigate the user back to settings or refresh the page from here.
   */
  onCanceled?: () => void

  /** Optional className applied to the outer wrapper. */
  className?: string

  /**
   * Whether to render the cancel-subscription button when the user is on a
   * paid tier. Defaults to `true`.
   */
  showCancel?: boolean

  /** Reactive translation, read in the injection context. */
  protected readonly i18n = useTranslation()

  /** The translation function for the template. */
  protected t = this.i18n.t

  /** The bonded ClassMap (styling tokens resolve at render time). */
  protected readonly cm: UIClassMap = getClassMap()

  /** The signed-in user's billing status. */
  protected readonly status = useBillingStatus()

  /** The cancel action and its async state. */
  protected readonly cancelState = useCancelSubscription()

  /** React's loading root (`<span>`), while the status is loading. */
  @ViewChild('loadingRoot') private loadingRoot?: ElementRef<HTMLElement>
  /** React's loaded root (`<div>`), while a status is shown. */
  @ViewChild('statusRoot') private statusRoot?: ElementRef<HTMLElement>

  private readonly host: ElementRef<HTMLElement> = inject(ElementRef)

  constructor() {
    // React's root varies with the load state and is nothing without a status: whichever
    // root renders stands in front of the host's place, and the host itself leaves the page.
    usePlacement(() => {
      const root = this.loadingRoot?.nativeElement ?? this.statusRoot?.nativeElement
      if (root) placeElementBefore(root, this.host.nativeElement)
      setElementPresent(this.host.nativeElement, false)
    })
  }

  /**
   * The translated "Current plan: <tier>" line.
   *
   * @returns The translated label.
   */
  currentPlanLabel(): string {
    return this.t(
      'billing.status.currentPlan',
      { tierName: this.status.data()?.name ?? '' },
      { defaultValue: 'Current plan: {{tierName}}' },
    )
  }

  /**
   * Whether the cancel button renders (React's `showCancel = true` default,
   * and never on the free tier).
   *
   * @returns True for a paid tier when the caller has not disabled it.
   */
  showsCancel(): boolean {
    const free = this.status.data()?.isFree ?? false
    return (this.showCancel ?? true) && !free
  }

  /**
   * The cancel button's class list (React's `cm.button({ variant: 'outline', size: 'sm' })`).
   *
   * @returns The class string.
   */
  cancelClasses(): string {
    return this.cm.button({ variant: 'outline', size: 'sm' })
  }

  /** Cancels the subscription and reports a confirmed cancellation. */
  async handleCancel(): Promise<void> {
    const result = await this.cancelState.cancel()
    if (result?.canceled) this.onCanceled?.()
  }
}

## E2E Tests

Integration checklist — drive the real UI (live preview, no mocks), adapt
each item to this app's actual screens/flows, and check every box off one
by one. A box you can't check is an integration bug to fix — not a skip:

- [ ] The pricing route renders every tier from `/api/billing/tiers` with name,
      price, and per-tier limits — no empty table, no `undefined` cells.
- [ ] The signed-in user's CURRENT tier is visibly marked (highlighted / "current
      plan") and its Upgrade button is disabled or absent.
- [ ] Clicking Upgrade on another tier posts to `/api/billing/checkout` and the
      page follows the returned checkout handoff (button is not a dead click).
- [ ] The billing-status badge on the account screen shows the live tier, and its
      cancel action updates the shown status after confirmation.
- [ ] A signed-out visitor can still view the public pricing table.
- [ ] If the tiers endpoint fails, the page shows a visible error state — not a
      blank page or spinner forever.
