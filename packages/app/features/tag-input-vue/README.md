# @molecule/app-tag-input-vue

Vue tag-token input and tag-chip display.

Exports:

- `<TagList>` — read-only saved tags on detail/preview screens. Renders every
  value in order; optional `itemClassName` and `renderTag` keep app-owned markup.
- `<TagChip>` — standalone labeled chip with optional remove button.
- `<TagInput>` — controlled tokenizer: Enter, comma, or Tab adds the
  draft; blur commits a non-empty draft; Backspace on an empty field
  removes the last token. Enter never submits an enclosing form.
- `useTagInput()` — the same tag-entry behavior without markup, for an
  app whose markup is already decided (a design system, a spec's selectors):
  spread `fieldProps` on a renderer-neutral `TextField` or `inputProps` on
  your own `<input>`, render the tags yourself, and call `remove(i)` from
  your own remove control.

This is the Vue counterpart of `@molecule/app-tag-input-react`: the same
exports, the same props (React names) and the same DOM for the same input.

## Quick Start

```ts
import { defineComponent, h, type PropType, ref } from 'vue'

import { TagChip, TagInput, TagList, useTagInput } from '@molecule/app-tag-input-vue'

const TagEditor = defineComponent({
  setup() {
    const tags = ref<string[]>(['vue'])
    return () =>
      h('div', [
        h(TagInput, {
          value: tags.value,
          onChange: (next: string[]) => {
            tags.value = next
          },
          maxTags: 10,
        }),
        h(
          TagChip,
          { onRemove: () => (tags.value = tags.value.filter((t) => t !== 'vue')) },
          {
            default: () => 'vue',
          },
        ),
      ])
  },
})

// Render the saved record's tags on the destination screen as well as in its editor.
const RecordLabels = defineComponent({
  props: { labels: { type: Array as PropType<string[]>, required: true } },
  setup(props) {
    return () => h(TagList, { value: props.labels })
  },
})

// App-owned markup: the input and the tag list are siblings.
const ArticleTags = defineComponent({
  setup() {
    const tags = ref<string[]>([])
    const { inputProps, remove } = useTagInput(() => ({
      value: tags.value,
      onChange: (next: string[]) => {
        tags.value = next
      },
    }))
    return () =>
      h('div', [
        h('input', { ...inputProps.value }),
        h(
          'ul',
          tags.value.map((tag, i) =>
            h('li', { key: tag }, [
              h('button', { type: 'button', onClick: () => remove(i) }, 'Remove'),
              ` ${tag}`,
            ]),
          ),
        ),
      ])
  },
})
```

### Functions

#### `useTagInput(options)`

Tag-entry behavior without markup, for an app whose markup is already
decided (a design system, a spec's selectors). Bind `inputProps` onto your
own `<input>` — or `fieldProps` onto a renderer-neutral `TextField` — and
render the tags however you need, calling `remove(i)` from your own remove
control. `<TagInput>` is this composable plus default markup.

Enter commits the draft and never submits an enclosing form: its default is
canceled even when the draft is blank, rejected, or past `maxTags`. Comma and
Tab commit a non-empty draft (an empty Tab keeps normal focus traversal);
blur commits a non-empty draft; Backspace on an empty draft removes the last
tag. A keystroke the input method owns is left to it, including the Enter
that confirms a composition and arrives with the legacy key code 229.

```typescript
function useTagInput(
  options: UseTagInputOptions | Ref<UseTagInputOptions> | (() => UseTagInputOptions),
): UseTagInputResult
```

- `options` — The controlled tag list and its rules, or a ref/getter of them so a component's changed props reach the same composable instance.

**Returns:** The draft, input props and add/remove actions (see {@link UseTagInputResult}).

### Runtime Dependencies

- `@molecule/app-ui`
- `@molecule/app-ui-vue`
- `@molecule/app-vue`
- `vue`

- `<TagInput>` and `<TagChip>` need the app's i18n provider and a ClassMap
  bond wired (`useTranslation()` / `getClassMap()` throw otherwise).
  `useTagInput` itself needs neither; the app owns its markup and text.
- A chip's visible text is its default slot. Node-valued props may also be
  passed as a same-named slot.
- `add(raw)` adds an independent value without changing the draft (for
  example, a suggestion). A custom draft-commit control should call
  `add(draft)` followed by `setDraft('')` to avoid a later blur reusing it.
  Actions compose within one tick and reconcile to the controlled `value`.
- Committing happens on Enter/comma/Tab AND on blur — clicking away
  with a non-empty draft adds a tag; keep that in mind in forms.
- Enter inside the field is always swallowed: a blank, rejected, or
  over-`maxTags` draft does nothing and never submits an enclosing
  form. An empty Tab keeps normal browser focus traversal.
- Default `normalize` trims whitespace and rejects empties +
  duplicates; pass your own to lowercase, validate, or map values
  (return `null` to reject).
- When `maxTags` is reached further input is silently discarded (the
  draft clears, no error UI).
- `<TagChip>` ships no background surface of its own — add one via
  `className` if bare text chips are too subtle in your theme.
