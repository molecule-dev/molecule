# @molecule/app-search-ui-solid

Solid search UI for `@molecule/app-client-search`.

The Solid counterpart of `@molecule/app-search-ui-react` — the same props
(React names) and the same DOM for the same input. Three pieces that fit a
`useSearchSession` from `@molecule/app-client-search-solid`:
{@link SearchBox} (the field, its clear button and shortcut cap, a help icon
whose tooltip shows the search syntax, an `afterField` slot for the
consumer's own tabs, the active filter chips and the hit count),
{@link SearchResults} (ranked rows with the matched terms marked, hover
prefetch, an optional action per row; the keyboard-active row is marked with
`aria-current` and announced through a polite status region), and
{@link QuickSearchDialog} (both in a `mod+k` dialog named for screen readers
by its `label`, "Search" by default). Every class comes from
the ClassMap's search tokens (`searchField`, `resultList`, …), so a UI bond
restyles all of it at once.

## Quick Start

```tsx
import { Link, useTranslation } from '@molecule/app-solid'
import { useSearchSession } from '@molecule/app-client-search-solid'
import { SearchBox, SearchResults } from '@molecule/app-search-ui-solid'
import type { SearchResultLinkProps } from '@molecule/app-search-ui-solid'

function Catalog() {
  const { t } = useTranslation()
  const session = useSearchSession({
    docs: packages,
    options: PACKAGE_INDEX_OPTIONS,
    rememberKey: 'catalog.search',
    onOpen: (p) => navigate(`/packages/${p.name}`),
  })
  const renderLink = (p: SearchResultLinkProps) => (
    <Link
      to={p.href}
      state={p.state}
      class={p.className}
      onClick={p.onClick}
      data-mol-id={p['data-mol-id']}
    >
      {p.children}
    </Link>
  )
  return (
    <>
      <SearchBox
        value={session.query()}
        onChange={session.setQuery}
        onKeyDown={session.onKeyDown}
        inputRef={session.inputRef}
        placeholder={t('catalog.search', undefined, { defaultValue: 'Search packages' })}
        count={session.hits().length}
        filters={session.parsed().filters}
        onRemoveFilter={session.removeFilter}
        onClear={session.clear}
        examples={['category:auth', 'type:bond']}
      />
      <SearchResults
        hits={session.hits()}
        view={(p) => ({
          href: `/packages/${p.name}`,
          title: `@molecule/${p.name}`,
          description: p.description,
          meta: [p.type, p.category],
          mono: true,
        })}
        activeIndex={session.activeIndex()}
        onActivate={session.setActiveIndex}
        onOpen={session.open}
        onPrefetch={session.prefetch}
        renderLink={renderLink}
        emptyText={t('catalog.empty', undefined, { defaultValue: 'Nothing matches' })}
      />
    </>
  )
}
```

#### `QuickSearchDialog(props)`

A search dialog for `mod+k`: the box on top with focus, the hits below in
a scrolling pane, and the key hints in the footer. Before anything is
typed the pane shows `idleText` rather than a browse list. Enter opens the active
hit through the session (which closes the dialog by the caller's `onOpen`).
The dialog is named for screen readers through `label` (or the translated
"Search" default).

- `props` — See {@link QuickSearchDialogProps}.

**Returns:** The dialog, or nothing while closed.

#### `SearchBox(props)`

A search field: a leading icon, the input, a help icon that shows the
syntax on hover, an × to clear, and the shortcut cap; under it, whatever
`afterField` holds, then the active filters as removable chips and the
hit count. The field stays mounted, and its text with it, across searches.

```typescript
function SearchBox(props: SearchBoxProps): JSX.Element
```

- `props` — See {@link SearchBoxProps}.

**Returns:** The field and its status row.

#### `SearchResults(props)`

The ranked hits: title and description with the matched terms marked, the
meta line, hover making a row active and warming its page. The whole row is
the link, so the list is a plain list of links (no listbox roles: an
option's children are presentational and would hide the row's link and
action); the active row is marked with `aria-current` on its `<li>` and
announced through a polite, visually hidden status region after the list.

React keys each row by the hit's `id` value, so a re-passed or re-ordered
array keeps the rendered rows per id. Solid's `For` keys by reference, so
the rows are keyed through stable per-id records: the record for an id is
created once and reused, while the row's content reads the CURRENT hit for
that id reactively.

```typescript
function SearchResults<T>(props: SearchResultsProps<T>): JSX.Element
```

- `props` — See {@link SearchResultsProps}.

**Returns:** The list, or the empty state.

### Runtime Dependencies

- `@molecule/app-client-search`
- `@molecule/app-client-search-solid`
- `@molecule/app-solid`
- `@molecule/app-ui`
- `@molecule/app-ui-solid`
- `solid-js`

- **Pass a router link through `renderLink`**, or every row is a full page
  load: the list renders a plain `<a>` by default because it does not know
  your router. A plain click calls `onOpen` (which the session turns into
  navigation); a modified click is left to the browser so "open in new tab" works.
- The box does not own the text: bind `value`/`onChange` to a session (or
  any state) and it stays mounted, with its text, across searches. Do not
  remount it per search.
- `placeholder`, `emptyText` and the like are already-translated strings
  from the app; the package translates only its own chrome ("Clear
  search", "{{count}} results", "Search tips") through `@molecule/app-locales-search-ui`.
- The quick dialog needs a session created with `syncUrl: false` and
  `onEscape: onClose`; the page's own session keeps the URL.
