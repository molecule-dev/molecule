### Classes

#### `TraceWaterfall`

TraceWaterfall component.

Datadog/Jaeger-style distributed-trace waterfall: each span renders as a
horizontal bar positioned by `startTime`, scaled to the trace's total
duration and indented by parent depth, under a time axis. Service name shows
as a colored tag beside the operation name; bar color encodes status.

React's root is the `<div role="region">` when there are rows, the bare
`emptyState` node when the trace is empty and a node was given, and the
`<div role="status">` fallback otherwise — three different roots, so the
rendered content stands in front of the host's place and the host itself
leaves the page (`placeContentBefore` + `setElementPresent`). The empty state
arrives as a node-valued input (`emptyState`, a `TemplateRef`).

Styling is fully ClassMap-driven for layout. Only color attributes (status
colors, service-tag colors, bar fill) and pixel-perfect axis geometry use
inline styles — properties ClassMap does not model.

  spans: Span[] = []

  rootSpanId?: string

  selectedSpanId?: string

  onSpanClick?: (span: Span) => void

  private readonly activeLocale = useLocale()

      placeContentBefore(this.host.nativeElement, this.host.nativeElement)

    return this.layout().rows

      defaultValue: 'Distributed trace waterfall',
    })

        name: row.span.name,
        service: row.span.service ?? '',
        duration: this.durationText(row),
      },
      { defaultValue: '{{service}} · {{name}} · {{duration}}' },

    const out: AxisTick[] = []
    for (let i = 0; i < AXIS_TICK_COUNT; i++) {
      const fraction = i / (AXIS_TICK_COUNT - 1)
      out.push({
        left: `${fraction * 100}%`,

#### `layoutSpans(spans, rootSpanId)`

Build a hierarchical, time-positioned layout for a flat list of spans.

Behavior:

- Spans are linked by `parentId`. A span whose `parentId` is missing from
  the input (or undefined) is treated as a root.
- If `rootSpanId` is provided AND that id exists in the input, the
  layout is restricted to that span and its descendants. Otherwise every
  root contributes its own subtree.
- Children are sorted by `startTime` ascending (stable for equal times).
- `traceStart` / `traceEnd` are derived from the included spans only.
- `traceDuration` is clamped to `>= 1` so callers can safely divide.

The output is intentionally framework-agnostic: callers (such as
`<TraceWaterfall>`) can render the rows however they like.

```typescript
function layoutSpans(spans: Span[], rootSpanId?: string): SpanLayout
```

- `spans` — Flat list of spans, in any order.
- `rootSpanId` — Optional id to use as the visible root.

**Returns:** Layout rows, sorted depth-first, with normalized fractions.

#### `serviceColor(service)`

Deterministically derive a hex color from a service name. Used for the
color tag next to each span row. Same input always yields the same color
across renders so a service is visually stable.

```typescript
function serviceColor(service: string): string
```

- `service` — Service / component label.

**Returns:** A hex color string suitable for an inline `style.background`.

renders values below 1 as microseconds and 1000+ as seconds, so
seconds-unit spans get wrong axis/row labels even though bar layout itself
