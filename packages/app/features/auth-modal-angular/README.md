# @molecule/app-auth-modal-angular

`@molecule/app-auth-modal-angular` — the shared in-app login / signup /
upgrade flow. Mount `<mol-auth-modal-mount>` ONCE inside the app's
providers (where the `@molecule/app-angular` auth hooks work) and every
in-app `/login` / `/signup` link opens `<mol-auth-modal>` instead of
navigating, while `/pricing` / `/billing` links open the upgrade flow in
a new tab (session auto-refreshes when the user returns) — no
navigation, no reload, no lost work. OAuth runs in a popup
(`loginViaPopup`), so social login never navigates the host either.

  constructor() {
    // Leaves no element in the page while closed (React renders nothing). The open
    // signal is written from a document listener, which refreshes only this view.
    useHostPresence(() => this.open())
  }

  /** Opens the modal on the given form (React's `openAuth`). */
  private openAuth(next: AuthModalMode): void {
    this.mode.set(next)
    this.open.set(true)
  }

  /**
   * The window focus return: refresh the session and run `onUpgradeReturn`,
   * but only after an upgrade tab was opened here.
   */
  private readonly onFocus = (): void => {
    if (!this.upgradeTabOpened) return
    this.upgradeTabOpened = false
    this.auth.refresh().catch((_error: unknown) => {
      // Best-effort freshness pass: the user may have returned without a
      // session to refresh (never logged in, or the API has no refresh
      // path) — not an error worth surfacing on a simple tab focus.
    })
    this.onUpgradeReturn?.()
  }

  /**
   * The capture-phase click interceptor (React's document click effect).
   * Handlers read the current inputs at call time, the way React's
   * re-subscribed effect does.
   */
  private readonly onClick = (e: MouseEvent): void => {
    if (e.defaultPrevented || e.button !== 0 || e.metaKey || e.ctrlKey || e.shiftKey || e.altKey)
      return
    const anchor = (e.target as HTMLElement | null)?.closest('a[href]') as HTMLAnchorElement | null
    if (!anchor) return

    const origin = window.location.origin
    const authMode = authModeForHref(href, origin, this.authPaths ?? DEFAULT_AUTH_PATHS)
    if (authMode) {
      e.preventDefault()
      e.stopPropagation()
      this.openAuth(authMode)
      return
    }
    const upgradePath = upgradePathForHref(href, origin, this.upgradePaths ?? DEFAULT_UPGRADE_PATHS)
    if (upgradePath) {
      e.preventDefault()
      e.stopPropagation()
      if (this.onUpgradeIntercept) {
        this.onUpgradeIntercept(upgradePath)
        return
      }
      this.upgradeTabOpened = true
      window.open(upgradePath, '_blank', 'noopener,noreferrer')
    }
  }

  /** Installs the document/window listeners (React's mount effect). */
  ngOnInit(): void {
    window.addEventListener('focus', this.onFocus)
    document.addEventListener('click', this.onClick, true)
  }

  /** Removes the document/window listeners (React's effect cleanup). */
  ngOnDestroy(): void {
    window.removeEventListener('focus', this.onFocus)
    document.removeEventListener('click', this.onClick, true)
  }

  /** Closes the modal (React's `setOpen(false)`). */
  close(): void {
    this.open.set(false)
  }

Interception is capture-phase on `document` and matches plain
left-clicks on `<a href>` whose resolved pathname is in `authPaths`
(default `/login`, `/signup`) or `upgradePaths` (default `/pricing`,
`/billing`) — modifier/middle clicks still navigate normally, and
non-anchor buttons that call `navigate()` are NOT intercepted. Hosts
that render pricing in-place pass `onUpgradeIntercept` and own that UI

- the post-upgrade session refresh. `AuthModalMount` must render inside
  the app's auth/HTTP providers (it calls `useAuth`), and the standalone
  `/login` & `/signup` pages should stay routed — they are the fallback
  for modifier clicks and deep links. App-specific extras (stash a guest
  id, claim guest work, invalidate usage) go in `onBeforeAuth` /
  `onAuthenticated`. The modal's `auth.modal.*` strings are homed in the
  `@molecule/app-locales-common` bond (79 languages), alongside the
  `auth.login.*` / `auth.signup.*` keys the modal also renders.

If the signup API requires a human-verification challenge (Turnstile /
hCaptcha), pass BOTH `captchaSlot` (the widget, rendered in the signup
form, as `[slot=captchaSlot]` projected content or a `TemplateRef`
input) and `captchaSolved` (which gates the submit). Rendering the widget
on the standalone `/signup` page alone is NOT enough: this modal is what
a `/signup` link actually opens, so the in-app signup would POST with no
token and the API would answer "complete the verification challenge"
while no challenge is on screen. Login is not gated, so the slot is
unmounted in login mode.
