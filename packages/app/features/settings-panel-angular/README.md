# @molecule/app-settings-panel-angular

`@molecule/app-settings-panel-angular` — the Angular counterpart of
`@molecule/app-settings-panel-react`: the same runtime export names, the
same props, and the same DOM for the same input. A composable,
batteries-included settings panel.

`<SettingsContainer [onClose]="…">` owns the layout and publishes `onClose`
via the settings-panel context; each section component is standalone and
loads its own data through the binding's hooks:

- `AccountSection` (as `<section mol-settings-account>`) — name/email edit
  (`PATCH /api/users/:id` over the auth client's profile transport).
- `AppearanceSection` — dark-mode toggle (`useTheme()`).
- `AuthSection` — password change + TOTP two-factor
  (`POST /api/users/:id/verify-two-factor`).
- `NotificationsSection` — web-push toggle (see the exported
  `enablePushOnCurrentDevice` / `disablePushOnCurrentDevice` helpers and
  their documented device-row contract).
- `BillingSection` — read-only plan display (`GET /api/billing/status`),
  or `TiersUpgradeSection` — full Stripe upgrade/cancel flow
  (`/api/billing/tiers|checkout|cancel`). Use one or the other, not both.
- `DevicesSection` / `ThisDeviceSection` — device list + current device
  (`GET/DELETE /api/devices`).
- `LogOutDeleteSection` — sign out + delete account
  (`DELETE /api/users/:id`).

#### `AccountSection`

AccountSection component.

Account fields over the shared profile lifecycle. Background validation uses
the auth client's configured route, mapping and session ownership guards.

`UserProfile.email` is optional (phone/handle accounts have none), so email
is validated only when non-empty and a blank email is never sent: clearing
the field leaves the stored address untouched, and a name-only account can
still save its name.

The host IS the `<section>` React renders. Blur-to-save is wired on the
`<form>` (`focusout` bubbles from the inputs, which the Angular `Input`
component does not re-emit) and dispatches on the blurred control's id —
exactly React's per-input `saveOnBlur`.

The email input's `aria-invalid` / `aria-describedby` are synced onto its
native control by an effect, the way React's rest props do
(`aria-invalid={emailError ? …} : undefined` — absent when valid, so the
attribute must be REMOVED, which the UI `Input`'s own always-on binding
cannot express); this mirrors what the UI package's `FormField` does when it
patches a control directly.

```typescript
@Component({
  selector: 'section[mol-settings-account]',
  standalone: true,
  imports: [Flex, Input, Spinner],
  template: `<div mol-flex [align]="'center'" [gap]="'sm'" [className]="cm.sp('mb', 3)">
      <h3 [class]="cm.sectionHeading">
        {{ t('settings.account', undefined, { defaultValue: 'Account' }) }}
      </h3>
      @if (profile.isSubmitting()) {
        <div mol-spinner [size]="'xs'"></div>
      }
    </div>
    <form [class]="cm.stack(3)" (submit)="submitForm($event)" (focusout)="saveOnFormBlur($event)">
      <div>
        <label for="settings-name" [class]="cm.formLabelSmall">{{
          t('settings.name', undefined, { defaultValue: 'Name' })
        }}</label>
        <div
          mol-input
          #nameField
          [id]="'settings-name'"
          type="text"
          autocomplete="name"
          [size]="'sm'"
          [value]="nameValue()"
          [name]="'name'"
          (change)="nameChange($event)"

      <div>

          t('settings.email', undefined, { defaultValue: 'Email' })
        }}</label>

          [name]="'email'"

            id="settings-email-error"
            role="alert"

          >
            {{ fieldError }}
          </p>
        }
        @if (saveError(); as submitError) {
          <p role="alert" [class]="cm.cn(cm.textSize('xs'), cm.textError, cm.sp('mt', 1))">
            {{ submitError }}
          </p>
        }
      </div>
    </form>`,
})
export class AccountSection implements AfterViewInit {
  /** The account fields over the shared profile lifecycle. */
  protected readonly profile = useProfileForm<UserProfile, AccountValues>({
    defaultValues: { name: '', email: '' },
    toValues: (user) => ({ name: user.name ?? '', email: user.email ?? '' }),
    toPatch: ({ email, ...changes }) => (email ? { ...changes, email } : changes),
  })

  /** The name field's registration (its onChange marks the field edited). */
  protected readonly nameReg = this.profile.register('name')
  /** The email field's registration, with the email format validation. */
  protected readonly emailReg = this.profile.register('email', { email: true })

  /** Reactive translation, read in the injection context. */
  protected readonly i18n = useTranslation()

  private readonly authClient = useAuthClient<UserProfile>()

  /** The name field's host (the native control is looked up inside it). */
  @ViewChild('nameField', { read: ElementRef }) nameField?: ElementRef<HTMLElement>
  /** The email field's host. */
  @ViewChild('emailField', { read: ElementRef }) emailField?: ElementRef<HTMLElement>

  /** The bonded ClassMap (styling tokens resolve at render time). */
  protected readonly cm: UIClassMap = getClassMap()

  /** The translation function for the template. */
  protected t = this.i18n.t

  /** The name field's controlled value (form state is the change signal). */
  protected readonly nameValue = computed(() => {
    void this.profile.formState()
    return this.profile.getValue('name')
  })

  /** The email field's controlled value. */
  protected readonly emailValue = computed(() => {
    void this.profile.formState()
    return this.profile.getValue('email')
  })

  /** The email field's validation message, or null when valid. */
  protected readonly emailError = computed(() => {
    void this.profile.formState()
    return this.profile.getError('email') ?? null
  })

  /** The latest save failure's display text, or null. */
  protected readonly saveError = computed((): string | null => {
    const error = this.profile.error()
    if (!error) return null
    return error instanceof Error
      ? error.message
      : this.t('settings.failedToUpdateProfile', undefined, {
          defaultValue: 'Failed to update profile',
        })
  })

  /** The cached native email control (re-resolved when the view is rebuilt). */
  private emailControl: HTMLInputElement | null = null

  /** Starts the auth client's background session validation (React's mount effect) and wires the email control's aria sync. */
  constructor() {
    // A provider's background validation must not cause an unhandled
    // rejection: render its auth state while useProfileForm reports mutation
    // failures.
    void this.authClient.validateSession?.().catch((_error) => {})
    // React's rest props on the email input: present with the error target
    // while the field is invalid, REMOVED while valid. An effect (view hooks
    // are skipped by signal-driven refreshes) keeps it exact.
    effect(() => {
      const error = this.emailError()
      untracked(() => this.syncEmailAria(error))
    })
  }

  /** Applies the initial rest-prop state (hooks run on the mount passes). */
  ngAfterViewInit(): void {
    const name = this.nameField?.nativeElement.querySelector('input')
    if (name) this.nameReg.ref?.(name)
    this.resolveEmailControl()
    this.syncEmailAria(this.emailError())
  }

  /**
   * Forwards the field's `change` (React's text-input onChange).
   * @param event - The native input event the UI Input re-emitted.
   */
  protected nameChange(event: Event): void {
    this.nameReg.onChange(event)
  }

  /**
   * Forwards the field's `change` (React's text-input onChange).
   * @param event - The native input event the UI Input re-emitted.
   */
  protected emailChange(event: Event): void {
    this.emailReg.onChange(event)
  }

  /**
   * Submits the form (React's `profile.formProps` onSubmit).
   * @param event - The native submit event.
   */
  protected submitForm(event: Event): void {
    this.profile.formProps.onSubmit(event)
  }

  /**
   * Saves on blur, exactly React's per-input `saveOnBlur`: the field's
   * registration blur first (touch + field validation), then the profile
   * submit.
   * @param event - The bubbling focusout from one of the two inputs.
   */
  protected saveOnFormBlur(event: FocusEvent): void {
    const id = (event.target as HTMLElement | null)?.id
    if (id === 'settings-name') this.saveOnBlur(this.nameReg)
    else if (id === 'settings-email') this.saveOnBlur(this.emailReg)
  }

  /**
   * React's `saveOnBlur` wrapper: one blur, then one submit.
   * @param registration - The blurred field's registration.
   */
  private saveOnBlur(registration: { onBlur: () => void }): void {
    registration.onBlur()
    void this.profile.submit()
  }

  /**
   * Looks the native email control up inside the UI `Input`'s host and
   * registers it as the field ref (React's spread `ref`, so a failed submit
   * focuses the first invalid field).
   */
  private resolveEmailControl(): void {
    this.emailControl =
      (this.emailField?.nativeElement.querySelector('input') as HTMLInputElement | null) ?? null
    if (this.emailControl) this.emailReg.ref?.(this.emailControl)
  }

  /**
   * Applies React's rest-prop state for one error value: `aria-invalid` and
   * `aria-describedby` on the native control while invalid, removed while
   * valid.
   * @param error - The field's validation message, or null.
   */
  private syncEmailAria(error: string | null): void {
    this.resolveEmailControl()
    const control = this.emailControl
    if (!control) return
    if (error) {
      control.setAttribute('aria-invalid', 'true')
      control.setAttribute('aria-describedby', 'settings-email-error')
    } else {
      control.removeAttribute('aria-invalid')
      control.removeAttribute('aria-describedby')
    }
  }
}
```

#### `AppearanceSection`

AppearanceSection component.

Appearance section — dark-mode toggle wired to the theme bond. The host IS
the `<section>` React renders.

Apps that expose other appearance knobs (font size, density, etc.) can
either add more sub-components to this package or render their own section
in line with this one.

The `id` / `aria-label` rest props of React's `<Switch>` are host
attributes here: the UI `Switch` moves host attributes onto its visible
trigger on every check, so the label follows the locale the same way. The
controlled `checked` is re-synced by an effect (React re-renders the hidden
checkbox's property; see {@link ControlledSwitchSync}).

```typescript
  protected t = this.i18n.t

  /** The bonded ClassMap (styling tokens resolve at render time). */
  protected readonly cm: UIClassMap = getClassMap()

  /** The theme switch's host element (the hidden checkbox lives inside). */
  @ViewChild('themeSwitch', { read: ElementRef }) themeSwitch?: ElementRef<HTMLElement>

  /** The controlled-`checked` sync (created once the host exists). */
  private sync?: ControlledSwitchSync

  /** Re-syncs the switch's hidden checkbox whenever the mode changes. */
  constructor() {
    effect(() => {
      const checked = this.isDark()
      untracked(() => this.runSync(checked))
    })
  }

  /** Captures the mount-time attribute state (hooks run on the mount passes). */
  ngAfterViewInit(): void {
    this.runSync(this.isDark())
  }

  /**
   * Runs the controlled-`checked` sync once the switch host exists.
   * @param checked - The controlled value this render shows.
   */
  private runSync(checked: boolean): void {
    if (!this.sync && this.themeSwitch) {
      this.sync = new ControlledSwitchSync(this.themeSwitch.nativeElement)
    }
    this.sync?.sync(checked)
  }
}
```

#### `AuthSection`

AuthSection component.

Authentication section — change password (modal) + two-factor (TOTP) setup.
React's root is a fragment (the `<section>` plus two modals) or nothing at
all for an OAuth-only user (React's `return null`); those nodes render in the
host's place and the host itself never appears in the page.

Two-factor uses the real enrollment flow against the user resource's
`POST /users/:id/verify-two-factor` endpoint (`@molecule/api-two-factor`):

- Enable → `{action:'setup'}` returns a QR code + secret to scan into an
  authenticator app → user enters the 6-digit code → `{action:'enable', token}`.
- Disable → user enters a current code → `{action:'disable', token}`.
  The current status is read from `/users/me`. (This replaces the previous
  boolean toggle, which PATCHed `twoFactorEnabled` — a field the update
  handler deliberately ignores — so it never actually enrolled 2FA.)

Auto-hides for OAuth-only users (`user.oauthServer` truthy) since
password / 2FA wouldn't apply. If the app's API has no two-factor
provider bonded, setup fails gracefully with an inline message.

`useChangePassword`'s state is a live getter over a plain object (the
Angular binding's `usePromise` port), so the pending/error reads are
mediated by a version signal the handlers bump at React's re-render points.

```typescript
  /** Whether the current device's push subscription is on. */
  protected readonly enabled = signal(false)
  /** Whether an enable/disable chain is running (the switch is disabled). */
  protected readonly busy = signal(false)
  /** The inline failure message, or null. */
  protected readonly error = signal<string | null>(null)

  /** The push switch's host element (the hidden checkbox lives inside). */
  @ViewChild('pushSwitch', { read: ElementRef }) pushSwitch?: ElementRef<HTMLElement>

  /** The controlled-`checked` sync (created once the host exists). */
  private sync?: ControlledSwitchSync

  /** The bonded ClassMap (styling tokens resolve at render time). */
  protected readonly cm: UIClassMap = getClassMap()

  /**
   * Reads the server's push state for THIS device (React's mount effect).
   * Resolves false (never throws) when the devices endpoint is unavailable;
   * a result that lands after unmount is dropped like React's cancelled one.
   */
  constructor() {
    let cancelled = false
    inject(DestroyRef).onDestroy(() => {
      cancelled = true
    })
    // Server truth for THIS device; resolves false (never throws) when the
    // devices endpoint is unavailable.
    void readCurrentDevicePushEnabled(this.http).then((serverEnabled) => {
      if (!cancelled && serverEnabled) this.enabled.set(true)
    })
    // React's controlled `checked` re-render, as an effect (view hooks are
    // skipped by signal-driven refreshes).
    effect(() => {
      const checked = this.enabled()
      untracked(() => this.runSync(checked))
    })
  }

  /** Captures the mount-time attribute state (hooks run on the mount passes). */
  ngAfterViewInit(): void {
    this.runSync(this.enabled())
  }

  /**
   * Runs the controlled-`checked` sync once the switch host exists.
   * @param checked - The controlled value this render shows.
   */
  private runSync(checked: boolean): void {
    if (!this.sync && this.pushSwitch) {
      this.sync = new ControlledSwitchSync(this.pushSwitch.nativeElement)
    }
    this.sync?.sync(checked)
  }

  /**
   * The switch's change: the hidden checkbox's `checked` at emit time (React
   * reads `e.target.checked` before its controlled restore).
   * @param event - The native change event the UI Switch re-emitted.
   */
  protected pushToggleChanged(event: Event): void {
    const checked = (event.target as HTMLInputElement | null)?.checked ?? false
    void this.handleToggle(checked)
  }

  /**
   * The localized message for one toggle failure (React's `failureMessage`).
   * @param result - The failed toggle result.
   * @returns The message text.
   */
  private failureMessage(result: Extract<PushToggleResult, { ok: false }>): string {
    switch (result.reason) {
      case 'permission-denied':
        return this.t('settings.pushPermissionDenied', undefined, {
          defaultValue: 'Notification permission was denied.',
        })
      case 'server-unconfigured':
        return this.t('settings.pushServerUnavailable', undefined, {
          defaultValue: 'Push notifications are not configured on this server.',
        })
      case 'register-failed':
        // The push provider throws already-localized messages (not supported /
        // no service worker in a dev build / push-service rejection).
        return (
          result.message ||
          this.t('settings.pushUpdateFailed', undefined, {
            defaultValue: 'Could not update push notification settings.',
          })
        )
      case 'persist-failed':
        // `result.message` here is the HTTP client's error (a status line or a
        // network error), not text written for the user, so it is not shown.
        return this.t('settings.pushUpdateFailed', undefined, {
          defaultValue: 'Could not update push notification settings.',
        })
    }
  }

  /**
   * Runs one enable/disable chain (React's `handleToggle`).
   * @param next - Whether the switch turned on.
   */
  private async handleToggle(next: boolean): Promise<void> {
    if (this.busy()) return
    this.busy.set(true)
    this.error.set(null)
    try {
      if (next) {
        const result = await enablePushOnCurrentDevice({
          http: this.http,
          requestPermission: this.push.requestPermission,
          register: this.push.register,
        })
        if (result.ok) {
          this.enabled.set(true)
        } else {
          this.error.set(this.failureMessage(result))
        }
      } else {
        const result = await disablePushOnCurrentDevice({
          http: this.http,
          unregister: this.push.unregister,
        })
        // The switch goes off locally either way; a failed server clear is
        // still reported so the user knows sends may continue.
        this.enabled.set(false)
        if (!result.ok) {
          this.error.set(this.failureMessage(result))
        }
      }
    } finally {
      this.busy.set(false)
    }
  }
}
```

#### `SettingsContainer`

SettingsContainer component.

Outer settings-panel layout: padded vertical stack that hosts the section
sub-components (projected content). The host IS the `<div>` React renders
(`div[mol-settings-container]`), with `cm.sp('p', 6)` + `cm.stack(6)`.

Publishes `onClose` to descendants via the settings-panel context so
`<LogOutDeleteSection>` etc. can dismiss the panel after an action without
explicit prop threading. The registration happens in the constructor, which
Angular runs before any projected child is created.

```typescript
@Component({

  standalone: true,
  inputs: ['onClose'],
  host: {
    '[class]': 'classes()',
  },
  template: `<ng-content></ng-content>`,
})
export class SettingsContainer {
  /** Closes the settings panel, published to sections through the container context. */
  onClose?: () => void

  private readonly host = inject(ElementRef)

  /** The context registration removal (set in the constructor). */
  private removeContext: () => void = () => {}

  /** Registers the container context before any projected child resolves it. */
  constructor() {
    this.removeContext = provideSettingsPanelContext(this.host.nativeElement, () => this.onClose)
    inject(DestroyRef).onDestroy(this.removeContext)
  }

  /** The bonded ClassMap (styling tokens resolve at render time). */
  protected readonly cm: UIClassMap = getClassMap()

  /**
   * Computes the container class list (`cm.sp('p', 6)` + `cm.stack(6)`).
   * @returns The class string.
   */
  classes(): string {
    return this.cm.cn(this.cm.sp('p', 6), this.cm.stack(6))
  }
}
```

#### `ThisDeviceSection`

ThisDeviceSection component.

"This device" detail strip — OS, browser, online/offline. The host IS the
`<section>` React renders.

Reads everything from `@molecule/app-device` through the `useDevice` hook
(`deviceInfo` and `isOnline()`), so the bonded device provider decides what
it shows. No side effects, no app-specific state.

The network line's `isOnline()` call is mediated by a `computed` over the
i18n notifications (its only change signal), so the provider is read once
per render — the same call count React's render records — and again on a
locale switch, exactly like a React re-render.

```typescript
@Component({
  selector: 'section[mol-settings-this-device]',

          {{ t('settings.platform', undefined, { defaultValue: 'Platform' }) }}
        </dt>
        <dd>{{ platformLabel() }}</dd>

        <dt [class]="cm.textMuted">
          {{ t('settings.browser', undefined, { defaultValue: 'Browser' }) }}
        </dt>
        <dd>{{ browserLabel() }}</dd>
      </div>
      <div mol-flex [justify]="'between'">
        <dt [class]="cm.textMuted">

export class ThisDeviceSection {
  /** The bonded device provider's info (read once, like React's memoized hook). */
  protected readonly device = useDevice()

  /** Reactive translation, read in the injection context. */
  protected readonly i18n = useTranslation()

  /** The translation function for the template. */
  protected t = this.i18n.t

  /** The bonded ClassMap (styling tokens resolve at render time). */
  protected readonly cm: UIClassMap = getClassMap()

  /** The OS name, or the localized Unknown fallback. */
  protected readonly platformLabel = computed(() => {
    return (
      this.device.deviceInfo.os.name ||
      this.t('settings.unknown', undefined, { defaultValue: 'Unknown' })
    )
  })

  /** The browser name, or the localized Unknown fallback. */
  protected readonly browserLabel = computed(() => {
    return (
      this.device.deviceInfo.browser.name ||
      this.t('settings.unknown', undefined, { defaultValue: 'Unknown' })
    )
  })

  /**
   * The network line: `isOnline()` runs when this computed first renders and
   * again whenever the locale changes (the t() calls track the i18n

  protected readonly networkLabel = computed(() => {

      : this.t('settings.offline', undefined, { defaultValue: 'Offline' })
  })
}
```

#### `TiersUpgradeSection`

TiersUpgradeSection component.

Billing section with full multi-tier upgrade flow. React's root is a
fragment (the `<section>` plus the upgrade modal), so those nodes render in
the host's place and the host itself never appears in the page.

Replaces the simpler `BillingSection` for apps backed by
`@molecule/api-payments-stripe` + `@molecule/api-resource-payment` — loads
the user's current plan from `/api/billing/status`, loads available tiers
from `/api/billing/tiers`, and renders an Upgrade modal with a Subscribe
button per tier price. Subscribe POSTs to `/api/billing/checkout` and
redirects to the Stripe checkout URL; paid users see a Cancel button that
POSTs to `/api/billing/cancel`. A refused request shows the server's
message.

```typescript
@Component({
  selector: 'mol-tiers-upgrade-section',
  standalone: true,
  hostDirectives: [MolPlacement],
  imports: [Alert, Button, ConfirmButton, Flex, Modal],
  inputs: ['redirectToCheckout'],
  template: `<section>
      <h3 [class]="cm.cn(cm.sectionHeading, cm.sp('mb', 3))">
        {{ t('settings.billing', undefined, { defaultValue: 'Billing' }) }}
      </h3>
      <div mol-flex [align]="'center'" [justify]="'between'">
        <span [class]="cm.textSize('sm')"
          >{{ t('settings.plan', undefined, { defaultValue: 'Plan: ' })
          }}<strong>{{ plan() }}</strong></span
        >
        @if (planKey() === 'free') {
          <button mol-button [variant]="'outline'" [size]="'sm'" (click)="showUpgrade.set(true)">
            {{ t('settings.upgrade', undefined, { defaultValue: 'Upgrade' }) }}
          </button>
        } @else {
          <button
            mol-confirm-button
            [variant]="'outline'"
            [size]="'sm'"
            [onConfirm]="cancelSubscription"
            data-mol-id="billing-cancel-subscription"
          >
            <ng-container ngProjectAs="[slot=label]">{{
              t('settings.billing.cancel', undefined, { defaultValue: 'Cancel' })
            }}</ng-container
            ><ng-container ngProjectAs="[slot=confirmLabel]">{{
              t('settings.billing.cancelConfirm', undefined, {
                defaultValue: 'Cancel your subscription?',
              })
            }}</ng-container>
          </button>
        }
      </div>
    </section>
    <mol-modal
      [open]="showUpgrade()"
      (close)="showUpgrade.set(false)"
      [title]="t('settings.billing.upgradeTitle', undefined, { defaultValue: 'Upgrade your plan' })"
    >
      @if (upgradeError(); as checkoutError) {
        <div mol-alert [status]="'error'" [className]="cm.sp('mb', 4)">{{ checkoutError }}</div>
      }
      @if (tiers().length === 0) {
        <p [class]="cm.cn(cm.textSize('sm'), cm.textMuted)">
          {{
            t('settings.billing.noTiers', undefined, { defaultValue: 'No paid plans configured.' })
          }}
        </p>
      } @else {
        <ul [class]="cm.stack(3)">
          @for (entry of subscribeEntries(); track entry.key) {
            <li [class]="cm.sp('p', 4)">
              <div mol-flex [align]="'center'" [justify]="'between'">
                <div>
                  <p [class]="cm.fontWeight('semibold')">
                    {{ entry.tier.name }} ({{ entry.price.interval }})
                  </p>
                  <p [class]="cm.cn(cm.textSize('xs'), cm.textMuted)">
                    {{ entry.price.priceLabel }}
                  </p>
                </div>
                <button
                  mol-button
                  [size]="'sm'"
                  [loading]="upgradeLoading() === entry.price.stripePriceId"
                  (click)="startCheckout(entry.price.stripePriceId)"
                >
                  {{ t('settings.billing.subscribe', undefined, { defaultValue: 'Subscribe' }) }}
                </button>
              </div>
            </li>
          }
        </ul>
      }
    </mol-modal>`,
})
export class TiersUpgradeSection {
  /** How the page leaves for the checkout URL the server returns. */
  redirectToCheckout: (checkoutUrl: string) => void = openUrl

  /** Reactive translation, read in the injection context. */
  protected readonly i18n = useTranslation()

  /** The translation function for the template. */
  protected t = this.i18n.t

  private readonly http = useHttpClient()

  /** The user's current plan name. */
  protected readonly plan = signal('Free')
  /** The user's current plan key. */
  protected readonly planKey = signal('free')
  /** The tiers loaded from `/api/billing/tiers`. */
  protected readonly tiers = signal<Tier[]>([])
  /** Whether the upgrade modal is open. */
  protected readonly showUpgrade = signal(false)
  /** The price id whose checkout request is running, or null. */
  protected readonly upgradeLoading = signal<string | null>(null)
  /** The upgrade modal's error message. */
  protected readonly upgradeError = signal('')

  /** The bonded ClassMap (styling tokens resolve at render time). */
  protected readonly cm: UIClassMap = getClassMap()

  private readonly host: ElementRef<HTMLElement> = inject(ElementRef)

  protected subscribeEntries(): { key: string; tier: Tier; price: TierPrice }[] {
    const entries: { key: string; tier: Tier; price: TierPrice }[] = []
    for (const tier of this.tiers()) {
      if (tier.planKey === 'free') continue
      for (const price of tier.prices) {
        if (!price.stripePriceId) continue
        entries.push({ key: `${tier.planKey}-${price.stripePriceId}`, tier, price })
      }
    }
    return entries
  }

  constructor() {
    usePlacement(() => {
      // host's place; the host itself leaves the page.
      placeContentBefore(this.host.nativeElement, this.host.nativeElement)
      setElementPresent(this.host.nativeElement, false)
    })
    let cancelled = false
    inject(DestroyRef).onDestroy(() => {
      cancelled = true
    })
    void Promise.all([
      // defaults ('Free', empty tier list) instead of throwing.
      this.http
        .get<{ planKey?: string; name?: string }>('/api/billing/status')
        .catch((_error) => null),
      this.http
        .get<{
          data?: Array<{
            key: string
            name: string
            prices: Array<{ stripePriceId: string | null; period: string; price: string }>
          }>
        }>('/api/billing/tiers')
        .catch((_error) => null),
    ])
      .then(([statusRes, tiersRes]) => {
        if (cancelled) return
        const status = statusRes?.data ?? null
        if (status?.name) this.plan.set(status.name)
        if (status?.planKey) this.planKey.set(status.planKey)
        const list = tiersRes?.data?.data ?? []
        if (Array.isArray(list)) {
          this.tiers.set(
            list.map((tier) => ({
              planKey: tier.key,
              name: tier.name,
              prices: (tier.prices || []).map((p) => ({
                stripePriceId: p.stripePriceId ?? undefined,
                interval: p.period,
                priceLabel: p.price,
              })),
            })),
          )
        }
      })
      .catch((_error) => {
        // Fetch failures already resolve to null above; this only guards the
        // mapping, keeping the section on its defaults rather than throwing.
      })
  }

  protected async startCheckout(stripePriceId: string | undefined): Promise<void> {
    if (!stripePriceId) return
    this.upgradeError.set('')
    this.upgradeLoading.set(stripePriceId)
    try {
      const res = await this.http.post<{ checkoutUrl?: string; updated?: boolean }>(
        '/api/billing/checkout',
        { priceId: stripePriceId },
      )
      const data = res.data
      if (data?.checkoutUrl) {
        this.redirectToCheckout(data.checkoutUrl)
        return
      }
      if (data?.updated) {
        this.showUpgrade.set(false)
        return
      }
      this.upgradeError.set(
        this.t('settings.billing.checkoutFailed', undefined, {
          defaultValue: 'Could not start checkout.',
        }),
      )
    } catch (err) {
      this.upgradeError.set(
        serverErrorMessage(err) ??
          this.t('settings.billing.checkoutFailed', undefined, {
            defaultValue: 'Could not start checkout.',
          }),
      )
    } finally {
      this.upgradeLoading.set(null)
    }
  }

  protected cancelSubscription = async (): Promise<void> => {
    this.upgradeError.set('')
    try {
      await this.http.post('/api/billing/cancel', {})
      this.plan.set('Free')
      this.planKey.set('free')
    } catch (err) {
      this.upgradeError.set(
        serverErrorMessage(err) ??
          this.t('settings.billing.cancelFailed', undefined, {
            defaultValue: 'Could not cancel.',
          }),
      )
    }
  }
}
```

### Functions

#### `useSettingsPanelContext()`

Reads the `onClose` handler exposed by the parent `<SettingsContainer>`.
Throws if used outside the container so component misuse is loud.

The lookup is deferred to the first property read (an event handler, long
after Angular has created and attached every element), so a section nested
in projected content resolves the container reliably.

```typescript
function useSettingsPanelContext(): SettingsPanelContextValue
```

**Returns:** The container context.

#### `findCurrentDevice(devices)`

Picks the caller's own device row: the api flags the session device
`isCurrent`; fall back to the first row for sessions predating the flag.

```typescript
function findCurrentDevice(devices: PushToggleDevice[] | undefined): PushToggleDevice | undefined
```

- `devices` — Rows from `GET /api/devices`.

**Returns:** The current device row, or `undefined` when the user has none.

#### `subscriptionFromToken(token)`

Converts an `@molecule/app-push` token into the device resource's
`pushSubscription` shape (web PushSubscription JSON, FCM registration for
Android, APNs registration for iOS).

```typescript
function subscriptionFromToken(token: PushToggleToken): unknown
```

- `token` — The push token returned by `register()`.

**Returns:** The `pushSubscription` value to PATCH onto the device row.

#### `enablePushOnCurrentDevice(deps)`

Runs the full enable chain: browser permission → runtime VAPID public key
(`GET /api/devices/push/public-key`) → `register({ vapidPublicKey })` →
persist the subscription on the current device row.

Every failure is returned as a typed reason (never thrown) so the UI can
show an honest, specific message instead of hanging or silently reverting.

```typescript
function enablePushOnCurrentDevice(deps: {
  http: PushToggleHttp
  requestPermission: () => Promise<string>
  register: (options?: { vapidPublicKey?: string }) => Promise<PushToggleToken>
}): Promise<PushToggleResult>
```

- `deps` — The http client + push actions from `usePush()`.
- `deps.http` — Authenticated http client (`useHttpClient()`).
- `deps.requestPermission` — `usePush().requestPermission`.
- `deps.register` — `usePush().register`.

**Returns:** `{ ok: true }` or a typed failure.

#### `disablePushOnCurrentDevice(deps)`

Disables push: unsubscribes the browser (best-effort — a dev build without
a service worker has nothing to unsubscribe) and ALWAYS clears the server
state so no further pushes target this device.

```typescript
function disablePushOnCurrentDevice(deps: {
  http: PushToggleHttp
  unregister: () => Promise<void>
}): Promise<PushToggleResult>
```

- `deps` — The http client + push action from `usePush()`.
- `deps.http` — Authenticated http client (`useHttpClient()`).
- `deps.unregister` — `usePush().unregister`.

**Returns:** `{ ok: true }` or a typed failure (server state not cleared).

#### `readCurrentDevicePushEnabled(http)`

Reads whether push is currently enabled for THIS device (server truth:
the current device row's `hasPushSubscription`).

```typescript
function readCurrentDevicePushEnabled(http: PushToggleHttp): Promise<boolean>
```

- `http` — Authenticated http client (`useHttpClient()`).

**Returns:** `true` when the current device has a stored subscription.
