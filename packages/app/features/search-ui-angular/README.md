# @molecule/app-search-ui-angular

Angular search UI for `@molecule/app-client-search`.

The Angular counterpart of `@molecule/app-search-ui-react` — the same props
(React names) and the same DOM for the same input. Three pieces that fit a
`useSearchSession` from `@molecule/app-client-search-angular`:
{@link SearchBox} (the field, its clear button and shortcut cap, a help icon
whose tooltip shows the search syntax, an `afterField` projection for the
consumer's own tabs, the active filter chips and the hit count),
{@link SearchResults} (ranked rows with the matched terms marked, hover
prefetch, an optional action per row; the keyboard-active row is marked with
`aria-current` and announced through a polite status region), and
{@link QuickSearchDialog} (both in a `mod+k` dialog named for screen readers
by its `label`, "Search" by default). Every class comes from
the ClassMap's search tokens (`searchField`, `resultList`, …), so a UI bond
restyles all of it at once.

#### `Highlight`

Highlight component.

Text with the matched terms marked: each term is marked where it starts a
word, case-insensitively, through the ClassMap's `resultMark`. React's root
is a FRAGMENT (the segments, plain text and `<mark>` side by side), so those
nodes render in the host's place and the host itself never appears in the
page. The text is an attribute of the element — pass `text` and `terms` as
inputs, not as content.

```typescript

  selector: 'mol-highlight',
  standalone: true,
  hostDirectives: [MolPlacement],
  inputs: ['text', 'terms'],
  // prettier-ignore
  template: `@for (seg of segments(); track $index) {@if (seg.hit) {<mark [class]="cm().cn(cm().resultMark)">{{ seg.text }}</mark>} @else {{{ seg.text }}}}`,
})
export class Highlight implements HighlightProps {
  /** The text to show. */
  text = ''
  /** The matched terms to mark (a hit's `terms`). */
  terms: string[] = []

  private readonly host: ElementRef<HTMLElement> = inject(ElementRef)

  constructor() {
    usePlacement(() => {
      // React's root is the fragment of segments; it renders in the host's place.
      placeContentBefore(this.host.nativeElement, this.host.nativeElement)
      setElementPresent(this.host.nativeElement, false)
    })
  }

  /**
   * The current class map.
   * @returns The UIClassMap.
   */
  cm(): UIClassMap {
    return getClassMap()
  }

  /**
   * The plain and matched segments, as React derives them per render.
   * @returns The segments, in order.
   */
  segments(): ReturnType<typeof highlightMatches> {
    return highlightMatches(this.text, this.terms)
  }
```

#### `QuickSearchDialog`

QuickSearchDialog component.

A search dialog for `mod+k`: the box on top with focus, the hits below in
a scrolling pane, and the key hints in the footer. Before anything is
typed the pane shows `idleText` rather than a browse list. Enter opens the active
hit through the session (which closes the dialog by the caller's `onOpen`).
The dialog is named for screen readers through `label` (or the translated
"Search" default). React renders `null` while closed, so the host itself
never appears in the page: while open the modal renders in the host's place
and while closed nothing does.

#### `SearchBox`

SearchBox component.

A search field: a leading icon, the input, a help icon that shows the
syntax on hover, an × to clear, and the shortcut cap; under it, whatever
`afterField` holds (projected as `[slot=afterField]`), then the active
filters as removable chips and the hit count. The field stays mounted, and
its text with it, across searches. The host IS the outer `<div>` React
renders (`div[mol-search-box]`).

#### `SearchResults`

The default row link is a plain anchor; the row body renders through the
`rowBody` template. React's root is a FRAGMENT of two nodes (the `<ul>` and
a visually hidden status `<p>`, or the empty text `<p>` and the status `<p>`),
so those nodes render in the host's place and the host itself never appears
in the page.

The ranked hits: title and description with the matched terms marked, the
meta line, hover making a row active and warming its page. The whole row is
the link, so the list is a plain list of links (no listbox roles: an option's
children are presentational and would hide the row's link and action); the
active row is marked with `aria-current` on its `<li>` and announced through
a polite, visually hidden status region after the list.

```typescript
  implements SearchResultsProps<T>, AfterViewChecked
{

  hits: SearchResultHit<T>[] = []
  /** How a hit renders. */
  view!: (doc: T) => SearchResultView
  /** The keyboard- or pointer-active row, or `-1`. */
  activeIndex = -1
  /** The pointer moved onto a row. */
  onActivate?: (index: number) => void
  onOpen!: (doc: T) => void
  onPrefetch?: (doc: T) => void

  renderLink?: TemplateRef<{ $implicit: SearchResultLinkProps }>
  action?: TemplateRef<{ $implicit: T }>
  /** Shown when there are no hits. */
  emptyText = ''
  molId?: string
  /** Extra classes composed onto the list. */
  className?: string

  @ViewChild('rowBody', { static: true }) rowBodyTpl?: TemplateRef<{
    $implicit: SearchResultHit<T>
  }>

  /** i18n handle, read in an injection context. */
  readonly t = useTranslation().t

  /** The current class map. */
  cm(): UIClassMap {
    return getClassMap()
  }

  id(): string {
    return this.molId ?? 'search'
  }

  viewOf(hit: SearchResultHit<T>): SearchResultView {
    return this.view(hit.doc)
  }

  /** A hit's meta facts (a copy, as React makes). */
  metaOf(hit: SearchResultHit<T>): string[] {
    return [...(this.viewOf(hit).meta ?? [])]
  }

  renderContext(arg: unknown): Record<string, unknown> {
    return { $implicit: arg, a0: arg, a1: undefined, a2: undefined }
  }

  listClasses(): string {
    return this.cm().cn(this.cm().resultList, this.className)
  }

  itemClasses(index: number): string {
    return this.cm().cn(
      this.cm().resultItem,
      index === this.activeIndex && this.cm().resultItemActive,
    )
  }

  relatedText(): string {
    return this.t('searchUi.related', undefined, { defaultValue: 'related' })
  }

  relatedTitle(): string {
    return this.t('searchUi.relatedTitle', undefined, {
      defaultValue: 'Matches the meaning of your search, not its words',
    })
  }

  activeText(): string {
    const hit = this.activeIndex >= 0 ? this.hits[this.activeIndex] : undefined
    if (!hit) return ''
    return this.t(
      'searchUi.activeResult',
      {
        title: this.viewOf(hit).title,
        position: this.activeIndex + 1,
        count: this.hits.length,
      },
      { defaultValue: '{{title}}, {{position}} of {{count}}' },
    )
  }

  titleClasses(hit: SearchResultHit<T>): string {
    const v = this.viewOf(hit)
    return this.cm().cn(this.cm().resultTitle, v.mono && this.cm().resultTitleMono)
  }

  /** The link props one row's link gets. */
  linkProps(hit: SearchResultHit<T>): SearchResultLinkProps {
    const v = this.viewOf(hit)
    return {
      href: v.href,
      state: v.state,
      className: this.cm().resultBody,
      'data-mol-id': `${this.id()}-link`,
      children: this.rowBodyTpl,
      childrenContext: { $implicit: hit },
      onClick: (event: MouseEvent) => {
        if (event.metaKey || event.ctrlKey || event.shiftKey || event.altKey || event.button !== 0)
          return
        event.preventDefault()
        this.onOpen(hit.doc)
      },
    }
  }

  openFromLink(event: MouseEvent, hit: SearchResultHit<T>): void {
    if (event.metaKey || event.ctrlKey || event.shiftKey || event.altKey || event.button !== 0)
      return
    event.preventDefault()
    this.onOpen(hit.doc)
  }

  activateRow(index: number, hit: SearchResultHit<T>): void {
    this.onActivate?.(index)
    this.onPrefetch?.(hit.doc)
  }

  private readonly rows = new Map<string, HTMLElement>()

  private revealedFor: { index: number; id: string | undefined } | null = null

  registerRow(id: string, el: HTMLElement): void {
    this.rows.set(id, el)
  }

  /** Forgets a row as it leaves the list. */
  unregisterRow(id: string, el: HTMLElement): void {
    if (this.rows.get(id) === el) this.rows.delete(id)
  }

  ngAfterViewChecked(): void {
    const index = this.activeIndex
    const id = index >= 0 ? this.hits[index]?.id : undefined
    const last = this.revealedFor
    if (last && last.index === index && last.id === id) return
    this.revealedFor = { index, id }
    if (id === undefined) return
    this.rows.get(id)?.scrollIntoView?.({ block: 'nearest' })
  }

  private readonly hostEl: HTMLElement = inject(ElementRef<HTMLElement>).nativeElement

  constructor() {
    usePlacement(() => this.adopt())
  }

  private adopt(): void {
    placeContentBefore(this.hostEl, this.hostEl)
    setElementPresent(this.hostEl, false)
  }
}
```

- **Pass a router link through `renderLink`**, or every row is a full page
  load: the list renders a plain `<a>` by default because it does not know
  your router. A plain click calls `onOpen` (which the session turns into
  navigation); a modified click is left to the browser so "open in new tab" works.
- The box does not own the text: bind `value`/`onChange` to a session (or
  any state) and it stays mounted, with its text, across searches. Do not
  remount it per search.
- `placeholder`, `emptyText` and the like are already-translated strings
  from the app; the package translates only its own chrome ("Clear
  search", "{{count}} results", "Search tips") through `@molecule/app-locales-search-ui`.
- The quick dialog needs a session created with `syncUrl: false` and
  `onEscape: onClose`; the page's own session keeps the URL.
- Node-valued React props are projected content: `afterField` is selected
  by `[slot=afterField]`, and a render function (`renderLink`, `action`) is
  a `TemplateRef` whose context carries its argument as `$implicit`.
