# @molecule/app-markdown

Markdown rendering core interface for molecule.dev.

Provides a standardized API for rendering markdown content into HTML,
with support for GFM and table of contents extraction.
Bond a provider (e.g. `@molecule/app-markdown-react-markdown`) to supply
the concrete implementation.

#### `MarkdownOptions`

Options for markdown rendering.

```typescript
interface MarkdownOptions {
  /**
   * Whether to sanitize the rendered HTML. Defaults to `true`.
   *
   * It controls two things: raw HTML in the markdown source is escaped to
   * inert text, and a link or image whose URL {@link isSafeMarkdownUrl}
   * refuses renders as its link text or alt text instead of an element.
   * A markdown link, autolink or image with a `javascript:` or `vbscript:`
   * URL is never emitted, even with `sanitize: false`; raw HTML that
   * `sanitize: false` passes through is the app's own trusted markup.
   */
  sanitize?: boolean

  /** Whether to enable GitHub Flavored Markdown extensions. Defaults to `true`. */
  gfm?: boolean

  /** Whether to convert line breaks to `<br>` elements. Defaults to `false`. */
  breaks?: boolean

  /**
   * Custom component overrides keyed by HTML element name.
   *
   * @deprecated The renderer returns an HTML string, so an override keeps only
   * its static markup — no click handler, state, or context. Use
   * {@link MarkdownOptions.elementAttributes} to add attributes instead. This
   * option is removed at the next major.
   */
  components?: Record<string, unknown>

  /**
   * Extra attributes for rendered elements, e.g. `{ a: { class: cm.link() } }`.
   *
   * Values are escaped. An attribute that is `href`, `src`, `id` or starts with
   * `on` is refused with an error, as is a name that is not a valid attribute
   * name; see `checkElementAttributes` in `./attributes.js`.
   */
  elementAttributes?: Partial<Record<MarkdownElement, Record<string, string>>>

  /** Target attribute for rendered links. */
  linkTarget?: '_blank' | '_self'
}
```

#### `createHeadingSlugger(slugBase)`

Creates a heading slugger for one rendered document.

Call the returned function once per heading, in document order. It applies
marked's rule (lowercase, hyphenated, Unicode letters and digits kept),
returns `section` for a heading with no letters or digits, and makes ids
unique: a repeat of `a` becomes `a-2`, then `a-3`, and a suffixed slug never
collides with a later heading whose own text slugs to it (`a`, `a`, `a-2`
gives `a`, `a-2`, `a-2-2`). Start a new slugger for each rendered document so
a new document begins again at no suffix.

```typescript
function createHeadingSlugger(slugBase?: (text: string) => string): (text: string) => string
```

- `slugBase` — Turns heading text into the base slug instead of the rule above (a provider's own `slugify` option). The ids it returns get the same `-2`, `-3` suffixes, and an empty one becomes `section`.

**Returns:** A function that slugs one heading's text into a unique id.

#### `isSafeMarkdownUrl(url)`

Decides whether a markdown link or image URL is safe to emit.

Accepts `http:`, `https:`, `mailto:`, `tel:`, `irc:`, `ircs:` and `xmpp:`
URLs (scheme case-insensitive), relative URLs (`a/b`, `../a`, `?q=1`) and
fragments (`#x`). Every other scheme — `javascript:`, `vbscript:`, `data:`,
`file:` and unknown ones — is refused, including obfuscated forms a browser
still runs: whitespace and control characters inside the scheme, and mixed
case. Percent-encoded or entity-encoded text is not decoded, so `%6Aavascript:`
stays a relative path.

```typescript
function isSafeMarkdownUrl(url: string): boolean
```

- `url` — The URL exactly as it appears in the markdown link or image.

**Returns:** `true` when the URL may be emitted as-is, `false` when it must not.

#### `isRefusedMarkdownUrl(url, sanitize)`

Decides whether a markdown link or image renders as its text (or alt text)
instead of an element: what every provider asks of each `href` and `src`.

With `sanitize` on (the default) that is every URL {@link isSafeMarkdownUrl}
refuses. With `sanitize` off every URL is kept except a `javascript:` or
`vbscript:` one, matched the same way (whitespace and control characters
stripped, case-insensitive), which no provider emits for any option.

```typescript
function isRefusedMarkdownUrl(url: string, sanitize?: boolean): boolean
```

- `url` — The URL exactly as it appears in the markdown link or image.
- `sanitize` — The render's `sanitize` option; `true` when unset.

**Returns:** `true` when the URL must not be emitted.

## Injection Notes

### Requirements

Peer dependencies:

- `@molecule/app-bond` ^1.0.1
- `@molecule/app-i18n` ^1.2.2

### Runtime Dependencies

- `@molecule/app-bond`
- `@molecule/app-i18n`

- **Wire a bond at startup** — {@link requireProvider} throws until
  `setProvider(provider)` has been called.
- **`sanitize` defaults to `true` and is the XSS gate.** `render()` returns
  `{ html, toc }`; inject only its `html` string via your framework's raw-HTML mechanism — that is
  only safe because it was sanitized. NEVER pass `sanitize: false` for
  user-supplied or model-generated markdown (chat replies, comments, notes);
  reserve it for fully trusted, app-authored content.
- Options are per-call (`gfm`, `breaks`, `linkTarget`); `result.toc` carries
  the document's headings in order (`[]` when there are none). Syntax
  highlighting is a provider concern — e.g. the react-markdown bond wires a
  rehype highlighter via its `rehypePlugins` config rather than a generic option.
- **Shared rules for providers.** `isSafeMarkdownUrl(url)` is the one URL
  allow-list (http/https/mailto/tel/irc/ircs/xmpp, relative URLs and
  fragments). `createHeadingSlugger()` is the one heading-id rule (Unicode
  letters and digits kept, `section` fallback, `-2`/`-3` suffixes).
  `MARKDOWN_ELEMENTS`, `checkElementAttributes()` and `escapeAttributeValue()`
  back the `elementAttributes` option.

## E2E Tests

Integration checklist — drive the real UI (live preview, no mocks), adapt
each item to this app's actual screens/flows, and check every box off one
by one. A box you can't check is an integration bug to fix — not a skip:

- [ ] Common markdown renders as real HTML wherever the app shows it (chat
      reply, comment, note, README preview): `#`..`######` become `<h1>`..`<h6>`,
      `**bold**` a `<strong>`, `*italic*` an `<em>`, `-`/`1.` lists become
      `<ul>`/`<ol>` of `<li>`, `[text](url)` an `<a>` anchor, and a fenced code
      block a `<pre><code>` — not the raw `*`/backticks shown as literal text.
- [ ] GFM extras render when enabled (`gfm`, default on): a pipe table
      `| a | b |` becomes a real `<table>` with header + rows, and `![alt](src)`
      an `<img>`.
- [ ] The output tracks the source: editing the markdown updates the preview
      live — change a heading's text and its `<h#>` updates; add a list item and
      a new `<li>` appears. No stale or one-shot render.
- [ ] SECURITY (XSS) — user- or model-supplied markdown is sanitized
      (`sanitize`, default on, the XSS gate): markdown containing a raw
      `<script>alert(1)</script>`, an `<img src=x onerror=alert(1)>`, or a
      `[click](javascript:alert(1))` link must NOT execute and must NOT produce
      active markup — the script is stripped, the `onerror` is gone, and the
      link's `href` is neutralized. Verify in the browser: no alert fires, and
      DevTools shows no `<script>`, `onerror`, or `javascript:` in the rendered
      DOM. Never render untrusted content with `sanitize: false`.
- [ ] Malformed markdown degrades gracefully — an unclosed `**`, a broken
      `[link](`, or a half-open code fence renders as readable text and never
      throws, blanks the view, or breaks the surrounding page.
