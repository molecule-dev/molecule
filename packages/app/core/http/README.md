# @molecule/app-http

Client HTTP interface for molecule.dev.

Provides a unified HTTP client API that works across different
HTTP libraries (fetch, axios, ky, etc.).

**The body is the SECOND argument: `post(url, data, config?)` — likewise `put` and `patch`,
and the response is `HttpResponse<T>` (read `.data` for the body).** `data` IS the request
body; a plain object is serialized as the JSON body. Passing `{ data: body }` there is NOT a
config object — it makes the wire body `{"data":{…}}`, so the API sees an object whose only
key is `data`, finds none of the fields it validates, and answers
`422 {"errors":{"username":["can't be blank"],…}}`. Write `post('/users', { user })`, never
`post('/users', { data: { user } })`. The config object (headers, params, timeout,
`skipAuthGate`) is the THIRD argument. Only `request({ method, url, data, … })` takes `data`
inside an options object, because there that object IS the config.

## Quick Start

```tsx
// In a React component, get the configured client from context and call it.
// The hook is exported by the framework binding (@molecule/app-react), not
// this core package — never construct your own fetch/axios client.
import { useHttpClient } from '@molecule/app-react'

function Plants() {
  const http = useHttpClient()
  const load = async () => {
    const res = await http.get<Plant[]>('/plants') // the bonded client's baseURL ('/api') is prepended
    setPlants(res.data)
  }
  // Body-carrying verbs take the body as the SECOND argument:
  //   http.post('/plants', plant)      — wire body is `plant`
  //   http.post('/plants', { data: plant })  — WRONG: wire body is `{"data": plant}`
  // http.put(url, body), http.patch(url, body) and http.delete(url) are also available.
}
```

#### `RequestConfig`

HTTP request options (headers, query params, timeout, credentials, response type, abort signal).

````typescript
interface RequestConfig {
  /**
   * Request headers.
   */
  headers?: Record<string, string>

  /**
   * Query parameters.
   */
  params?: Record<string, string | number | boolean | undefined>

  /**
   * Request timeout in milliseconds.

   * promise never settles, and every request on the page stalls until the gate times out —
   * so pass `skipAuthGate: true` on the restore's own request:
   *

   * // the request the gate's restore makes, through the same client the gate holds back

   * gate with `setAuthGate` does.

  skipAuthGate?: boolean

  /**
   * Response type.
   */
  responseType?: 'json' | 'text' | 'blob' | 'arraybuffer'

  /**
   * Abort signal for cancellation.
   */
  signal?: AbortSignal

  /**
   * Request body data, as a field of THIS config object — the `request({ method, url, data })`

   */
  options?: Record<string, unknown>

### Functions

#### `setAuthGate(next)`

Registers the gate every HTTP request awaits before it is sent, or clears it
with `null`.

Pass a function that resolves once the session restore has settled — with the
template auth that is `() => authClient.whenRestored()`, which resolves
immediately when no restore is in flight, so registering it never makes a
request wait longer than the restore it was about to race anyway.

A gate whose restore sends its OWN request through the gated client deadlocks — the
gate holds the request it is waiting for. That request must pass `skipAuthGate: true`
(see `RequestConfig.skipAuthGate`); `@molecule/app-auth`'s own restore does not
need it because it uses `fetch` rather than the bonded client.

```typescript
function setAuthGate(next: (() => Promise<void>) | null): void
```

- `next` — The gate, or `null` to clear a previously registered one.

#### `awaitAuthGate(request)`

Awaits the registered gate, if any. Every HTTP provider calls this before it
sends a request; callers never need to.

A gate that rejects (a restore that failed) is logged and cleared of consequence: the request
is sent rather than held forever, because a dead restore must not block every request for the
life of the page. The same holds for a gate that never settles — the wait is bounded by
`GATE_TIMEOUT_MS`, and a timeout with requests held is reported at error level naming the fix
(`skipAuthGate`).

```typescript
function awaitAuthGate(request?: AuthGateRequest): Promise<void>
```

- `request` — The request being gated, so a request the gate itself depends on can opt out (`skipAuthGate`) and a stalled gate can name what it held. A provider passes its own request config; a caller passing nothing gets the plain wait.

**Returns:** A promise that settles when the gate has released the request.

#### `unwrapList(res)`

Normalize an unknown response body into a typed array.

Accepts:

- a bare array → returned as-is (cast)
- `{ data: T[] }` envelope → the inner array
- `HttpResponse<T[]>` (i.e. `{ data: T[], status, ... }`) → the inner array
- `HttpResponse<{ data: T[] }>` (the response of an envelope-returning
  endpoint as it arrives from `@molecule/app-http`'s `HttpClient`) → the
  doubly-nested inner array
- `HttpResponse<{ data: T[], total, limit, offset }>` (a RICH pagination
  envelope from a pre-built `@molecule/api-resource-*` list endpoint) → the
  inner `data` array (the numeric `total`/`limit`/`offset` make the shape
  unambiguous, so callers can pass the whole HttpResponse and still get the rows)
- anything else → `[]`

Callers commonly pass either the raw JSON body (e.g. from `fetch().then(r =>
r.json())`) or the `HttpResponse` returned by `useHttpClient().get(...)`.
Both shapes are handled here so pages don't have to remember to call
`unwrapList(res.data)` vs `unwrapList(res)`.

```typescript
function unwrapList(res: unknown): T[]
```

- `res` — Raw response body OR an `HttpResponse` envelope from `@molecule/app-http`.

**Returns:** A typed array `T[]`; never `null`/`undefined`.

#### `unwrapSingle(res)`

Normalize an unknown response body into a single typed resource.

Accepts:

- a non-empty plain object → returned as-is (cast)
- `{ data: T }` envelope → the inner value
- `{ data: null }`, `{ data: undefined }`, `{ data: [] }`, or
  `{ data: {} }` (mock-server's no-match shape) → `null`
- an empty object `{}` → `null`
- arrays, primitives, `null`, `undefined` → `null`

The "envelope contains an array → null" branch handles the case
where the mock server returns `[]` for unmatched endpoints but the
caller expects a single resource.

```typescript
function unwrapSingle(res: unknown): T | null
```

- `res` — Raw response body (e.g. `HttpResponse.data` from `@molecule/app-http`).

**Returns:** The typed resource `T`, or `null` when the response shape indicates "no resource" (including the various empty envelopes above).

```typescript

- `source` — Returns the current access token (null when signed out), or `null` to clear.

#### `setClient(client)`

A registered `setAuthTokenSource` token source is applied to the client

```typescript

```

- `client` — The HTTP client implementation to bond.

#### `getClient()`

Retrieves the bonded HTTP client. If none is bonded, returns a module-level
fetch-based fallback — it is NOT bonded.

The fallback has NO `baseURL` — a core cannot know an app's API prefix. A relative
call then resolves against the page origin, where a dev server answers its own HTML
shell with a 200. It warns once so the misconfiguration is named instead of showing up
as a crash three components later; a scaffold bonds the shared client with its API
prefix, so the fallback only runs in an app that never bonded one.

Returning it WITHOUT bonding is what keeps a later `setClient()` authoritative: a
caller that captured this fallback early does not make it the app's client, so the
scaffold's client (and its token source) still takes effect for every later call.

```typescript
function getClient(): HttpClient
```

**Returns:** The active HTTP client, or the unbonded fallback when none is bonded.

## Injection Notes

### Requirements

Peer dependencies:

- `@molecule/app-i18n` ^1.0.1
- `@molecule/app-logger` ^1.0.1

### Runtime Dependencies

- `@molecule/app-bond`
- `@molecule/app-i18n`
- `@molecule/app-logger`

Make ALL API calls through this client (via the framework hook `useHttpClient()` in
React / the Vue composable) — it carries the configured `baseURL`, auth headers, and
interceptors. Do NOT call `fetch()` / `axios` directly in components — that bypasses auth

- base-URL config and breaks when the transport is swapped.

Two mistakes that break in preview/production (seen in real imported apps):

- **Pass RELATIVE paths; never a hardcoded host.** Use `'/plants'` (the BONDED client's
  `baseURL` — `'/api'` in a scaffold — is prepended), NOT `'/api/plants'`, and NEVER an
  absolute dev URL like `'http://localhost:4000/api/…'`. A hardcoded `localhost`/host works on
  the author's machine, then fails cross-origin (CORS) in the preview and points at the wrong
  server in production. The base URL is configured ONCE (via `setClient`), not per call.
- **`getClient()` itself knows no baseURL.** The fallback client it mints when nothing is
  bonded has `baseURL: ''`, so `getClient().get('/articles')` requests the PAGE origin — in
  dev the Vite server answers its own `index.html` with a 200, and the HTML arrives as
  `data` (xr-molecule-flash-m126 lost 6.5 minutes to that). A scaffold bonds
  `'/api'`; an app that builds its own client must pass `{ baseURL }`.
- **The client is PUBLIC — never put a secret in it.** Anything the browser sends (an API
  key, a service-role / `sk_…` key, a signing secret) is visible to every user. Secrets
  stay in YOUR API; the browser calls your API and the API uses the secret server-side.
  Only a publishable/public key may ever be client-side.

Auth (the bearer token / session cookie) is attached by the client's interceptors — do not
read a token from `localStorage` or hand-attach it (the token is memory-only; see the user
resource).
An API that wants another scheme than `Bearer` (`Authorization: Token <jwt>`) passes
`authScheme: 'Token'` to the client's CONSTRUCTOR — `setClient(createFetchClient({ baseURL,
authScheme: 'Token' }))`, or the bonded provider's constructor
(`createAxiosClient({ … })` from `@molecule/app-http-axios`). It is NOT a property of
`getClient()`'s result: that is a built client, and `client.authScheme = 'Token'` is a type
error (TS2339) that changes no header. Do not hand-write a fetch wrapper for the scheme either.

A request made while the session is still being restored WAITS for that restore, so a page
that fetches viewer-dependent data on mount (a profile's `following` flag, a feed, a
`favorited` state) cannot go out unauthenticated and answer for an anonymous viewer. The auth
bond registers that wait with `setAuthGate`; apps that bond auth through
`@molecule/app-bonds-default-react` get it without doing anything. An app with its own session
module registers its own: `setAuthGate(() => session.whenRestored())`.
Waiting for the restore does NOT attach the token: a client created beside the auth bond needs
`createDefaultHttpClientWithAuthBearer({ baseURL, getToken: () => authClient.getAccessToken(),
authScheme })` from `@molecule/app-bonds-default-react` (or an auth client built with
`createDefaultAuthClientWithHttpSync`, which mirrors the token into the bonded client), because
`setAuthGate` alone sends no `Authorization` header.

**A request the gate itself depends on must opt out of it: pass `skipAuthGate: true`.** A gate
that waits for a session restore whose own request goes through this client waits on itself —
that request is held by the gate waiting for it, so the restore never settles and every request
the gate holds stalls until it times out (3 s). The request that restores the session for a gate
you registered yourself is therefore written
`http.get(currentUserEndpoint, { skipAuthGate: true })`; `@molecule/app-auth`'s own restore does
not need it (it calls `fetch`, not this client).
