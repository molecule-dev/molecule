# @molecule/app-http

Client HTTP interface for molecule.dev.

Provides a unified HTTP client API that works across different
HTTP libraries (fetch, axios, ky, etc.).

**The body is the SECOND argument: `post(url, data, config?)` — likewise `put` and `patch`,
and the response is `HttpResponse<T>` (read `.data` for the body).** `data` IS the request
body; a plain object is serialized as the JSON body. Passing `{ data: body }` there is NOT a
config object — it makes the wire body `{"data":{…}}`, so the API sees an object whose only
key is `data`, finds none of the fields it validates, and answers
`422 {"errors":{"username":["can't be blank"],…}}`. Write `post('/users', { user })`, never
`post('/users', { data: { user } })`. The config object (headers, params, timeout,
`skipAuthGate`) is the THIRD argument. Only `request({ method, url, data, … })` takes `data`
inside an options object, because there that object IS the config.

## Quick Start

```tsx
// In a React component, get the configured client from context and call it.
// The hook is exported by the framework binding (@molecule/app-react), not
// this core package — never construct your own fetch/axios client.
import { useHttpClient } from '@molecule/app-react'

function Plants() {
  const http = useHttpClient()
  const load = async () => {
    const res = await http.get<Plant[]>('/plants') // the bonded client's baseURL ('/api') is prepended
    setPlants(res.data)
  }
  // Body-carrying verbs take the body as the SECOND argument:
  //   http.post('/plants', plant)      — wire body is `plant`
  //   http.post('/plants', { data: plant })  — WRONG: wire body is `{"data": plant}`
  // http.put(url, body), http.patch(url, body) and http.delete(url) are also available.
}
```

#### `HttpClient`

HTTP client interface.

All HTTP providers must implement this interface.

```typescript
interface HttpClient {
  /**
   * Base URL for all requests.
   */
  baseURL: string

  /**
   * Default headers for all requests.
   */
  defaultHeaders: Record<string, string>

  /**
   * Makes a generic HTTP request. `data` is a field of THIS config object — the same body
   * `post(url, data, config)` takes as its second argument.
   */
  request<T = unknown>(config: FullRequestConfig): Promise<HttpResponse<T>>

  /**
   * Makes a GET request.
   */
  get<T = unknown>(url: string, config?: RequestConfig): Promise<HttpResponse<T>>

  /**
   * Makes a POST request. `data` is the request BODY, not a config object: the wire body is
   * `data` itself, so `post(url, { data: body })` sends `{"data":body}` — pass `body` directly.
   * A config (headers, params) is the THIRD argument.
   */
  post<T = unknown>(url: string, data?: unknown, config?: RequestConfig): Promise<HttpResponse<T>>

  /**
   * Makes a PUT request. `data` is the request BODY (second argument) — never `{ data: body }`,
   * which sends `{"data":body}`; a config is the THIRD argument.
   */
  put<T = unknown>(url: string, data?: unknown, config?: RequestConfig): Promise<HttpResponse<T>>

  /**
   * Makes a PATCH request. `data` is the request BODY (second argument) — never `{ data: body }`,
   * which sends `{"data":body}`; a config is the THIRD argument.
   */
  patch<T = unknown>(url: string, data?: unknown, config?: RequestConfig): Promise<HttpResponse<T>>

  /**
   * Makes a DELETE request.
   */
  delete<T = unknown>(url: string, config?: RequestConfig): Promise<HttpResponse<T>>

  /**
   * Adds a request interceptor.
   * Returns a function to remove the interceptor.
   */
  addRequestInterceptor(interceptor: RequestInterceptor): () => void

  /**
   * Adds a response interceptor.
   * Returns a function to remove the interceptor.
   */
  addResponseInterceptor(interceptor: ResponseInterceptor): () => void

  /**
   * Adds an error interceptor.
   * Returns a function to remove the interceptor.
   */
  addErrorInterceptor(interceptor: ErrorInterceptor): () => void

  /**
   * Sets the authorization token.
   *
   * A static token: every request carries it until the next `setAuthToken` call. A client
   * that has a {@link HttpClient.setAuthTokenResolver | resolver} (registered through
   * `@molecule/app-http`'s `setAuthTokenSource`) ignores this value when it assembles a
   * request — the resolver IS the session, and reading it per request is what keeps a
   * session adopted without an auth event from sending the previous account's bearer. Once
   * the resolver is removed, the static token is sent again.
   */
  setAuthToken(token: string | null): void

  /**
   * Returns the token the client applies to its next request: the resolver's answer when one
   * is registered, else the static token from `setAuthToken`.
   */
  getAuthToken(): string | null

  /**
   * Registers the LIVE token resolver every request of this client reads, or clears it with
   * `null`.
   *
   * `@molecule/app-http`'s `setAuthTokenSource()` calls this on every client it bonds, and the
   * client MUST consult the resolver again each time it assembles a request (and report it from
   * `getAuthToken()`). A session can change with no auth event and no observable state change —
   * `authClient.setSession()` with the same profile data, or the OAuth callback's
   * `setAccessToken()` — so a token pushed only at bond time or on `login`/`logout` events
   * leaves every later request carrying the PREVIOUS session's bearer while the UI shows the
   * new one.
   *
   * The resolved token takes the static token's place, with the same precedence: an
   * `Authorization` header passed per request or in the client's default headers wins over it
   * exactly where it won over a static token in this transport.
   *
   * A resolver that returns `null` (or `undefined`) means "this session has no body token": the
   * request carries no `Authorization` header of the client's own. A cookie-session API issues
   * no bearer, and the server prefers the header over the fresh cookie, so a kept bearer
   * authenticates as the prior — possibly deleted — session.
   *
   * Optional, so an implementation written against the previous interface still conforms.
   * `setAuthTokenSource()` follows such a client through a request interceptor instead, pushing
   * the source with `setAuthToken` before each request: that request carries the change only
   * when the transport applies its token after running its interceptors, so a transport that
   * applies it earlier sends a session adopted mid-page from the following request on.
   *
   * @param resolver - Returns the current access token (or null/undefined), or `null` to clear.
   */
  setAuthTokenResolver?(resolver: AuthTokenResolver | null): void

  /**
   * Registers a handler for authentication errors (401).
   *
   * @returns An unsubscribe function.
   */
  onAuthError(handler: () => void): () => void
}
```

### Classes

#### `HttpError`

HTTP error with response details.

**`status` is an HTTP status when the server answered, and `0` when it did not.**
A `0` means NO response exists: the request was aborted (an `AbortController`, a
component's effect cleanup, a route change tearing the request down) or the
network failed before anything came back. It is not an HTTP status at all, so it
says nothing about the session — an app must never treat `status < 500` as
"signed out", because every aborted request on a route change would clear the
session. The correct check is {@link isAuthFailure} (`status === 401 || status === 403`);
`isNoResponse` (`status === 0`) identifies this case.

```typescript
class HttpError extends Error {
  /**
   * Builds a failed-request error.
   *
   * @param message - Human-readable message (already translated where a key exists).
   * @param status - HTTP status, or `0` when no response was received (aborted / network failure).
   * @param response - Parsed response when the server answered, otherwise undefined.
   * @param config - The request config that failed.
   * @param errorKey - Translation key for the failure (`http.error.aborted` for an
   *   aborted request, `http.error.networkError` for a real network failure).
   * @param aborted - Whether the request was aborted before a response: an
   *   `AbortController` signal (component cleanup, a cancelled request) or the
   *   browser tearing the fetch down during a navigation. Distinguishes an abort
   *   from a network outage on the same `status === 0`, without parsing the message.
   */
  constructor(
    message: string,
    public status: number,
    public response?: HttpResponse,
    public config?: FullRequestConfig,
    public errorKey?: string,
    public aborted = false,
  ) {
    super(message)
    this.name = 'HttpError'
  }
}
```

### Functions

#### `setAuthGate(next)`

Registers the gate every HTTP request awaits before it is sent, or clears it
with `null`.

Pass a function that resolves once the session restore has settled — with the
template auth that is `() => authClient.whenRestored()`, which resolves
immediately when no restore is in flight, so registering it never makes a
request wait longer than the restore it was about to race anyway.

Waiting for the restore does NOT attach its token: a separately created HTTP
client needs `createDefaultHttpClientWithAuthBearer({ baseURL,
getToken: () => authClient.getAccessToken(), authScheme })` from
`@molecule/app-bonds-default-react` (or the auth client built with
`createDefaultAuthClientWithHttpSync`, which mirrors the token into the
bonded client) plus `setAuthGate(() => authClient.whenRestored())`.

The restore's own requests are never held: a request the settle function issues while it
runs goes out immediately, so `setAuthGate(() => restoreSession())` cannot deadlock even
when `restoreSession` calls the gated client. A restore that awaits something else first
(a storage read, a `Promise.resolve()`) issues its request from a later continuation, which
the gate cannot recognize — that request needs `skipAuthGate: true` (see
`RequestConfig.skipAuthGate`). `@molecule/app-auth`'s own restore needs neither because it
uses `fetch` rather than the bonded client.

```typescript
function setAuthGate(next: (() => Promise<void>) | null): void
```

- `next` — The gate, or `null` to clear a previously registered one.

#### `awaitAuthGate(request)`

Awaits the registered gate, if any. Every HTTP provider calls this before it
sends a request; callers never need to.

A gate that rejects (a restore that failed) is logged and cleared of consequence: the request
is sent rather than held forever, because a dead restore must not block every request for the
life of the page. The same holds for a gate that never settles — the wait is bounded by
`GATE_TIMEOUT_MS`, and a timeout with requests held is reported at error level naming the fix
(`skipAuthGate`).

```typescript
function awaitAuthGate(request?: AuthGateRequest): Promise<void>
```

- `request` — The request being gated, so a request the gate itself depends on can opt out (`skipAuthGate`) and a stalled gate can name what it held. A provider passes its own request config; a caller passing nothing gets the plain wait.

**Returns:** A promise that settles when the gate has released the request.

#### `unwrapList(res)`

Normalize an unknown response body into a typed array.

Accepts:

- a bare array → returned as-is (cast)
- `{ data: T[] }` envelope → the inner array
- `HttpResponse<T[]>` (i.e. `{ data: T[], status, ... }`) → the inner array
- `HttpResponse<{ data: T[] }>` (the response of an envelope-returning
  endpoint as it arrives from `@molecule/app-http`'s `HttpClient`) → the
  doubly-nested inner array
- `HttpResponse<{ data: T[], total, limit, offset }>` (a RICH pagination
  envelope from a pre-built `@molecule/api-resource-*` list endpoint) → the
  inner `data` array (the numeric `total`/`limit`/`offset` make the shape
  unambiguous, so callers can pass the whole HttpResponse and still get the rows)
- anything else → `[]`

Callers commonly pass either the raw JSON body (e.g. from `fetch().then(r =>
r.json())`) or the `HttpResponse` returned by `useHttpClient().get(...)`.
Both shapes are handled here so pages don't have to remember to call
`unwrapList(res.data)` vs `unwrapList(res)`.

A custom envelope such as `{ items: [...], count: 10 }` is not a `data`
envelope and returns `[]`. Read its named array directly: `body.items` for
raw JSON, or `response.data.items` for an `HttpResponse`. Passing that
array to `unwrapList` is also valid; passing the enclosing object is not.

```typescript
function unwrapList(res: unknown): T[]
```

- `res` — Raw response body OR an `HttpResponse` envelope from `@molecule/app-http`.

**Returns:** A typed array `T[]`; never `null`/`undefined`.


- `res` — Raw response body (e.g. `HttpResponse.data` from `@molecule/app-http`).

**Returns:** The typed resource `T`, or `null` when the response shape indicates "no resource" (including the various empty envelopes above).

#### `setAuthTokenSource(source)`

Registers the token source every bonded client reads on EACH request, or removes it with
`null`.

Every client that receives the source — the one bonded now, any bonded later, and the
fallback {@link getClient} returns while none is bonded — is hydrated from `source()` and
reads it again for every request: through {@link HttpClient.setAuthTokenResolver} where the
client implements it (`createFetchClient`, `@molecule/app-http-axios` from 1.2.0), else
through a request interceptor that pushes it with `setAuthToken`, which a transport applying
its token after its interceptors sends on that same request and one applying it before them
from the next request on. So a restored session reaches a client bonded after the auth setup
(which holds no client reference), and a session adopted later with no auth event
(`setSession`, `setAccessToken`) never leaves the previous account's bearer on the wire.

A source that returns `null` means "no body token": the client sends no `Authorization`
header of its own (see {@link HttpClient.setAuthTokenResolver} for why a kept bearer is a
bug). A header passed per request or in a client's default headers keeps the precedence that
client's transport gives it over the client's token.

A replaced source is followed from the next request on. Removing it (`null`) leaves the
bonded client (and the fallback) on the token the source returned at that moment, as a
static token that `setAuthToken` controls from then on.

```typescript
function setAuthTokenSource(source: AuthTokenResolver | null): void
```

- `source` — Returns the current access token (null when signed out), or `null` to remove it.

#### `setClient(client)`

Registers an HTTP client as the active singleton.

A registered `setAuthTokenSource` token source is applied to the client
here, so a client bonded after the auth setup resolves the restored
session's token on every request it makes.

```typescript
function setClient(client: HttpClient): void
```

- `client` — The HTTP client implementation to bond.

#### `getClient()`

Retrieves the bonded HTTP client. If none is bonded, returns a module-level
fetch-based fallback — it is NOT bonded.

The fallback has NO `baseURL` — a core cannot know an app's API prefix. A relative
call then resolves against the page origin, where a dev server answers its own HTML
shell with a 200. It warns once so the misconfiguration is named instead of showing up
as a crash three components later; a scaffold bonds the shared client with its API
prefix, so the fallback only runs in an app that never bonded one.

Returning it WITHOUT bonding is what keeps a later `setClient()` authoritative: a
caller that captured this fallback early does not make it the app's client, so the
scaffold's client (and its token source) still takes effect for every later call.
The fallback follows a registered `setAuthTokenSource` source like a bonded client
does, so an app that bonds no client at all still sends the current session.

```typescript
function getClient(): HttpClient
```

**Returns:** The active HTTP client, or the unbonded fallback when none is bonded.

## Injection Notes

### Requirements

Peer dependencies:

- `@molecule/app-bond` ^1.0.1
- `@molecule/app-i18n` ^1.0.1
- `@molecule/app-logger` ^1.0.1

### Runtime Dependencies

- `@molecule/app-bond`
- `@molecule/app-i18n`
- `@molecule/app-logger`

Make ALL API calls through this client (via the framework hook `useHttpClient()` in
React / the Vue composable) — it carries the configured `baseURL`, auth headers, and
interceptors. Do NOT call `fetch()` / `axios` directly in components — that bypasses auth

- base-URL config and breaks when the transport is swapped.

Two mistakes that break in preview/production (seen in real imported apps):

- **Pass RELATIVE paths; never a hardcoded host.** Use `'/plants'` (the BONDED client's
  `baseURL` — `'/api'` in a scaffold — is prepended), NOT `'/api/plants'`, and NEVER an
  absolute dev URL like `'http://localhost:4000/api/…'`. A hardcoded `localhost`/host works on
  the author's machine, then fails cross-origin (CORS) in the preview and points at the wrong
  server in production. The base URL is configured ONCE (via `setClient`), not per call.
- **`getClient()` itself knows no baseURL.** The fallback client it mints when nothing is
  bonded has `baseURL: ''`, so `getClient().get('/articles')` requests the PAGE origin — in
  dev the Vite server answers its own `index.html` with a 200, and the HTML arrives as
  `data` (xr-molecule-flash-m126 lost 6.5 minutes to that). A scaffold bonds
  `'/api'`; an app that builds its own client must pass `{ baseURL }`.
- **The client is PUBLIC — never put a secret in it.** Anything the browser sends (an API
  key, a service-role / `sk_…` key, a signing secret) is visible to every user. Secrets
  stay in YOUR API; the browser calls your API and the API uses the secret server-side.
  Only a publishable/public key may ever be client-side.

Auth (the bearer token / session cookie) is attached by the client's interceptors — do not
read a token from `localStorage` or hand-attach it (the token is memory-only; see the user
resource).
An API that wants another scheme than `Bearer` (`Authorization: Token <jwt>`) passes
`authScheme: 'Token'` to the client's CONSTRUCTOR — `setClient(createFetchClient({ baseURL,
authScheme: 'Token' }))`, or the bonded provider's constructor
(`createAxiosClient({ … })` from `@molecule/app-http-axios`). It is NOT a property of
`getClient()`'s result: that is a built client, and `client.authScheme = 'Token'` is a type
error (TS2339) that changes no header. Do not hand-write a fetch wrapper for the scheme either.

A request made while the session is still being restored WAITS for that restore, so a page
that fetches viewer-dependent data on mount (a profile's `following` flag, a feed, a
`favorited` state) cannot go out unauthenticated and answer for an anonymous viewer. The auth
bond registers that wait with `setAuthGate`; apps that bond auth through
`@molecule/app-bonds-default-react` get it without doing anything. An app with its own session
module registers its own: `setAuthGate(() => session.whenRestored())`.
Waiting for the restore does NOT attach the token: a client created beside the auth bond needs
`createDefaultHttpClientWithAuthBearer({ baseURL, getToken: () => authClient.getAccessToken(),
authScheme })` from `@molecule/app-bonds-default-react` (or an auth client built with
`createDefaultAuthClientWithHttpSync`, which registers the auth client's token source with
`setAuthTokenSource`: the client reads it on each request, so a session adopted mid-page by
`setSession()` or an OAuth callback's `setAccessToken()` is sent instead of the previous
account's token — `setAuthTokenSource` says which request first carries it on a transport
without `setAuthTokenResolver`), because `setAuthGate` alone sends no `Authorization` header.

**The gate never holds its own restore's request.** A request the settle function issues
while it runs (its call reaches this client before the function awaits anything) is part of
the restore it is waiting for, so it goes out immediately — `setAuthGate(() =>
restoreSession())` does not deadlock even when `restoreSession` uses this client. A restore
that awaits something else first and only then calls the client reaches it after that
window, and that request must opt out of the gate: `http.get(currentUserEndpoint, {
skipAuthGate: true })`. Without the opt-out the gate waits on itself, the restore never
settles, and every request the gate holds stalls until it times out (3 s).
`@molecule/app-auth`'s own restore does not need it (it calls `fetch`, not this client).

**A failed request's `status` is `0` when NO response arrived — never read it as
"signed out".** An aborted request (an `AbortController` signal, a component's
effect cleanup, a route change tearing the fetch down) and a network outage both
throw an `HttpError` with `status === 0`; the aborted ones also carry
`aborted: true` and the `http.error.aborted` key, the rest `http.error.networkError`.
Neither says anything about the session. To decide whether a session ended, use
`isAuthFailure(err)` (401/403 only); `isNoResponse(err)` identifies the no-response
case so a caller can stay silent instead of reporting an outage. **Do not write
`err instanceof HttpError && err.status < 500` as a sign-out check** — it clears
the session on every aborted navigation request.
