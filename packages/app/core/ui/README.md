```typescript
    | 'flex'

    | 'grid'
    | 'inline-grid'
```

#### `KitEvent`

The event a UI kit hands a component's handler: the members that behave the same on every kit. React's kit
passes React's event (so `stopPropagation()` stops React parent handlers), the other kits pass the DOM event;
both satisfy this type. A handler that needs a member only one of them has (`nativeEvent`, `composedPath()`,
`isComposing`) takes the component's ref element (see {@link BaseProps}) and listens on it.

`type` is left out on purpose: kits report different event types for the same moment (a text field's
`onChange` is React's `'change'` and the DOM's `'input'`).

```typescript
interface KitEvent {
  /** The element the event started on (`(event.target as HTMLInputElement).value` reads a field). */
  readonly target: EventTarget | null
  /** The element of the component the handler was passed to. */
  readonly currentTarget: EventTarget | null
  /** Whether a handler already called {@link KitEvent.preventDefault}. */
  readonly defaultPrevented: boolean
  /** Cancels the browser's default action (a form's submit, a checkbox's toggle). */
  preventDefault(): void
  /** Stops handlers of ancestor components of the same kit. */
  stopPropagation(): void
}
```

#### `BaseProps`

Base props shared by all components.

Ref element: a component that renders one main element gives the caller that element, the one
that takes `className` and `style`. Each UI kit hands it over in its framework's own way: React
and Solid a `ref`, Vue a template ref's `$el`, Svelte `bind:ref`, Angular the component's
`element()` signal. It is empty while the element is not rendered (a closed Tooltip, Dropdown or
Modal). A component's own doc names the element when it is not the outermost one.

```typescript

   */

  /**
   * Automation ID for AI agents and E2E tests. Maps to the `data-mol-id`
   * HTML attribute. Use `molId()` from `./automation.js` to generate
   * semantic IDs. (Tooling only — screen readers do not expose `data-*`
   * attributes; accessible names come from labels/`aria-*`.)
   */
  automationId?: string

  /**
   * Disables the controls the component renders: a disabled Button, Input, Textarea, Select,
```

## Injection Notes

### Requirements

Peer dependencies:

- `@molecule/app-bond` ^1.0.1
- `@molecule/app-i18n` ^1.0.1

### Runtime Dependencies

- `@molecule/app-bond`
- `@molecule/app-i18n`

**Style through {@link getClassMap} — NEVER write raw CSS/Tailwind class names in a
component.** `const cm = getClassMap()` returns the resolver; use its helpers (`cm.flex`,
`cm.surface`, `cm.textSize(size)`, the component helpers like `cm.button`/`cm.card`, and
`cm.cn(...)` to compose) and pass the result to `className`. Class-name STRINGS live only in
the ClassMap bond (`@molecule/app-ui-tailwind`), so swapping the styling library touches
only the bond — a literal `"flex p-4"` in a component defeats that and is the #1 styling
mistake.

A stylesheet the request supplies (a theme CSS, a CSS framework, a design export with its
own class names) is used by those class names written directly in `className` — ClassMap
governs molecule's own utilities, not a supplied stylesheet's contract; never wrap,
re-generate or rename its classes.

- **`Button` defaults to `type="button"`.** A form's primary action needs
  `type="submit"`, or Enter does nothing and tests that select `button[type="submit"]`
  miss it (X1 RealWorld runs failed 15 browser tests on one Settings button).
- **Inline styles must not fight ClassMap.** An inline `style` has higher specificity and
  SILENTLY overrides the class controlling the same property (e.g. `style={{ background }}`
  kills `cm.surface`). Use inline only for what ClassMap can't express (a specific pixel
  width, an SVG attribute, a one-off accent color).
- **Check what a class resolves to before using it** — read the bond definition, don't guess
  a helper name or option value; an invalid `cm.*` value is a type error or a silent no-op.
- **Every interactive element needs a stable `data-mol-id`** — spread {@link molIdProps} (or
  set {@link MOL_ID_ATTR} via {@link molId}) so AI agents and tests can target it.
- **`tabsList`/`tabsTrigger`/`tabsContent` are resolver functions**, not static strings —
  call `cm.tabsList(opts)`/`cm.tabsTrigger(opts)`/`cm.tabsContent(opts)` with an optional
  {@link TabsClassOptions} (`variant`/`size`). Active-tab styling stays a `data-state`
  attribute selector the caller sets, not one of these options. `cm.switchBase(opts)` also
  accepts a `color` ({@link SwitchClassOptions}) alongside `size`.
